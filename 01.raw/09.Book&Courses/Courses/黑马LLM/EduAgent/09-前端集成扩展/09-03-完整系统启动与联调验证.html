    9.3 完整系统启动与联调验证¶

    学习目标¶

    • 能够独立启动前端 + 后端，看到完整运行的 EduAgent 系统
    • 验证四大 Agent 功能在 UI 上端到端可用

    9.3.1 前提条件¶

    在启动前端之前，确认后端基础设施已就绪（第 9 章已完成过的步骤）：

    # 检查基础服务运行状态
docker-compose --env-file .env.local ps
# 应看到 postgres、redis、minio、milvus 状态为 Up

# 检查后端能否正常启动
conda activate edu_agent
uvicorn backend.main:app --reload --port 8000
# 浏览器打开 http://localhost:8000/docs，能看到 Swagger 文档说明后端正常

    9.3.2 安装前端依赖¶

    进入 frontend/ 目录，安装 Node.js 依赖（只需做一次）：

    cd frontend
npm install

    Node.js 版本要求：18+。可用 node --version 检查，低于 18 请先升级。

    9.3.3 配置前端环境变量¶

    # 在 frontend/ 目录下，复制模板
cp .env.example .env.local

    .env.local 内容只有一行，保持默认即可（本机开发）：

    VITE_API_BASE_URL=http://localhost:8000

    这个变量告诉前端 SSE 流式请求的目标地址。如果后端运行在其他机器上，把 localhost 改成对应 IP。

    9.3.4 启动前端开发服务器¶

    # 在 frontend/ 目录下
npm run dev

    控制台输出类似：

      VITE v5.x.x  ready in 800 ms

  ➜  Local:   http://localhost:3000/
  ➜  Network: use --host to expose

    前端服务就绪，访问 http://localhost:3000。

    9.3.5 两个终端同时运行¶

    正常开发时需要**两个终端**分别维持：

    终端 命令 端口
    终端 A uvicorn backend.main:app --reload --port 8000 :8000 后端
    终端 B cd frontend && npm run dev :3000 前端

    两者都在运行时，浏览器访问 :3000 即是完整系统。

    9.3.6 端到端验证步骤¶

    登录验证¶

    1. 打开 http://localhost:3000，自动跳转到 /login
    2. 输入用户名 student01，密码 Student@123456，点击「登录」
    3. 正常跳转到 Dashboard，左侧显示侧边栏导航

    如果登录失败（「用户名或密码错误」提示）： - 检查 seed_data.py 是否执行过：python scripts/seed_data.py - 检查后端终端有无报错

    智能问答验证¶

    1. 点击 Dashboard 上的「智能问答」或左侧导航「QA」
    2. 在输入框输入：什么是 Java 的多态，按 Enter
    3. 预期效果：右侧气泡区出现流式 token（字符逐渐出现），最终显示完整回答并附上来源文档

    如果回复一直显示三个跳动点但不出字： - 检查 frontend/.env.local 是否存在且 VITE_API_BASE_URL=http://localhost:8000 - 检查后端终端是否有报错 - 用浏览器开发者工具 → Network → 找到 /chat/stream 请求，查看响应状态码

    试卷批改验证¶

    1. 点击「试卷批改」
    2. 在「试卷 ID」输入框中填入测试试卷 ID： 
      3e76aeed-5e01-4aa7-be8d-2055d12b9ea7
    3. 点击「选择文件」，上传 tests/fixtures/test_exam_answer.docx
    4. 点击「提交批改」，等待几秒后状态变为 processing
    5. 点击「查看结果」，进入结果页，看到逐题评分和薄弱点分析

    使用教师账号验证 HitL 流程： 1. 退出登录，用 teacher01 / Teacher@123456 重新登录 2. 左侧导航出现「教师端 → 批改确认」菜单 3. 点击进入，看到学生提交的待确认列表 4. 点击「审阅」，在抽屉里查看 AI 批改详情，点击「批准」完成 HitL 确认

    简历审查验证¶

    1. 用学生账号登录，点击「简历审查」
    2. 点击「选择 PDF 文件」，上传任意一份 PDF 简历
    3. 点击「开始审查」，等待状态轮询完成（通常 10-20 秒）
    4. 历史记录列表出现条目后，点击「查看报告」
    5. 预期：看到六维度评分、问题清单和总体建议

    模拟面试验证¶

    1. 点击「模拟面试」
    2. 输入目标岗位：Java 后端开发工程师，点击「开始面试」
    3. 进入对话页，AI 发出开场问题
    4. 输入几句回答，观察面试对话是否正常推进
    5. 面试结束后（通常 6-10 轮）自动跳转到报告页，看到五维度评分

    9.3.7 常见问题速查¶

    现象 可能原因 解决方法
    登录后空白页 后端未启动 启动 uvicorn backend.main:app --reload
    QA 流式不出字 VITE_API_BASE_URL 未配置 检查 frontend/.env.local
    上传文件 400 错误 文件格式不对 试卷必须 .docx，简历必须 .pdf
    教师菜单不出现 用了学生账号 换用 teacher01 登录
    试卷结果一直 processing Milvus 或知识库未初始化 运行 python scripts/init_milvus.py 后重试
    前端 npm install 报错 Node 版本过低 升级到 Node 18+

    9.3.8 AI 助手统一入口（UnifiedChatView）¶

    除了各独立功能页，Dashboard 上的「✨ AI 助手」是统一入口，对应 POST /api/v1/chat。

    使用方式：直接用自然语言描述需求，系统自动识别意图并路由：

    输入示例 路由结果
    "Java 的 GC 算法有哪些" → QA Agent（RAG 检索）
    "帮我批改一份 Java 基础试卷" → 引导进入试卷批改页面
    "分析一下我的简历" → 引导进入简历审查页面
    "我想练习面试" → 引导进入模拟面试页面

    多 Agent 协作场景（如先审查简历、再基于简历开展面试）也可以通过对话式描述触发。

    本章总结¶

    至此，EduAgent 系统的完整闭环已经跑通：

    学生 / 教师
    ↓ 浏览器 :3000
Vue3 前端（SPA）
    ↓ Vite proxy / 直连 SSE
FastAPI 后端 :8000
    ↓ LangGraph Agent
DeepSeek-V3 / DeepSeek-Coder-V2
    ↓
PostgreSQL / Milvus / Redis / MinIO

    前端不是本课程的教学重心，你不需要深入理解每行 Vue 代码。关键的三个连接点已经讲清楚：Vite proxy 转发普通请求、fetch 直连处理 SSE 流式、JWT 由 Axios 拦截器自动注入。其余 UI 细节，结合 frontend/src/views/ 目录下的源码阅读即可。

    整个 EduAgent 课程到这里结束。你完整地构建了一个基于国产大模型的 AI 原生教学系统，涵盖从 LangGraph 状态机、RAG 检索、HitL 批改流程到生产级基础设施的全链路实践。

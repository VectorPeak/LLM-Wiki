    1.1 项目全景介绍¶

    学习目标¶

    • 了解 EduAgent 项目的业务背景与四大 Agent 的定位
    • 掌握项目整体技术栈与系统分层架构
    • 了解项目最终交付物与本课件的使用方法

    1.1.1 项目背景：教培机构的真实痛点¶

    在一家 IT 教育培训机构里，每天都在重复发生这样几件事：

    • 学员在学习过程中遇到问题，需要老师答疑，但老师精力有限，很多重复问题被反复问；
    • 老师要批改大量试卷，选择题、简答题、编程题都要看，工作量大且主观题评分容易不一致；
    • 学员投简历前希望有人帮忙审一审，但老师没时间逐份精读打分；
    • 学员想练习技术面试，却缺少可以随时陪练、还能给出专业反馈的「面试官」。

    这些场景有一个共同特征：它们都需要「专业知识 + 判断 + 反馈」，而这正是大语言模型（LLM）擅长的事。但直接把问题丢给一个通用大模型并不够用，原因有三：

    1. 缺少企业私有知识。通用大模型只懂公开知识，不知道「我们这门课第 3 章具体讲了什么」「我们项目里那段代码为什么这么写」，容易答非所问甚至「一本正经地胡说」（业内称为「幻觉」）。
    2. 缺少业务流程。批改试卷不是「问一次大模型」就完事，它需要分题型处理、需要老师最终把关；模拟面试需要分阶段推进、记住前面聊过什么。这些都是**多步骤、有状态、有分支**的流程。
    3. 缺少工程化的可靠性。线上系统会遇到网络抖动、模型超时，不能一出错就崩，需要重试和降级兜底。

    EduAgent 就是为了解决这些痛点而生的一套 AI 原生教学辅助系统。它把上面四类业务分别做成四个专门的「智能体（Agent）」，每个 Agent 都融合了企业私有知识、内置了完整业务流程、并配备了工程化的容错机制。

    本课程的核心目标，不只是教你「做出 EduAgent」，而是让你掌握一套**可迁移到任何企业业务场景的多 Agent 系统开发方法论**。学完之后，无论是做客服 Agent、运维 Agent 还是数据分析 Agent，你都能套用同一套思路。

    1.1.2 EduAgent 是什么：四大核心 Agent¶

    EduAgent 由四个各司其职的 Agent 组成，每一个都对应一个真实业务场景，也分别承载了一类典型的 Agent 开发技术：

    Agent 业务场景 它教你的核心技术
    智能问答（QA） 学员答疑 RAG 检索增强：私有知识库 + 向量检索 + 精排 + 流式输出
    试卷批改（Exam） 自动批改试卷 三轨并行批改 + HitL 人在环中（老师最终确认）
    简历审查（Resume） 简历打分与建议 结构化抽取 + 多维度并行评分
    模拟面试（Interview） 技术面试陪练 **状态机**多阶段对话 + 双轨评估 + 流式输出

    这四个 Agent 不是孤立的。它们上面还有一个**编排者（Orchestrator）**，负责理解用户意图，把请求路由到正确的 Agent，甚至在复杂场景下把多个 Agent 串成一条流水线协作完成任务。

    1.1.3 技术栈一览¶

    层面 技术选型 说明
    开发语言 Python 3.11 全异步开发
    Web 框架 FastAPI 提供 REST + SSE 流式接口
    Agent 框架 LangChain 1.2.10 + LangGraph 1.0.9 本项目的绝对核心，版本严格锁定
    主力大模型 DeepSeek-V3（API） 问答 / 批改 / 简历 / 面试都用它
    向量数据库 Milvus 存储知识库的向量，支撑 RAG 检索
    关系数据库 PostgreSQL 存储用户、试卷、会话等业务数据
    嵌入模型 BGE-M3（进程内） 把文本转成向量，dense + sparse 双输出
    精排模型 BGE-Reranker（进程内） 对检索结果做二次精排
    意图分类 MiniLM-L6-v2（进程内） 判断问题该走通用直答还是知识库检索

    关于「进程内」：BGE-M3、BGE-Reranker、MiniLM 这三个本地小模型不需要单独起服务、不占用独立端口，它们在后端进程启动时被加载进内存，直接函数调用即可。这是本项目一个很实用的工程简化——避免了为三个小模型各起一个微服务的复杂度。

    1.1.4 系统整体架构¶

    EduAgent 采用清晰的分层架构，从上到下数据流向明确：

    这张图你现在不需要全看懂，但请记住几个关键角色——后面每一章都会逐个把它们填充成真实代码：

    • API 层：系统的「大门」，接收前端请求、做身份校验、把结果（可能是流式的）返回。
    • 编排层 Orchestrator：系统的「调度中心」，判断这个请求该交给哪个 Agent。
    • Agent 层：四个用 LangGraph 写成的「状态图」，每个图就是一套完整的业务流程。
    • 公共层：所有 Agent 共享的「基础设施」——统一的大模型工厂、本地小模型、记忆管理、容错机制。
    • MCP 层：把「知识库检索」和「联网搜索」封装成标准化的工具服务，供 Agent 调用。
    • 数据层：PostgreSQL 存业务数据，Milvus 存向量。

    1.1.5 最终交付物预览¶

    学完本课程并跟着动手，你将得到一个**可以在本地完整跑起来的后端系统**，包含：

    • 一套可登录、带 JWT 鉴权的 FastAPI 服务，访问 http://localhost:8000/docs 能看到全部接口；
    • 四个端到端可用的 Agent，能真实地回答问题、批改试卷、审查简历、模拟面试；
    • 一套可导入课程文档的知识库构建管线；
    • 一套完整的容错与降级机制；
    • 一份清晰的接口契约文档，方便你后续自己接前端。

    1.1.6 本课件如何使用¶

    本课程采用**「复刻式」**教学：我们会带你把 EduAgent 一行行写出来、一步步跑通，而不是只讲概念。使用建议如下：

    1. 先读「工具介绍」（第二章）。LangChain、LangGraph、异步编程等工具，如果你之前没学过，第二章会用脱离项目的最小例子帮你建立基本认知。有了认知，进入项目实战时即使某处写法略有不同，也能很快理解。
    2. 严格按章节顺序学。章节的排列是精心设计的学习曲线：先搭地基，再用最简单的「简历 Agent」跑通第一个完整流程获得成就感，然后才进入最重的 RAG 问答和 HitL 批改。
    3. 每章都要动手敲、动手跑。每章末尾都有可验证的运行环节，别只看不练。
    4. 遇到报错先查附录 A（常见报错排查）。

    章节总结¶

    本节我们从业务和工程两个角度俯瞰了整个 EduAgent 项目：

    • 业务层面：EduAgent 是面向 IT 教培机构的 AI 教学辅助系统，用四个专门的 Agent（智能问答、试卷批改、简历审查、模拟面试）解决答疑、批改、简历、面试四类真实痛点。
    • 技术层面：项目以 Python 3.11 + FastAPI + LangChain/LangGraph + DeepSeek-V3 为核心，应用真正依赖的数据库只有 PostgreSQL 和 Milvus。
    • 架构层面：系统自上而下分为 API 层、编排层、Agent 层、公共层、MCP 层、数据层，每一层的职责清晰。

    下一节我们会暂时离开「项目」本身，先把一个更根本的问题讲透：到底什么是 Agent，为什么要用 LangGraph 来实现它。

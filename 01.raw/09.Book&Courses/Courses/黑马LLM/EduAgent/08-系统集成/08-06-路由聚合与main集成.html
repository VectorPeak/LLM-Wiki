    8.6 路由聚合与 main.py 最终集成¶

    学习目标¶

    • 掌握 api/router.py 如何把六个子路由聚合成一个总路由
    • 读懂完整 main.py：lifespan 启动钩子、CORS、路由挂载、MCP 挂载、health
    • 理解 lifespan 里的三件事：DB 迁移、本地模型预热、MCP 子应用生命周期
    • 厘清 main.py 每个零件「在前面哪一章造的」——本章只做装配

    💡 本节涉及文件：backend/api/router.py（路由聚合）+ backend/main.py（应用装配）。两者都是"连线"，零件都来自前面章节。

    📁 本节涉及的文件¶

    文件 状态 说明
    backend/api/router.py 🆕 新建 六个子路由聚合成 api_router
    backend/main.py ✏️ 最终版 FastAPI 应用装配（前面各章逐步补，本章定稿）

    8.6.1 api/router.py：六个 router 聚合¶

    每个功能模块（认证、问答、批改、简历、面试、统一入口）各自定义了一个 APIRouter。router.py 把它们**带前缀聚合**成一个总路由 api_router，再由 main.py 统一挂到 /api/v1 下。

    # backend/api/router.py
# API 路由总入口

from fastapi import APIRouter
from backend.api.v1 import auth, qa, exam, resume, interview, unified_chat  # 六个子模块

api_router = APIRouter()                              # 总路由

# 把每个子 router 带前缀 + 标签聚合进来
api_router.include_router(auth.router,          prefix="/auth",      tags=["认证"])
api_router.include_router(unified_chat.router,  prefix="/chat",      tags=["AI助手"])   # 本章统一入口
api_router.include_router(qa.router,            prefix="/qa",        tags=["智能问答"])  # 第 5 章
api_router.include_router(exam.router,          prefix="/exam",      tags=["试卷批改"])  # 第 6 章
api_router.include_router(resume.router,        prefix="/resume",    tags=["简历审查"])  # 第 4 章
api_router.include_router(interview.router,     prefix="/interview", tags=["模拟面试"])  # 第 7 章

    include_router 三个要点：

    • prefix：给该模块所有路由加统一前缀。比如 unified_chat 的 POST /stream，聚合后变成 /chat/stream，再加 main.py 的 /api/v1，最终是 POST /api/v1/chat/stream。
    • tags：给 Swagger 文档（/docs）分组，便于查看。
    • 顺序：把 unified_chat（统一入口）放在各 Agent 之前，语义上突出它是"主入口"。

    8.6.2 完整路由表¶

    聚合后，整个系统对外暴露的接口（都在 /api/v1 前缀下）：

    模块 前缀 代表性接口 来自
    认证 /auth POST /auth/login 3.6
    AI 助手 /chat POST /chat/stream（统一入口 SSE） 本章
    智能问答 /qa POST /qa/... 第 5 章
    试卷批改 /exam POST /exam/... 第 6 章
    简历审查 /resume POST /resume/... 第 4 章
    模拟面试 /interview POST /interview/sessions、.../chat、.../chat/stream 第 7 章

    💡 统一入口 /chat/stream 是"总机"——用户一句话进来，由它路由到后面五个模块。其余 /qa /exam 等是"分机"，前端的专门页面（上传简历、选岗位）直接调它们。两套接口并存：聊天框走总机，功能页走分机。

    8.6.3 main.py：应用装配总览¶

    main.py 是整个后端的入口，uvicorn backend.main:app 启动的就是它。它做四件事：定义 lifespan 启动钩子 → 创建 FastAPI 应用 → 配 CORS → 挂路由和 MCP。

    先看文件头和 MCP 子应用的创建：

    # backend/main.py

import os
import sys

# Windows conda 专用：把 base 的 Library/bin 加入 DLL 搜索路径，
# 让 _lzma.pyd 能找到 liblzma.dll（非 Windows 跳过，不影响 Linux/Mac）
if sys.platform == "win32":
    _conda_base_lib_bin = os.path.normpath(
        os.path.join(os.path.dirname(sys.executable), "..", "..", "Library", "bin")
    )
    if os.path.isdir(_conda_base_lib_bin):
        os.add_dll_directory(_conda_base_lib_bin)

from contextlib import asynccontextmanager
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

from backend.config import get_settings                          # 配置（第 3 章）
from backend.core.logger import configure_logging, get_logger    # 日志（3.3）
from backend.api.router import api_router                        # 8.6.1 聚合的总路由

settings = get_settings()

# MCP Sub-Apps（第 5.11 章实现）在 lifespan 定义前创建，
# 这样 lifespan 与下面的 mount 共享同一实例
from backend.mcp.knowledge_base_server import mcp as kb_mcp      # 知识库 MCP（5.11）
from backend.mcp.web_search_server import mcp as ws_mcp          # 联网搜索 MCP（5.11）

_kb_app = kb_mcp.streamable_http_app()                          # 把 MCP 变成 ASGI 子应用
_ws_app = ws_mcp.streamable_http_app()

    💡 MCP 子应用提前创建：streamable_http_app() 把 MCP Server（5.11）包成标准 ASGI 应用。这里在模块级提前创建 _kb_app / _ws_app，是为了让下面的 lifespan（要驱动它们的生命周期）和最后的 mount（要把它们挂上去）用的是**同一个实例**。

    8.6.4 lifespan：启动与关闭钩子¶

    lifespan 是 FastAPI 的生命周期钩子：yield 之前的代码在**启动时**跑一次，yield 之后的在**关闭时**跑一次。这里启动时做三件事，全是"调用前面各章造好的东西"：

    @asynccontextmanager
async def lifespan(app: FastAPI):
    configure_logging()                                  # 初始化结构化日志（3.3）
    logger = get_logger(__name__)
    logger.info("app.starting | env=%s port=%s", settings.app_env, settings.app_port)

    # ① DB Schema 自动迁移（幂等，每次启动执行）—— 第 3 章的建表/迁移
    try:
        from backend.db.migrations import run_migrations
        await run_migrations()
    except Exception as e:
        logger.warning("app.migrations_failed | error=%s", e)   # 迁移失败只告警，不拦启动

    # ② 并行预热三个本地模型（首次加载慢，提前热好，避免首个请求卡顿）
    import asyncio
    try:
        from backend.core.reranker import BGEReranker            # 重排序模型（5.8）
        from backend.core.query_classifier import QueryClassifier # 意图分类器（5.9）
        from backend.core.knowledge_base import BGEMEmbedder      # BGE-M3 嵌入（5.4）

        loop = asyncio.get_running_loop()
        await asyncio.gather(                                    # 三个模型并行加载（各跑在线程池里）
            loop.run_in_executor(None, BGEReranker.get_instance),
            loop.run_in_executor(None, QueryClassifier.get_instance),
            loop.run_in_executor(None, BGEMEmbedder.get_instance),
        )
        logger.info("app.local_models_warmed_up")
    except Exception as e:
        logger.warning("app.local_models_warmup_failed | error=%s", e)  # 预热失败也不拦启动

    # ③ 驱动 MCP Server 的 lifespan（mount 不会自动调用子应用的 lifespan，需手动嵌套进入）
    async with _kb_app.router.lifespan_context(_kb_app):
        async with _ws_app.router.lifespan_context(_ws_app):
            logger.info("app.started")
            yield                                               # ← 应用运行期间停在这里

            # ── 关闭时执行 ──
            logger.info("app.shutting_down")
            from backend.core.llm_factory import LLMFactory      # LLM 工厂（3.4）
            LLMFactory.clear_cache()                            # 清缓存
            logger.info("app.shutdown_complete")

    lifespan 启动三件事，对应来源：

    启动步骤 做什么 来自
    ① run_migrations 建表/迁移 Schema（幂等） 第 3 章
    ② 模型预热 并行热好 reranker / 分类器 / 嵌入模型 5.8 / 5.9 / 5.4
    ③ MCP lifespan 手动驱动两个 MCP 子应用的生命周期 5.11

    ⚠️ 为什么模型要"预热"：reranker / 分类器 / 嵌入这三个本地模型首次加载要读权重、占几秒。如果不预热，第一个真实用户请求就会卡这几秒。启动时用 asyncio.gather 把三个并行加载（各自丢进线程池，避免阻塞事件循环），用户来时已经热好。

    📎 三件事都包了 try/except 且只告警：迁移失败、模型预热失败都**不拦截启动**——本地开发没装某个模型也能起服务调试。这是"优雅降级"在启动阶段的体现。

    8.6.5 应用创建、CORS、挂载与 health¶

    app = FastAPI(
    title="EduAgent API",
    description="AI 助教智能体系统 API",
    version="1.0.0",
    docs_url="/docs",                                    # Swagger 文档
    redoc_url="/redoc",                                  # ReDoc 文档
    lifespan=lifespan,                                   # 挂上面的生命周期钩子
)

# CORS：允许前端开发端口跨域访问（3000/5173/8080）
app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "http://localhost:3000", "http://localhost:5173", "http://localhost:8080",
        "http://127.0.0.1:3000", "http://127.0.0.1:5173", "http://127.0.0.1:8080",
    ],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

app.include_router(api_router, prefix="/api/v1")        # 挂总路由（8.6.1），所有业务接口在 /api/v1 下

app.mount("/mcp/kb",         _kb_app)                   # 挂知识库 MCP 子应用（5.11）
app.mount("/mcp/web-search", _ws_app)                   # 挂联网搜索 MCP 子应用（5.11）


@app.get("/health", tags=["系统"])                       # 健康检查（运维探活用）
async def health_check():
    return {"status": "ok", "env": settings.app_env}

    装配四步：

    1. FastAPI(...)：创建应用，挂上 lifespan，配好文档地址。
    2. CORS 中间件：允许前端开发服务器（3000/5173/8080）跨域调用。
    3. include_router(api_router, prefix="/api/v1")：把 8.6.1 的总路由挂上，所有业务接口落在 /api/v1/*。
    4. mount MCP + /health：把两个 MCP 子应用挂到 /mcp/*，再加一个健康检查端点。

    💡 include_router vs mount 的区别：业务路由用 include_router（路由级合并，共享 FastAPI 的依赖/中间件）；MCP 用 mount（子应用级挂载，MCP 是独立的 ASGI 应用，有自己的协议和生命周期，所以整体挂上去而非合并路由）。这也是为什么 8.6.4 要手动驱动它们的 lifespan——mount 的子应用不会自动触发。

    8.6.6 零件来源全景（本章的精髓）¶

    把 main.py 拆开看，几乎每一行都在调用前面章节造好的零件。这张表是"集成 = 连线"最直观的体现：

    main.py 里的东西 来自哪一章
    get_settings / app_env / app_port 第 3 章（配置）
    configure_logging / get_logger 3.3（日志）
    run_migrations 第 3 章（数据库建表/迁移）
    BGEReranker（重排序） 5.8
    QueryClassifier（意图分类器） 5.9
    BGEMEmbedder（BGE-M3 嵌入） 5.4
    kb_mcp / ws_mcp（两个 MCP Server） 5.11
    LLMFactory.clear_cache 3.4（LLM 工厂）
    api_router（聚合 auth/qa/exam/resume/interview/chat） 3.6 + 第 4-7 章 + 本章
    CORS / /health 本章装配

    ✅ 这正是第 8 章想让你建立的认知：一个能跑的系统，不是一口气写出来的，是把一个个独立验证过的模块，按依赖关系装配起来的。 main.py 就是这张"装配图"。

    🧪 本节实测¶

    main.py 的验证就是"服务能起来、/health 能响应"。完整启动依赖 DB / 本地模型 / MCP，属于整章联调，放到 8.7 用真实环境跑。本节给出启动命令与冒烟检查，以及离线可看的**路由清单**。

    启动服务：

    启动日志应依次出现（印证 lifespan 三件事）：

app.started                         # ③ MCP lifespan 进入，应用就绪

    打开交互式文档，确认六组接口都挂上了：

    章节总结¶

    • api/router.py：用 include_router 把六个子路由带前缀（/auth /chat /qa /exam /resume /interview）聚合成 api_router
    • main.py 四步装配：定义 lifespan → 创建 FastAPI → 配 CORS → 挂路由（include_router）和 MCP（mount）
    • lifespan 启动三件事：DB 迁移（ch3）、本地模型并行预热（5.⅘.8/5.9）、MCP 子应用 lifespan（5.11）；都包 try/except 只告警不拦启动
    • include_router vs mount：业务路由用前者（路由合并），MCP 用后者（独立 ASGI 子应用挂载）
    • 集成 = 连线：main.py 几乎每行都在调用前面章节造好的零件，它是整个系统的"装配图"

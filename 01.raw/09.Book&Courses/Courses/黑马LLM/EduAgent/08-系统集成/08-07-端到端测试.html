    8.7 端到端测试¶

    学习目标¶

    • 通过统一入口 /chat/stream 跑通全部路由分支
    • 掌握消费 SSE 流、按事件类型分别处理的方法
    • 通过日志确认前置拦截 / LLM 路由 / Agent 执行的全链路
    • 验证求职全链路（multi_agent）的计划推送

    8.7.1 测试前提条件¶

    # ① 基础服务运行中
docker-compose --env-file .env.local ps
# 确认 postgres / milvus 状态为 Up
#   - postgres：会话、简历、面试数据
#   - milvus：QA 分支的 RAG 检索（其它分支不需要）

# ② 初始化测试数据（只需做一次）
conda activate edu_agent
python scripts/seed_data.py          # 建账号 student01
# 若要测 QA 分支，知识库需已写入（见 5.18）

# ③ 启动后端（main.py 全装配）
uvicorn backend.main:app --reload --port 8000

    💡 统一入口里只有 qa 分支真正执行 Agent（需 DeepSeek + Milvus）；exam/resume/interview/multi_agent 分支只推**引导/计划**（只需 DeepSeek 做路由判断，不跑 Agent）。所以即使知识库没建好，除 qa 外的分支也能验证。

    8.7.2 端到端测试脚本（统一入口全分支）¶

    李明打开统一 AI 助手，依次说五句话，覆盖全部分支：寒暄（前置拦截）→ 技术提问（qa 流式）→ 综合求职（pipeline 计划）→ 模拟面试（引导跳转）→ 道谢（前置拦截）。

    # scripts/manual_tests/uc_08_07_e2e.py
# 运行：python scripts/manual_tests/uc_08_07_e2e.py

import sys
import json
import httpx

sys.path.insert(0, "scripts/manual_tests")
from itv_fixtures import load_env, seed_resume   # 复用第 7 章李明的简历 fixture

load_env()

BASE_URL   = "http://localhost:8000/api/v1"
STUDENT_UN = "student01"
STUDENT_PW = "Student@123456"

# 李明的五句话，依次触发：前置拦截 / qa / multi_agent / interview / 前置拦截
MESSAGES = [
    "你好",                      # → 前置拦截（HELLO 模板，零 Token）
    "什么是 RAG 的核心原理？",    # → LLM 路由 qa → QA Agent 流式作答
    "帮我准备求职",              # → LLM 路由 multi_agent → 求职全链路计划
    "我要模拟面试",              # → LLM 路由 interview → 引导跳转 /interview
    "谢谢",                      # → 前置拦截（THANKS 模板，零 Token）
]


def login(username: str, password: str) -> str:
    resp = httpx.post(f"{BASE_URL}/auth/login",
                      json={"username": username, "password": password}, trust_env=False)
    resp.raise_for_status()
    return resp.json()["access_token"]


def print_section(title: str):
    print(f"\n{'='*64}\n  {title}\n{'='*64}")


def stream_one(headers: dict, session_id: str, message: str):
    """对一句话发起 SSE 流式请求，按事件类型分别处理。"""
    print(f"\n👤 李明：{message}")
    print("🤖 助手：", end="", flush=True)

    with httpx.stream(                                   # 流式 POST，边收边处理
        "POST", f"{BASE_URL}/chat/stream",
        headers=headers,
        json={"session_id": session_id, "message": message},
        timeout=60.0,
    ) as resp:
        for line in resp.iter_lines():                  # 逐行读 SSE
            if not line.startswith("data:"):            # 只处理 data: 行
                continue
            data_str = line[len("data:"):].strip()
            if not data_str:
                continue
            event = json.loads(data_str)                # 解析事件
            etype = event.get("type")

            if etype == "routing_decision":             # 路由决策卡片
                print(f"\n  〔路由→{event['agent_display']}"
                      f"（{event['execution_mode']}）：{event['reason']}〕")
                print("  ", end="", flush=True)
            elif etype == "progress":                   # QA 进度提示
                print(f"\n  …{event['stage']}", flush=True)
                print("  ", end="", flush=True)
            elif etype == "token":                      # 文本片段（模板回复 / QA 答案）
                print(event["content"], end="", flush=True)
            elif etype == "guidance":                   # 引导跳转卡片
                print(f"\n  〔引导：{event['message']}〕")
                if event.get("action_url"):
                    print(f"  〔按钮：{event['action_label']} → {event['action_url']}〕")
            elif etype == "pipeline_plan":              # 求职全链路计划
                print(f"\n  〔{event['title']}〕{event['intro']}")
                for step in event["steps"]:
                    print(f"    {step['step']}. {step['label']} → {step['action_url']}")
            elif etype == "meta":                       # QA 元数据（答案模式/来源）
                print(f"\n  〔来源：{event.get('sources', [])}〕")
            elif etype == "error":                      # 异常
                print(f"\n  ⚠ {event['message']}")
            # done 事件无需特殊处理，循环自然结束
    print()


if __name__ == "__main__":
    print_section("① 登录 + 写入李明简历（供求职链路使用）")
    token = login(STUDENT_UN, STUDENT_PW)
    headers = {"Authorization": f"Bearer {token}"}
    seeded = __import__("asyncio").run(seed_resume())   # 写入李明简历，resume_review_id 备用
    print(f"token: {token[:18]}...  resume_review_id: {seeded['resume_review_id']}")

    print_section("② 统一入口五句话，覆盖全部路由分支")
    session_id = "liming-unified-001"
    for msg in MESSAGES:
        stream_one(headers, session_id, msg)

    print_section("✅ 08-07 统一入口端到端：全分支验证完成")

    运行：

    conda activate edu_agent
python scripts/manual_tests/uc_08_07_e2e.py

    8.7.3 SSE 事件消费详解¶

    测试脚本的核心是**按 event["type"] 分别处理**——这正是前端要做的事。统一入口会推出 8 种事件，脚本对每种做不同渲染：

    事件类型 脚本处理 前端真实表现
    routing_decision 打印"路由→XX"卡片 顶部转接卡片
    progress 打印"…检索知识库" 进度条
    token 逐字拼接打印 答案气泡逐字
    guidance 打印引导 + 按钮 引导卡片 + 跳转按钮
    pipeline_plan 打印多步骤计划 计划卡片（可点击各步）
    meta 打印来源 "引用了 N 篇文档"
    error 打印错误 错误提示
    done 自然结束循环 关闭流

    💡 解析模式是固定的：line.startswith("data:") → 去前缀 → json.loads → 按 type 分发。无论哪个分支，前端这套消费逻辑不变，变的只是收到哪几种事件。

    8.7.4 后端日志关键字¶

    阶段 日志关键字
    LLM 路由结果 unified_chat.llm_route_result label=qa reason=...
    路由降级（异常时） unified_chat.llm_route_failed fallback=qa
    QA 流式异常 unified_chat.qa_stream_error
    编排器加载某 Agent 图 orchestrator.agent_graph_loaded agent_type=qa
    编排器初始化 orchestrator.initialized
    应用启动就绪 app.started

    📎 前置拦截不留路由日志：李明说"你好""谢谢"时，_pre_filter 直接返回模板、return 退出，根本不会出现 llm_route_result——这是验证"前置拦截真的省了 LLM 调用"的依据：日志里数一数 llm_route_result 的条数，应该等于"非寒暄"消息数。

    8.7.5 常见问题排查¶

    现象 可能原因 排查方法
    所有消息都被路由到 qa LLM 路由降级了 查日志 llm_route_failed，看 DeepSeek key / 网络
    "你好"也走了 LLM 路由 _pre_filter 没命中 确认输入是否带了额外字（如"你好啊在吗"非精确匹配）
    qa 分支无 token 输出 知识库为空或 Milvus 未启动 查 qa_stream_error，确认 milvus Up + 知识库已写入
    multi_agent 不推计划 LLM 判成了别的 label 查 llm_route_result 的 label，调整 Prompt 措辞
    /chat/stream 401 未带 token 确认 Authorization: Bearer 头

    💡 这就是全章的收束：李明的五句话，把第 8 章的每条路径都走了一遍—— - "你好""谢谢"命中**前置拦截**，零 Token 秒回，日志里没有路由记录； - "什么是 RAG"经 LLM 路由**判为 qa，触发 **QA Agent 流式（第 5 章的图，经 _stream_qa_agent 透传）； - "帮我准备求职"判为 multi_agent，推**求职全链路计划**（注意是计划，不是跑 Pipeline）； - "我要模拟面试"判为 interview，推**引导卡片**导向 /interview（第 7 章李明真正的面试在那里发生）。

    节次 内容

    核心收获：

    • 集成 = 连线，不是重写：异常体系（3.3）、重试降级（3.5）、LLM 工厂（3.4）、MCP（5.11）、本地模型（5.⅘.8/5.9）、四个 Agent 图（4-7 章）全是已造好的零件，本章只做装配

    至此，EduAgent 的后端从地基（第 2-3 章）、四个 Agent（第 4-7 章）到系统集成（第 8 章）全部打通——一个 IT 教培 AI 原生多 Agent 教学辅助系统的完整后端，学员已能从零亲手复刻。

    2.10 测试FastAPI（选读）¶

    第一步：准备完整的服务端代码（demo.py）¶

    把下面的代码全部复制到 demo.py 中，保存。

    import asyncio
import json
from fastapi import FastAPI, Depends, HTTPException, File, UploadFile, status
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials
from pydantic import BaseModel, Field
from sse_starlette.sse import EventSourceResponse

app = FastAPI(title="EduAgent Demo")

# ---------- 2.5.2 健康检查 ----------
@app.get("/health")
async def health_check():
    return {"status": "ok"}

# ---------- 2.5.3 登录（请求体 + 响应模型） ----------
class LoginRequest(BaseModel):
    username: str = Field(..., description="用户名或邮箱")
    password: str = Field(..., description="密码")

class TokenResponse(BaseModel):
    access_token: str
    token_type: str = "bearer"
    role: str

@app.post("/login", response_model=TokenResponse)
async def login(req: LoginRequest):
    if req.username == "student01" and req.password == "Student@123456":
        return TokenResponse(access_token="fake-token-abc", role="student")
    # 为了演示，错误的也返回 guest
    return TokenResponse(access_token="", token_type="bearer", role="guest")

# ---------- 2.5.4 路径参数与查询参数 ----------
@app.get("/reviews/{review_id}")
async def get_review(review_id: str):
    return {"review_id": review_id, "status": "completed"}

@app.get("/reviews")
async def list_reviews(page: int = 1, size: int = 10):
    return {"page": page, "size": size}

# ---------- 2.5.5 依赖注入（模拟数据库 + 模拟鉴权） ----------
# 为了让你在 Postman 里能直接测通，这里不强制要求传 Token，而是直接返回模拟用户。
# 但为了演示真实鉴权流程，我加一个可选的 Bearer Token 校验（非必须，以便测试）。
# 这里我们使用文档中的 get_current_user 模拟版本。
async def get_db():
    return {"db": "fake_session"}

# 模拟的当前用户（不校验 Token，直接返回）
async def get_current_user():
    return {"user_id": "test_user", "role": "student"}

@app.get("/my-reviews")
async def my_reviews(
    db = Depends(get_db),
    current_user: dict = Depends(get_current_user),
):
    return {"user": current_user["user_id"], "data": "这是受保护的数据"}

# 如果你想知道带上真实 Authorization 头怎么测，这里额外写一个真实的 Bearer 校验示例（选看）
# 为了简化，依然不验签，只从Header取token展示
bearer_scheme = HTTPBearer(auto_error=False)  # auto_error=False 允许不带Token

@app.get("/secure-endpoint")
async def secure_endpoint(
    credentials: HTTPAuthorizationCredentials = Depends(bearer_scheme)
):
    if credentials is None:
        raise HTTPException(status_code=401, detail="请提供 Token")
    token = credentials.credentials
    return {"message": f"收到您的 Token: {token[:10]}..."}

# ---------- 2.5.6 文件上传 ----------
@app.post("/upload", status_code=202)
async def upload(file: UploadFile = File(...)):
    content = await file.read()
    return {"filename": file.filename, "size": len(content)}

# ---------- 2.5.7 SSE 流式响应 ----------
@app.post("/chat/stream")
async def chat_stream():
    async def event_generator():
        answer = "装饰器是一种包装函数的语法。"
        for char in answer:
            await asyncio.sleep(0.1)  # 模拟逐字生成
            yield {"data": json.dumps({"type": "token", "content": char})}
        yield {"data": json.dumps({"type": "done"})}
    return EventSourceResponse(event_generator())

# ---------- 2.5.8 错误处理 ----------
def find_review(review_id: str):
    return None  # 模拟查不到

@app.get("/reviews-with-error/{review_id}")
async def get_review_with_error(review_id: str):
    review = find_review(review_id)
    if review is None:
        raise HTTPException(status_code=404, detail="审查记录不存在")
    return review

    第四步：Postman 调试 SSE 的小技巧¶

    对于 /chat/stream 这个 SSE 接口，在 Postman 里操作时注意：

    1. 点击 Send 按钮。
    2. 响应区域不要切换到 "Pretty"（美化JSON模式），因为 SSE 不是标准 JSON，要切换到 "Raw"（原始） 或 "EventStream"（如果版本支持） 视图，你才能看到一串串 data: {...} 陆续出现。
    3. 你可以看到每个字确实是分批到达的，这就是“打字机效果”。

    注意：

    1. bearer_scheme = HTTPBearer(auto_error=False) 是做什么的？¶

    • HTTPBearer 是 FastAPI 提供的一个 安全工具类（位于 fastapi.security）。它的本职工作就是：解析 HTTP 请求头中的 Authorization 字段。
    • 它严格按照标准规范行事：只会识别格式为 Authorization: Bearer <你的Token字符串> 的请求头。
    • auto_error=False 是它的一个开关：
      • 默认情况下（True）：如果请求头里没有 Bearer Token，FastAPI 会自动抛出 403 异常，你根本拿不到 credentials。
      • 设置为 False：它**不再自动报错**，而是“乖乖地”把解析结果返回给你。解析成功就返回对象，解析失败（没有头或格式不对）就返回 None。

    总结：这个对象就是一个**“请求头提取器”**，专门负责从请求头里把 Token 字符串“拽”出来。

    2. credentials: HTTPAuthorizationCredentials = Depends(bearer_scheme) 是什么意思？¶

    这是 FastAPI 依赖注入（Depends） 的语法糖。

    • Depends(bearer_scheme)：告诉 FastAPI，在执行这个接口函数之前，先调用 bearer_scheme 这个提取器，把它的返回值拿过来。
    • credentials: HTTPAuthorizationCredentials：将提取器的返回值赋值给 credentials 变量。

    如果请求头是 Authorization: Bearer abc123xyz，那么 bearer_scheme 会返回一个对象，这个对象里包含两部分：

    • credentials.scheme：值为 "Bearer"
    • credentials.credentials：值为 "abc123xyz"（这就是你想要的 Token 字符串）

    3. 为什么你执行后显示 None，并提示“请提供 Token”？¶

    你收到这个提示，说明代码运行完全正常，且符合预期！

    原因很简单：你在 Postman（或浏览器）里发送请求时，没有在请求头中添加 Authorization 字段。

    因为设置了 auto_error=False，bearer_scheme 在请求头里找不到 Token，就返回了 None。紧接着你的代码判断 if credentials is None:，于是手动抛出了 401 异常。

    4. 怎么测试才能拿到 {"message": "收到您的 Token: ..."}？¶

    在 Postman 中，给这个请求**手动添加一个请求头**：

    • Key（键）：Authorization
    • Value（值）：Bearer 1234567890abcdef（注意 Bearer 后面有一个英文空格）

    请务必按照这个格式，不要写成 Token，也不要漏掉空格。标准格式必须是：Bearer <token>。

    添加后再次点击 Send，你的 credentials 就不会是 None，接口会返回： 

    {"message": "收到您的 Token: 1234567890..."}

    5. 为什么文档里说“依然不验签”？（真正的坑在这里）¶

    文档特意注明“依然不验签”，是因为：目前的代码只完成了“提取 Token”，并没有完成“验证 Token 是否合法”。

    • 现实场景中，拿到 credentials.credentials 之后，你应该调用 JWT 库去验签（比如 verify_jwt(token)），检查签名对不对、过期没有。
    • 如果在验签时发现无效，你应该手动抛出 HTTPException(status_code=401)。

    把这两者结合起来，才是完整的鉴权逻辑：

    @app.get("/secure-endpoint")
async def secure_endpoint(
    credentials: HTTPAuthorizationCredentials = Depends(bearer_scheme)
):
    if credentials is None:
        raise HTTPException(status_code=401, detail="请提供 Token")
    
    token = credentials.credentials
    # 真正的项目里，这里会补上这一行：
    # user = verify_jwt(token)  # 验签，如果失败就抛 401
    
    return {"message": f"收到您的 Token: {token[:10]}..."}

    一句话总结¶

    • HTTPBearer = 专门找 Authorization: Bearer xxx 头的**提取器**。
    • Depends(...) = 让 FastAPI 自动把提取器运行结果塞进你的函数参数里。
    • 你看到 None = 请求头里没带 Token。加上 Authorization: Bearer xxx 就能解决。
    • 提取归提取，验签归验签，现在的代码只做了一半，所以文档说“依然不验签”，目的是让你先理解提取机制。

    总结¶

    • 你只需 启动服务 → 打开 Postman（或浏览器 /docs） → 按表格输入 URL 和参数。
    • 通过观察返回的 状态码、响应体格式 以及 SSE 的流式效果，就能直观理解 FastAPI 每个装饰器、每个参数的作用。
    • 对于依赖注入，你可以尝试修改 get_current_user 的返回值，或者去掉 Depends，观察接口行为变化，加深理解。
    • 所有接口均无外部依赖（无需真实数据库或 Redis），开箱即测。

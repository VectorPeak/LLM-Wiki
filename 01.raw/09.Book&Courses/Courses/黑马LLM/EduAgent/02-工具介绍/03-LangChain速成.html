    2.3 LangChain 速成¶

    学习目标¶

    • 了解 LangChain 在 EduAgent 里扮演的角色：统一的大模型调用层
    • 掌握用 init_chat_model 创建模型实例（LangChain 1.x 新写法），并接入 DeepSeek
    • 掌握消息体系 SystemMessage / HumanMessage / AIMessage
    • 掌握异步调用 ainvoke，并用 .text 属性取回文本
    • 掌握 with_structured_output：让大模型按 Pydantic 模型结构化输出（本节重点，承接 2.2）
    • 了解流式输出 astream
    • 知道为什么本项目必须用新版 API、哪些旧写法被禁用

    ⚠️ 版本提醒（务必注意）：本项目锁定 LangChain 1.x（1.2.10）。网上大量旧教程用的是 0.x 的 API（如 LLMChain、ChatOpenAI、initialize_agent、ConversationChain），那些写法在本项目里一律禁止使用，照抄会报错或行为不一致。本节教的全部是 1.x 新写法。

    📌 运行说明：前两节的 demo 是纯 Python，不联网就能跑。但本节的 demo 会**真正调用 DeepSeek 大模型**，需要一个 DeepSeek API Key 才能跑出结果。没有 Key 也没关系——先看懂写法，等第三章把环境和 Key 配好后，再回来动手跑。

    2.3.1 LangChain 是什么、在项目里干什么¶

    市面上的大模型有很多（DeepSeek、通义千问、OpenAI……），每家的 SDK 调用方式都不一样。LangChain 的核心价值，就是给各种大模型提供一套「统一接口」：你用同一套代码就能调用不同的模型，将来换模型时业务代码几乎不用改。

    在 EduAgent 里，LangChain 主要负责两件事：

    1. 统一地调用 DeepSeek 大模型——发消息、拿回答。
    2. 把大模型的输出「约束」成结构化数据——这是本节的重点，也是后面简历、批改、问答等 Agent 的实现基础。

    LangChain 进入 1.x 后做了大重构，许多 0.x 的类和函数被废弃或迁移。所以本节有一条贯穿始终的原则：只学 1.x 新写法。文末会给你一张「禁用 / 必用」对照表。

    2.3.2 用 init_chat_model 创建模型（1.x 新写法）¶

    在 LangChain 1.x 里，创建一个大模型实例的标准方式是 init_chat_model（注意：不是 旧版的 ChatOpenAI(...)）。DeepSeek 提供的是「OpenAI 兼容接口」，所以我们通过指定 model_provider="openai" + DeepSeek 的 base_url 来接入它：

    from langchain.chat_models import init_chat_model

llm = init_chat_model(
    model="deepseek-chat",                       # 模型名称
    model_provider="openai",                     # 走 OpenAI 兼容协议（关键）
    api_key="sk-你的DeepSeekKey",                # DeepSeek 的 API Key
    base_url="https://api.deepseek.com/v1",      # DeepSeek 接口地址（关键）
    temperature=0,                               # 输出的随机性，0 = 最稳定
)

    逐个理解关键参数：

    • model_provider="openai" + base_url=...：这两个配合使用，意思是「用 OpenAI 的协议格式，但把请求发到 DeepSeek 的地址」。

      这里有个**必须避开的坑**：千万**不要**把模型名写成 "deepseek/deepseek-chat" 这种带前缀的形式，那会触发框架去找另一个专用的 langchain-deepseek 包，导致出错。正确做法就是上面这样：model="deepseek-chat" + model_provider="openai" + base_url。

    • temperature：控制输出的随机性，范围 0~1（或更高）。0 表示「每次尽量给最确定、最稳定的答案」，适合评分、批改这种需要稳定的场景；对话场景可以调到 0.3~0.7 让回答更自然。

    EduAgent 里的真实应用：项目不会在业务代码里到处写 init_chat_model，而是把它统一封装进一个 LLM Factory（core/llm_factory.py），所有 Agent 都通过工厂获取模型。这样 Key、地址、超时、重试等配置只需在一处管理。我们会在第三章实现它。本节你先理解 init_chat_model 本身怎么用。

    2.3.3 消息体系：System / Human / AI¶

    和大模型对话时，每一句话都有一个「角色」。LangChain 用三种消息类来表示：

    from langchain_core.messages import SystemMessage, HumanMessage, AIMessage
    • SystemMessage（系统消息）：给大模型设定身份和规则，比如「你是一位严谨的简历评审专家」。它影响大模型整体的行为风格。
    • HumanMessage（用户消息）：用户实际说的话 / 提出的问题。
    • AIMessage（AI 消息）：大模型的回复。我们调用模型后，拿到的就是一个 AIMessage；在多轮对话里，也用它来表示「AI 之前说过的话」。

    调用模型时，我们传入一个**消息列表**，通常是「一条系统消息 + 一条用户消息」：

    messages = [
    SystemMessage(content="你是一位专业的 Python 讲师，用简洁的语言回答。"),
    HumanMessage(content="什么是装饰器？一句话解释。"),
]

    关于提示词的写法：LangChain 也提供了 ChatPromptTemplate 这类「提示词模板」工具，但 EduAgent 选择更直白的方式——直接用 Python 的 f-string 拼出提示词文本，放进 HumanMessage(content=...) 里。这样提示词一目了然、好调试。本课程沿用项目的这种写法，不引入额外的模板概念。

    2.3.4 调用模型：ainvoke 与 .text¶

    因为整个项目是异步的（回顾 2.1），我们用**异步方法 ainvoke** 来调用模型（a 代表 async）。它返回一个 AIMessage，我们用 **.text 属性**取出其中的文本：

    import asyncio
from langchain.chat_models import init_chat_model
from langchain_core.messages import SystemMessage, HumanMessage

llm = init_chat_model(
    model="deepseek-chat",
    model_provider="openai",
    api_key="sk-你的DeepSeekKey",
    base_url="https://api.deepseek.com/v1",
    temperature=0,
)

async def main():
    messages = [
        SystemMessage(content="你是一位专业的 Python 讲师，用一句话回答。"),
        HumanMessage(content="什么是装饰器？"),
    ]
    response = await llm.ainvoke(messages)    # 异步调用，返回一个 AIMessage
    print(response.text)                       # 用 .text 取出文本（属性，不加括号！）

asyncio.run(main())

    预期输出（大致如此）：

    装饰器是一种在不修改原函数代码的前提下，为其增加额外功能的函数包装语法。

    这里有一个**本项目强制的细节**，请务必记住：

    取文本用 response.text（属性，不要加括号），绝对不要写成 response.text()。在 LangChain 1.x 里 .text 是属性而不是方法，写成 .text() 会出错。这是项目明确列入「禁用」的写法之一。

    （补充：AIMessage 还有一个 .content 字段是更底层的原始内容，它有时是字符串、有时是结构化的内容块；日常取纯文本时，用 .text 最省心。）

    模型也有同步版的 invoke，但本项目全程异步，统一用 ainvoke。

    2.3.5 重点：with_structured_output —— 让大模型按 Pydantic 填空¶

    这是本节最重要的能力，它把 2.2 学的 Pydantic 真正用起来。

    普通调用拿回的是一段**自由文本**，但很多业务需要的是**结构化数据**：比如简历审查要拿到「姓名、教育经历、各维度分数」这种字段分明的结果。如果让大模型返回一段文本，我们还得自己费劲地解析——又容易出错。

    LangChain 的 with_structured_output 解决了这个问题：你把一个 Pydantic 模型「绑定」到大模型上，大模型就会**严格按照这个模型的结构来填空**，并**直接返回一个 Pydantic 对象**（而不是文本，也不需要你手动解析 JSON）。

    import asyncio
from pydantic import BaseModel, Field
from langchain.chat_models import init_chat_model
from langchain_core.messages import SystemMessage, HumanMessage

llm = init_chat_model(
    model="deepseek-chat", model_provider="openai",
    api_key="sk-你的DeepSeekKey",
    base_url="https://api.deepseek.com/v1", temperature=0,
)

# ① 定义期望的输出结构（回顾 2.2：description 就是给大模型的填空指令）
class PersonInfo(BaseModel):
    name: str = Field(description="姓名")
    age:  int = Field(description="年龄（整数）")
    city: str = Field(description="所在城市")

# ② 把模型绑定上去，得到一个「结构化输出版」的 llm
structured_llm = llm.with_structured_output(PersonInfo, method="function_calling")

async def main():
    messages = [
        SystemMessage(content="你负责从文本中抽取人物信息。"),
        HumanMessage(content="我叫小明，今年 25 岁，住在上海。"),
    ]
    # ③ 调用后直接返回 PersonInfo 对象，不是文本！
    result: PersonInfo = await structured_llm.ainvoke(messages)
    print(type(result))      # <class '__main__.PersonInfo'>
    print(result.name)       # 小明
    print(result.age)        # 25
    print(result.city)       # 上海

asyncio.run(main())

    注意两个关键点：

    1. method="function_calling" 必须写。这是本项目又一条强制规范——DeepSeek 不支持另一种 json_schema 模式，所以结构化输出必须指定 method="function_calling"，否则会报错。
    2. 返回值直接就是 Pydantic 对象。你能立刻用 result.name、result.age 点号访问，不需要自己解析任何 JSON 字符串。要存数据库时，再用 2.2 学的 result.model_dump() 转成字典即可。

    EduAgent 里的真实应用：这是项目的「核心招式」，反复出现—— - 简历 Agent 用它把简历文本抽成 ResumeStructured，再做六个维度的结构化评分； - 试卷批改 Agent 用它输出每道题的评分结果和薄弱点报告； - 问答、面试 Agent 用它生成结构化的中间结果。

    凡是「需要大模型给出格式固定的结果」，本项目一律用 with_structured_output + Pydantic，绝不让大模型返回文本再手动解析。

    2.3.6 流式输出：astream（了解即可）¶

    当用户问问题时，我们希望答案像打字机一样**一个字一个字地蹦出来**，而不是憋几秒后一次性弹出。这就是「流式输出」，用异步方法 astream 实现：

    async def main():
    messages = [HumanMessage(content="用三句话介绍一下 Python。")]
    async for chunk in llm.astream(messages):   # 逐块接收
        print(chunk.text, end="", flush=True)    # 拼接打印，形成打字机效果

asyncio.run(main())

    astream 会不断「吐」出一小块一小块的内容（chunk），我们边收边显示，用户就能看到答案在实时生成。

    EduAgent 里的真实应用：智能问答和模拟面试都用流式输出。项目里在模型层用 streaming=True 打开流式能力，再在 API 层借助 LangGraph 的事件流，把生成的 token 通过 SSE 实时推给前端。这套完整链路我们会在第五章（问答）和第八章（统一入口）里实现。本节你先理解 astream 这个底层能力即可。

    2.3.7 必须用新版 API：禁用 / 必用对照表¶

    最后把本项目的硬性规范汇总一下。当你在网上搜到的代码用了「禁用」列里的写法时，说明它是旧版教程，不要照抄：

    用途 ❌ 禁用（0.x 旧写法） ✅ 必用（1.x 新写法）
    创建模型 ChatOpenAI(...) init_chat_model(...)
    串联调用 LLMChain / AgentExecutor / initialize_agent LangGraph 状态图（见 2.4）
    多轮记忆 ConversationBufferMemory / ConversationChain Checkpointer（见 2.4）
    取回文本 message.text()（当方法调用） message.text（当属性）
    结构化输出 自己解析 JSON 字符串 with_structured_output(模型, method="function_calling")

    一句话总结这条规范背后的原因：LangChain 1.x 重构后，旧 API 大多已废弃；锁定版本 + 统一新 API，是为了让你写的代码稳定、可复现、不踩坑。

    章节总结¶

    本节我们学会了用 LangChain 1.x 调用大模型，并把它和 Pydantic 串了起来：

    • 角色：LangChain 是统一的大模型调用层，本项目用它调 DeepSeek、并约束输出结构。
    • 创建模型：用 init_chat_model(model="deepseek-chat", model_provider="openai", base_url=...) 接入 DeepSeek，注意不能用 deepseek/ 前缀。
    • 消息体系：SystemMessage（设定身份）/ HumanMessage（用户输入）/ AIMessage（AI 回复）。
    • 调用与取文本：异步用 await llm.ainvoke([...])，用 .text（属性，不加括号）取文本。
    • 结构化输出（重点）：with_structured_output(Pydantic模型, method="function_calling") 让大模型直接返回 Pydantic 对象，无需手动解析——这是简历、批改、问答 Agent 的核心招式。
    • 流式输出：astream 实现打字机效果，用于问答和面试。
    • 版本规范：全程使用 1.x 新 API，禁用 ChatOpenAI、LLMChain、message.text() 等旧写法。

    下一节 2.4 LangGraph 速成，我们将学习本项目的绝对核心——用「图」把节点和状态组织起来，亲手写出第一个能跑、带条件分支和记忆的最小 Agent。

    2.7 用 SQLAlchemy 异步操作数据库¶

    学习目标¶

    • 理解为什么用 SQLAlchemy 访问数据库，而不是在代码里直接写数据库驱动
    • 掌握用 SQLAlchemy 异步引擎连接数据库（create_async_engine + AsyncSession）
    • 掌握项目的核心写法：用 text() 执行原生 SQL + 参数化查询（防注入）
    • 掌握读取查询结果（fetchone / fetchall / mappings）
    • 把数据库操作和前面的 Depends(get_db)、异步串起来

    📌 前置：上一节 2.6 你已经认识了 PostgreSQL、并亲手在真实库上做过 CRUD（含 PG 专属特性）。本节换一个角度——学**怎么用 Python 异步代码去操作数据库**，这才是项目里真正的访问方式。

    运行说明：本节 demo 为了零配置仍用 SQLite（pip install sqlalchemy aiosqlite）。这里 SQLite 只是为了**演示 SQLAlchemy 的用法本身**——SQLAlchemy 的 API 和连接 PostgreSQL 完全一样，区别只在连接地址那一行（你在 2.6 已经连过真实 PG 了，把地址换成 postgresql+asyncpg://... 即可）。

    ⚠️ 本项目不使用 SQLAlchemy 的 ORM 模型（不写 declarative_base、Mapped、relationship），而是直接用 text() 写原生 SQL。本节只教这种方式。网上很多 SQLAlchemy 教程教 ORM，本项目用不到，别被带偏。

    2.7.1 从「手敲 SQL」到「用 Python 操作数据库」¶

    在 2.6 里，你是用 psql / PyCharm 手敲 SQL 来操作 PostgreSQL 的。但在真实应用里，是**程序**在自动执行这些 SQL——用户登录时，后端代码要自动去查 users 表；批改完成时，代码要自动把结果写进 exam_reviews 表。

    那么 Python 代码怎么连数据库、怎么发 SQL、怎么拿结果？这就是本节要解决的。我们用的工具是 SQLAlchemy——一个给各种数据库提供统一访问接口的 Python 库。因为整个项目是异步的（回顾 2.1，数据库查询是典型的 I/O 等待），我们用它的**异步**版本。

    一句话定位：2.6 教你「人怎么操作 PostgreSQL」，本节教你「Python 程序怎么操作数据库」。 两者结合，你既能手动验证、又能让代码自动读写。你在 2.6 练过的 SELECT / INSERT / UPDATE / DELETE，本节会原封不动地交给 SQLAlchemy 去执行。

    2.7.2 用 SQLAlchemy 异步连接数据库¶

    我们不直接跟数据库对话，而是通过 SQLAlchemy 这个工具库。因为整个项目是异步的（回顾 2.1，数据库查询是典型的 I/O 等待），我们用它的**异步**版本。

    连接分三步：建引擎 → 建会话工厂 → 用会话：

    from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker, AsyncSession

# ① 创建异步引擎（管理数据库连接池）
#    项目里是 PostgreSQL： "postgresql+asyncpg://用户:密码@主机:端口/库名"
#    本 demo 用 SQLite 零配置演示；换成 PostgreSQL 只改这一行（2.6 你已连过真实 PG）：
engine = create_async_engine("sqlite+aiosqlite:///demo.db")

# ② 创建「会话工厂」，之后每次操作数据库都从它产出一个会话
AsyncSessionLocal = async_sessionmaker(engine, expire_on_commit=False)
    • 引擎（engine）：管理「连接池」——一组可复用的数据库连接，避免每次都重新建立连接。
    • 会话（session）：你和数据库的一次「对话」。每次要执行 SQL，就从 AsyncSessionLocal() 拿一个会话来用。
    • 连接地址的唯一区别：项目用 postgresql+asyncpg://...，本 demo 用 sqlite+aiosqlite:///demo.db。换地址即可，下面的代码完全通用。

    2.7.3 执行 SQL：text() + 参数化查询（项目核心写法）¶

    这是本节最重要的一节。在 SQLAlchemy 里执行原生 SQL，要把 SQL 字符串用 text() 包起来，再交给会话的 execute 方法。

    而当 SQL 里需要嵌入变量时（比如「查用户名等于某个值的用户」），绝对不要用 f-string 直接拼接，而要用**参数化查询**：在 SQL 里用 :名字 占位，再用一个字典把值传进去。

    from sqlalchemy import text

# ✅ 正确：参数化查询。:val 是占位符，真实值通过字典传入
await session.execute(
    text("SELECT id, role FROM users WHERE username = :val"),
    {"val": user_input},
)

# ❌ 危险：用 f-string 拼 SQL，会有「SQL 注入」安全漏洞，项目严禁这样写
# await session.execute(text(f"SELECT id FROM users WHERE username = '{user_input}'"))

    为什么必须参数化？ 如果用户输入的是 ' OR '1'='1，f-string 拼出来的 SQL 就被篡改了，可能泄露整张表的数据——这就是著名的「SQL 注入」攻击。参数化查询会把用户输入当作**纯数据**而非 SQL 代码处理，从根上杜绝这个风险。项目里所有 SQL 都用 :名字 + 字典的参数化方式。

    执行查询后，用以下方式读取结果：

    result = await session.execute(
    text("SELECT id, username, role FROM users WHERE role = :r"),
    {"r": "student"},
)

row = result.fetchone()        # 取第一行；没有则返回 None
print(row.username, row.role)  # 用「点号 + 列名」访问字段

rows = result.fetchall()       # 取所有行（列表）

# 或者把每行变成字典，便于遍历
for m in result.mappings().all():
    print(m["username"], m["role"])
    • fetchone()：取一行，用 row.列名 访问。常用于「查一个用户」。
    • fetchall()：取全部行的列表。
    • mappings().all()：取全部行，但每行是字典（m["列名"]），遍历更方便。

    EduAgent 里的真实应用：登录接口就是这么查用户的——text("SELECT ... FROM users WHERE username = :val OR email = :val") + {"val": 输入}，再 fetchone() 拿到 row.password_hash 去校验密码。试卷、简历、问答等所有数据读写，统一用这套 text() + 参数化 + execute 的写法。

    关于 commit()（提交事务）：INSERT / UPDATE / DELETE 这类改动，执行后必须 await session.commit() 才会真正写入数据库；如果中途出错，可以 await session.rollback() 撤销。在 EduAgent 里，你几乎不用手动写 commit——回顾 2.5.5 的 get_db 依赖，它已经在 yield 之后帮你自动 commit、出错自动 rollback 了。

    2.7.5 串起来：在接口里操作数据库¶

    最后把本节和 2.5 的依赖注入连起来，看一段贴近项目的登录查询（简化版）：

    from fastapi import APIRouter, Depends, HTTPException
from sqlalchemy import text
from sqlalchemy.ext.asyncio import AsyncSession
from backend.dependencies import get_db        # 2.5 学的依赖

router = APIRouter()

@router.post("/login")
async def login(req: LoginRequest, db: AsyncSession = Depends(get_db)):
    # 用注入进来的 db 会话，参数化查询用户
    result = await db.execute(
        text("SELECT id, password_hash, role FROM users WHERE username = :val"),
        {"val": req.username},
    )
    row = result.fetchone()
    if not row:
        raise HTTPException(status_code=401, detail="用户名或密码错误")

    # 密码校验是 CPU 密集型，用 run_in_executor 丢线程池（回顾 2.1.4）
    loop = asyncio.get_running_loop()
    ok = await loop.run_in_executor(None, verify_password, req.password, row.password_hash)
    if not ok:
        raise HTTPException(status_code=401, detail="用户名或密码错误")

    return {"role": row.role}   # 实际项目里这里会签发 JWT Token

    看这段代码是怎么把前面几节融会贯通的：

    • db: AsyncSession = Depends(get_db) —— 2.5 的依赖注入，自动拿到数据库会话；
    • text(...) + {"val": ...} —— 本节的参数化查询；
    • run_in_executor(...) —— 2.1 的「同步阻塞操作丢线程池」；
    • async def / await —— 2.1 的异步。

    这就是 EduAgent 接口的典型样貌。 你现在已经能看懂它的每一个部分了。

    章节总结¶

    本节我们补齐了数据库这块拼图：

    • 本节定位：在 2.6「人操作 PostgreSQL」的基础上，学会「Python 异步操作数据库」。
    • 异步连接：create_async_engine + async_sessionmaker 建立连接，换数据库只需换连接地址。
    • 核心写法：用 text() 执行原生 SQL，用 :名字 + 字典做**参数化查询**防 SQL 注入；用 fetchone / fetchall / mappings 读结果。项目不用 ORM。
    • 事务：改动后 commit 才生效，项目里由 get_db 依赖自动处理。
    • 融会贯通：一个真实登录接口串起了依赖注入、参数化查询、run_in_executor、异步。

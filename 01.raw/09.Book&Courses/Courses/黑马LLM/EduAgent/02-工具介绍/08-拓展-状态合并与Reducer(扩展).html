    2.8 状态合并与 Reducer（选读）¶

    这是对应主线 2.4.6 的选读拓展。如果你对「节点明明只返回一个小字典，State 是怎么更新的？」「add_messages 到底是什么魔法？」感到好奇，这篇会讲清楚。不读它完全不影响你继续学习主线。

    本文所有 demo 不需要大模型，可独立运行。

    学习目标¶

    • 理解 LangGraph 默认的状态合并规则（覆盖）
    • 理解为什么有时「覆盖」会出问题，从而引出 Reducer
    • 彻底搞懂 add_messages 的本质，并能写一个自己的 Reducer

    1. 默认规则：节点返回的字典「覆盖式」合并进 State¶

    回顾主线 2.4.3 的约定：节点不直接改 State，而是 return 一个「只含要更新字段」的字典。那么 LangGraph 拿到这个字典后，是怎么把它并进 State 的呢？

    默认规则非常简单：你返回哪个字段，就用新值覆盖 State 里那个字段；没返回的字段保持不变。 看个例子：

    from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class S(TypedDict):
    a: int
    b: int

def node1(state: S) -> dict:
    return {"a": 100}        # 只更新 a，不动 b

builder = StateGraph(S)
builder.add_node("n1", node1)
builder.add_edge(START, "n1")
builder.add_edge("n1", END)
graph = builder.compile()

print(graph.invoke({"a": 1, "b": 2}))

    输出：

    {'a': 100, 'b': 2}

    a 被覆盖成 100，b 没被节点返回，保持原值 2。这就是默认的「覆盖式合并」——大多数普通字段（字符串、数字）用这个规则刚刚好。

    2. 问题来了：列表字段用「覆盖」会丢数据¶

    但有一类字段，「覆盖」会出大问题——那就是**需要不断累积的列表**，最典型的就是「对话消息历史」。

    设想一个聊天场景：State 里有一个 messages 列表。第一轮加进去一条消息，第二轮我们又想加一条。如果用默认的覆盖规则：

    from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class ChatS(TypedDict):
    messages: list

def add_one(state: ChatS) -> dict:
    return {"messages": ["新消息"]}     # 想「加」一条，但默认是「覆盖」

builder = StateGraph(ChatS)
builder.add_node("n", add_one)
builder.add_edge(START, "n")
builder.add_edge("n", END)
graph = builder.compile()

# 初始已经有两条历史消息
print(graph.invoke({"messages": ["历史1", "历史2"]}))

    输出：

    {'messages': ['新消息']}

    糟糕——历史消息「历史1、历史2」全没了，被整个覆盖掉了！这显然不是我们想要的。我们想要的是 ['历史1', '历史2', '新消息']。

    3. 解决方案：Reducer —— 自定义「合并规则」¶

    LangGraph 允许你给某个字段**指定一个自定义的合并规则**，这个规则就叫 Reducer。写法是用 Annotated 把「字段类型」和「合并函数」绑在一起：

    Annotated[字段类型, 合并函数]

    合并函数接收两个参数：(旧值, 新值)，返回「合并后的值」。比如，对列表我们想要的是「拼接」，那合并函数就是「旧列表 + 新列表」。Python 标准库的 operator.add 正好能做列表拼接：

    import operator
from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END

class ChatS(TypedDict):
    # 关键：用 operator.add 作为合并规则 → 列表会「拼接」而不是「覆盖」
    messages: Annotated[list, operator.add]

def add_one(state: ChatS) -> dict:
    return {"messages": ["新消息"]}

builder = StateGraph(ChatS)
builder.add_node("n", add_one)
builder.add_edge(START, "n")
builder.add_edge("n", END)
graph = builder.compile()

print(graph.invoke({"messages": ["历史1", "历史2"]}))

    输出：

    {'messages': ['历史1', '历史2', '新消息']}

    这次历史保住了，新消息被**追加**到末尾。秘密就在 Annotated[list, operator.add]：它告诉 LangGraph「这个字段的合并方式是『旧值 + 新值』」。

    你可以把 Reducer 理解为：节点返回的不是「最终值」，而是「这一步的贡献」，由 Reducer 决定这份贡献怎么并进总账。 默认 Reducer 是「直接替换」，operator.add 则是「累加 / 拼接」。

    4. add_messages：为消息列表量身定制的 Reducer¶

    理解了 Reducer，add_messages 就不神秘了——它就是 LangChain 为「消息列表」专门写的一个 Reducer，比 operator.add 更聪明：

    from langgraph.graph.message import add_messages

class ChatState(TypedDict):
    messages: Annotated[list, add_messages]

    它在「追加」的基础上，还额外处理了几件消息场景特有的事：

    • 自动把字符串、字典等格式包装成标准的消息对象；
    • 如果新消息带有和旧消息相同的 id，会做**更新**而不是重复追加（这在流式输出等场景很有用）。

    所以在 EduAgent 里，凡是 State 里的对话消息字段，统一写成 Annotated[list[BaseMessage], add_messages]。这一行就让「多轮对话历史自动累积」这件事变得理所当然。

    5. 一个加深理解的小例子：自定义计数 Reducer¶

    最后用一个例子巩固——我们做一个「每经过一个节点就把计数加 1」的累加器，自己写一个 Reducer：

    from typing import Annotated, TypedDict
from langgraph.graph import StateGraph, START, END

def add(old: int, new: int) -> int:     # 自定义 Reducer：把新旧值相加
    return old + new

class CounterState(TypedDict):
    count: Annotated[int, add]           # count 字段的合并方式 = 相加

def step(state: CounterState) -> dict:
    return {"count": 1}                  # 每个节点只「贡献」+1

builder = StateGraph(CounterState)
builder.add_node("a", step)
builder.add_node("b", step)
builder.add_node("c", step)
builder.add_edge(START, "a")
builder.add_edge("a", "b")
builder.add_edge("b", "c")
builder.add_edge("c", END)
graph = builder.compile()

print(graph.invoke({"count": 0}))

    输出：

    {'count': 3}

    每个节点都只返回 {"count": 1}，但因为 Reducer 是「相加」，三个节点跑下来，count 累积成了 3。如果是默认的覆盖规则，结果会是 1。

    总结¶

    这篇拓展讲清了 LangGraph 状态更新的底层机制：

    • 默认规则：节点返回的字段「覆盖」进 State，没返回的保持不变——适合普通字段。
    • Reducer：用 Annotated[类型, 合并函数] 自定义合并规则，把「覆盖」改成你要的行为（如拼接、累加）。
    • add_messages：就是为消息列表定制的 Reducer，实现历史自动追加，是项目里所有对话字段的标配。

    理解了 Reducer，你以后看任何 LangGraph 的 State 定义，看到 Annotated[..., 某函数] 就能立刻明白「这个字段的更新方式被定制过」。现在可以放心回到主线，继续 2.5 FastAPI 速成。

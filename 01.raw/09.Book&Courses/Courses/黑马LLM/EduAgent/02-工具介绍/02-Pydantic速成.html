    2.2 Pydantic 速成¶

    学习目标¶

    • 理解 Pydantic 是什么、它在 EduAgent 里解决什么问题
    • 掌握用 BaseModel 定义数据模型，理解「自动类型校验」
    • 掌握 Field 的 description / default / default_factory
    • 理解为什么 Field 的 description 是「让大模型输出结构化数据」的关键
    • 掌握嵌套模型、Optional、list[...] 等组合写法
    • 掌握用 model_dump() 在「模型」和「字典」之间转换
    • 了解 Enum 与 BaseSettings 的配合用法

    本节所有代码可独立运行。Pydantic 已经是项目依赖，如果你单独练习，先 pip install pydantic 即可。本项目用的是 Pydantic v2。

    2.2.1 Pydantic 是什么，解决什么问题¶

    写程序时，我们经常要处理**来自外部、不可全信的数据**：用户提交的表单、数据库查询结果、第三方接口返回的 JSON……这些数据「该有哪些字段、字段是什么类型」，全靠我们自己一个个手动检查，又啰嗦又容易漏。

    来感受一下「没有 Pydantic」时的痛苦——假设我们要确保一份学员数据合法：

    def check_student(data: dict):
    if "name" not in data or not isinstance(data["name"], str):
        raise ValueError("name 缺失或类型错误")
    if "age" not in data or not isinstance(data["age"], int):
        raise ValueError("age 缺失或类型错误")
    if data["age"] < 0:
        raise ValueError("age 不能为负")
    # ……字段一多，这样的检查会写到天荒地老
    return data

    Pydantic 把这一切自动化了。你只需要用 Python 的「类型注解」声明「数据应该长什么样」，Pydantic 就会自动帮你校验、自动帮你做合理的类型转换、出错时给出清晰的报错。

    在 EduAgent 里，Pydantic 有两个核心用途：

    1. 让大模型输出结构化数据（最重要）。比如让大模型从简历里抽取出「姓名、教育经历、项目经历」并以固定结构返回——靠的就是 Pydantic 模型。这是简历审查、试卷批改、问答等多个 Agent 的基础。
    2. 读取配置与接口参数。比如从 .env 文件读数据库密码（BaseSettings），以及定义 API 的请求/响应格式。

    2.2.2 第一个模型：BaseModel 与自动校验¶

    用 Pydantic，第一步是定义一个**继承自 BaseModel 的类**，用类型注解写明每个字段：

    from pydantic import BaseModel

class Student(BaseModel):
    name: str          # 字符串
    age: int           # 整数

# 用关键字参数创建实例
s = Student(name="小明", age=18)
print(s.name)          # 小明
print(s.age)           # 18
print(s)               # name='小明' age=18

    Pydantic 会在创建实例时**自动校验类型**。它还会做**合理的自动转换**——比如你传了一个字符串 "18"，它会自动转成整数 18：

    s = Student(name="小红", age="18")   # age 传的是字符串
print(s.age, type(s.age))            # 18 <class 'int'>  → 自动转成了 int

    但如果数据**没法合理转换**，Pydantic 会立刻抛出 ValidationError，并告诉你错在哪：

    from pydantic import BaseModel, ValidationError

class Student(BaseModel):
    name: str
    age: int

try:
    Student(name="小刚", age="十八")   # "十八" 无法转成整数
except ValidationError as e:
    print(e)

    输出（节选）：

    1 validation error for Student
age
  Input should be a valid integer, unable to parse string as an integer ...

    这就是 Pydantic 的核心价值：你只管声明「数据该长什么样」，校验和报错它全包了。

    2.2.3 Field：给字段加「说明书」¶

    光有类型还不够。很多时候我们想给字段补充更多信息：它是必填的还是可选的？默认值是什么？这个字段是什么含义？这些都通过 Field 来表达。

    from pydantic import BaseModel, Field

class UserProfile(BaseModel):
    name:  str = Field(description="用户姓名")            # 必填：没有默认值
    phone: str = Field(default="", description="手机号")  # 可选：有默认值 ""
    age:   int = Field(default=18, description="年龄")    # 可选：默认 18

    几个要点：

    • 必填 vs 可选：Field 里**没写 default 的字段就是必填**（创建实例时必须提供，否则报错）；写了 default 的就是可选的。
    • description：对字段含义的文字说明。请记住这个参数——下一节你会看到它有多重要。

    一个常见坑：列表 / 字典的默认值要用 default_factory¶

    如果一个字段的默认值是「空列表」或「空字典」这类**可变对象**，**不要**写 default=[]，而要写 default_factory=list：

    from pydantic import BaseModel, Field

class Article(BaseModel):
    title: str  = Field(description="标题")
    tags:  list[str] = Field(default_factory=list, description="标签列表")  # 正确写法

a = Article(title="Python 入门")
print(a.tags)    # []  —— 默认是一个空列表

    为什么不能用 default=[]？ 因为如果所有实例共享同一个列表默认值，往一个实例里加元素会「污染」到其他实例。default_factory=list 的意思是「每次创建实例时，都新建一个空列表」，从而避免这个隐患。在 EduAgent 里，凡是列表字段一律用 default_factory=list，你照做就对了。

    2.2.4 重点：description 为什么是「大模型结构化输出」的关键¶

    这是本节最该理解的一点，它直接关系到后面好几个 Agent 的实现原理。

    我们后面会用到 LangChain 的一个能力：让大模型不要返回一段自由文本，而是严格按照一个 Pydantic 模型的结构来填空（对应代码 llm.with_structured_output(你的模型)，第 2.3 节会讲）。

    那么大模型怎么知道每个字段该填什么？答案就是：它会读取你这个 Pydantic 模型的「字段名 + 类型 + description」，把它们当成填空指令。 换句话说：

    你给字段写的 description，就是你对大模型下达的精确指令。 description 写得越清楚，大模型填得越准。

    来看 EduAgent 简历审查里真实的一个模型（节选）：

    from pydantic import BaseModel, Field

class EducationItem(BaseModel):
    """单条教育经历"""
    school:   str = Field(description="学校名称")
    major:    str = Field(description="专业名称")
    degree:   str = Field(description="学历：本科/专科/硕士等")
    duration: str = Field(description="在校时间，如 2020.09 - 2024.06")
    gpa:      str = Field(default="", description="GPA 或成绩（可选）")

    当我们把一份简历文本和这个模型一起交给大模型时，大模型读到：

    • school（字符串，「学校名称」）→ 它就去简历里找学校名填进来；
    • degree（字符串，「学历：本科/专科/硕士等」）→ description 里给的例子帮它规范了输出格式；
    • duration（「在校时间，如 2020.09 - 2024.06」）→ 连日期格式都被这句话约束住了。

    所以**写 Pydantic 模型 = 设计大模型的输出格式 = 写提示词的一部分**。这就是为什么本项目里几乎每个字段都认真写了 description。等你到第四章（简历 Agent）和第五章（问答 Agent）就会反复用到这个套路。

    2.2.5 组合复杂结构：嵌套模型与列表¶

    真实业务的数据往往是「模型套模型」。比如一份完整简历，里面有**多条**教育经历、**多条**项目经历。Pydantic 支持把一个模型作为另一个模型的字段类型，用 list[子模型] 表示「一个列表，里面每一项都是这种子模型」：

    from pydantic import BaseModel, Field

class EducationItem(BaseModel):
    school: str = Field(description="学校名称")
    major:  str = Field(description="专业名称")

class Resume(BaseModel):
    name:      str                = Field(description="姓名")
    education: list[EducationItem] = Field(default_factory=list)  # 教育经历列表

# 创建时，嵌套部分可以直接用字典，Pydantic 会自动转成对应的子模型
resume = Resume(
    name="小明",
    education=[
        {"school": "清华大学", "major": "计算机"},
        {"school": "北京大学", "major": "软件工程"},
    ],
)

print(resume.name)                    # 小明
print(resume.education[0].school)     # 清华大学  ← 注意：已经是 EducationItem 对象了
print(type(resume.education[0]))      # <class '__main__.EducationItem'>

    注意最后一行：你传进去的是普通字典，但 Pydantic 自动把它转成了 EducationItem 对象，所以你能用 .school 这样的点号访问。这就是 EduAgent 里 ResumeStructured 模型的结构——一个大模型里嵌着 list[EducationItem]、list[ProjectItem]、list[WorkItem]。

    如果某个字段「可能有、也可能没有（可以是 None）」，用 Optional：

    from typing import Optional
from pydantic import BaseModel

class Profile(BaseModel):
    nickname: Optional[str] = None    # 可以是字符串，也可以是 None

    2.2.6 model_dump()：在「模型」和「字典」之间转换¶

    模型对象适合在代码里用（带类型、带校验、能点号访问），但当我们要**存进数据库、或作为 JSON 返回给前端**时，往往需要把它转成普通字典。用 .model_dump()：

    from pydantic import BaseModel, Field

class Student(BaseModel):
    name: str = Field(description="姓名")
    age:  int = Field(default=18, description="年龄")

s = Student(name="小明", age=20)

d = s.model_dump()       # 模型 → 字典
print(d)                 # {'name': '小明', 'age': 20}
print(type(d))           # <class 'dict'>

    反过来，如果你手上有一个字典，想把它变成模型对象，可以直接解包传入：

    data = {"name": "小红", "age": 22}
s2 = Student(**data)     # 字典 → 模型
print(s2.name)           # 小红

    EduAgent 里的真实应用：简历 Agent、试卷批改 Agent 在拿到大模型返回的 Pydantic 结果后，几乎都会立刻调用 .model_dump() 转成字典，再存进 PostgreSQL 或放进 LangGraph 的 State 里。你会在代码里频繁看到 result.model_dump()。

    2.2.7 配套：Enum 与 BaseSettings¶

    最后了解两个会和 Pydantic 一起出现的搭档。

    Enum：把字段限定为「固定的几个取值」¶

    有些字段的取值是固定的一小撮，比如模拟面试的「阶段」只能是「热身 / 技术基础 / 项目 / 收尾 / 结束」之一。这时用 Enum（枚举）来定义合法取值集合，既防止写错，又让代码更清晰：

    from enum import Enum

class InterviewStage(str, Enum):       # 继承 str，取值就是字符串
    WARMUP    = "warmup"
    TECH_BASE = "tech_base"
    PROJECT   = "project"
    CLOSING   = "closing"
    FINISHED  = "finished"

print(InterviewStage.WARMUP)           # InterviewStage.WARMUP
print(InterviewStage.WARMUP.value)     # warmup

    EduAgent 里的真实应用：模拟面试 Agent 用 InterviewStage 枚举表示对话进行到哪个阶段；Orchestrator 用枚举表示 Agent 类型（qa / exam / resume / interview）和执行模式。枚举也能直接作为 Pydantic 模型的字段类型。

    BaseSettings：从环境变量 / .env 文件读配置¶

    Pydantic 还有一个专门用来「读配置」的基类 BaseSettings（来自 pydantic-settings 包）。它能自动从**环境变量**或 **.env 文件**里把配置项读出来，并同样做类型校验。

    from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    db_host: str = "localhost"
    db_port: int = 5433              # 会自动把环境变量里的字符串转成 int

settings = Settings()
print(settings.db_host, settings.db_port)

    EduAgent 里的真实应用：项目的 config.py 就是用 BaseSettings 定义的，所有数据库地址、API Key、端口等配置都从 .env.local 文件读取，绝不硬编码在代码里。我们会在第三章详细实现它。

    章节总结¶

    本节我们掌握了贯穿 EduAgent 全程的数据建模工具 Pydantic：

    • 它解决什么：用类型注解声明「数据该长什么样」，自动完成校验与合理的类型转换，出错给清晰报错。
    • BaseModel：定义模型的起点，自动校验字段类型。
    • Field：给字段加说明书——description（含义）、default（默认值/可选）、default_factory=list（可变默认值的正确写法）。
    • 重点 description：它会被大模型当作「填空指令」，是「让大模型输出结构化数据」的关键，等于提示词的一部分。
    • 嵌套与组合：用 list[子模型] 和 Optional 搭建复杂结构，Pydantic 会自动把字典转成子模型对象。
    • model_dump()：模型转字典（存库 / 返回 JSON）；反向用 Model(**字典)。
    • 搭档：Enum 限定固定取值（面试阶段、Agent 类型）；BaseSettings 从 .env 读配置。

    下一节 2.3 LangChain 速成，我们将学习如何用 LangChain 调用大模型，并把本节学到的 Pydantic 模型真正用起来——让大模型按我们定义的结构「填空」输出。

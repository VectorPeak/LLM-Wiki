    2.5 FastAPI 速成¶

    学习目标¶

    • 了解 FastAPI 在 EduAgent 里的角色：系统对外的「大门」
    • 掌握用 @app.get / @app.post 定义接口，并用自动文档 /docs 调试
    • 掌握用 Pydantic 模型接收请求体、用 response_model 约束响应
    • 掌握路径参数与查询参数
    • 掌握依赖注入 Depends：复用「数据库连接」「登录校验」等通用逻辑（重点）
    • 掌握文件上传 UploadFile
    • 掌握 SSE 流式响应 EventSourceResponse（问答 / 面试的打字机效果）

    📌 运行说明：FastAPI 应用要用 uvicorn 启动。把示例存成 demo.py 后，在终端运行： 

    pip install "fastapi[standard]" uvicorn sse-starlette
uvicorn demo:app --reload
    启动后浏览器打开 http://localhost:8000/docs，FastAPI 会**自动生成一个可交互的 API 文档页面**，你能直接在网页上点按钮测试每个接口——这是 FastAPI 最贴心的特性之一。

    2.5.1 FastAPI 是什么、在项目里干什么¶

    回顾第一章的架构图：API 层是整个系统的「大门」。前端发来的每一个请求（登录、提问、上传简历……）都先经过这道门。FastAPI 就是用来建这道门的 Web 框架，它负责：

    1. 接收并校验请求——把前端发来的 JSON、文件、URL 参数解析成 Python 对象，并自动校验格式；
    2. 调用业务逻辑——比如调用某个 Agent；
    3. 返回结果——普通 JSON，或者「一个字一个字往外吐」的流式响应。

    FastAPI 的两大招牌优势，正好契合本项目：

    • 基于类型注解自动校验：你用 Pydantic 写清楚「请求该长什么样」，校验它全包了（这就是 2.2 学的东西派上用场的地方）。
    • 全异步：天然支持 async def 接口，和我们 2.1 学的异步、以及大模型调用无缝配合。

    2.5.2 第一个接口：最小应用¶

    from fastapi import FastAPI

app = FastAPI(title="EduAgent Demo")

@app.get("/health")
async def health_check():
    return {"status": "ok"}

    把它存成 demo.py，运行 uvicorn demo:app --reload，然后：

    • 访问 http://localhost:8000/health，会看到 {"status":"ok"}；
    • 访问 http://localhost:8000/docs，会看到自动生成的交互式文档。

    要点：

    • app = FastAPI() 创建应用实例。
    • @app.get("/health") 这个装饰器把下面的函数注册成「处理 GET /health 请求」的接口。常用的还有 @app.post（提交数据）、@app.put、@app.delete。
    • 接口函数**返回一个字典**，FastAPI 会自动把它转成 JSON 响应。

    EduAgent 里的真实应用：main.py 里就有一个一模一样的 /health 健康检查接口，用来确认服务是否正常启动。

    2.5.3 用 Pydantic 接收请求体¶

    当前端要「提交数据」（比如登录时提交用户名密码），我们用一个 Pydantic 模型作为接口函数的参数。FastAPI 会自动把请求体里的 JSON 解析成这个模型，并完成校验：

    from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()

# 请求体模型：前端要发来的数据长这样
class LoginRequest(BaseModel):
    username: str = Field(..., description="用户名或邮箱")
    password: str = Field(..., description="密码")

# 响应模型：我们会返回的数据长这样
class TokenResponse(BaseModel):
    access_token: str
    token_type:   str = "bearer"
    role:         str

@app.post("/login", response_model=TokenResponse)
async def login(req: LoginRequest):           # 参数类型是 Pydantic 模型
    # req 已经是解析并校验好的对象，直接用 req.username / req.password
    if req.username == "student01" and req.password == "Student@123456":
        return TokenResponse(access_token="fake-token-abc", role="student")
    return {"access_token": "", "token_type": "bearer", "role": "guest"}

    要点：

    • req: LoginRequest：把 Pydantic 模型写成参数类型，FastAPI 就知道「请求体应该是这个结构」，并自动解析 + 校验。如果前端少传了 password，FastAPI 会自动返回一个清晰的 422 错误，你一行校验代码都不用写。
    • response_model=TokenResponse：声明这个接口返回的数据结构。它会让自动文档更准确，也会过滤掉不该返回的多余字段。
    • Field(..., description=...) 里的 ... 表示「必填」（回顾 2.2）。

    EduAgent 里的真实应用：登录接口 api/v1/auth.py 用的正是 LoginRequest → TokenResponse 这套，校验通过后签发 JWT Token。我们会在第三章实现完整版。

    2.5.4 路径参数与查询参数¶

    除了请求体，还有两种常见的传参方式：

    路径参数——把参数嵌在 URL 路径里，用 {} 占位，函数里同名参数自动接收：

    @app.get("/reviews/{review_id}")
async def get_review(review_id: str):
    return {"review_id": review_id, "status": "completed"}
# 访问 GET /reviews/abc-123 → review_id 自动等于 "abc-123"

    查询参数——URL 问号后面的 ?key=value，在函数里写成「带默认值的普通参数」：

    @app.get("/reviews")
async def list_reviews(page: int = 1, size: int = 10):
    return {"page": page, "size": size}
# 访问 GET /reviews?page=2&size=20 → page=2, size=20
# 不传则用默认值 page=1, size=10

    EduAgent 里的真实应用：简历审查的「查询某条审查结果」用路径参数 /reviews/{review_id}，「分页列出所有审查」用查询参数 ?page=...。

    2.5.5 依赖注入 Depends（核心）¶

    很多接口都需要做一些**相同的前置工作**：拿一个数据库连接、校验用户有没有登录……如果在每个接口里都重复写这些，既啰嗦又难维护。FastAPI 用**依赖注入（Depends）**优雅地解决了这个问题：

    把「通用的前置逻辑」写成一个函数（叫「依赖」），在接口参数里用 Depends(依赖函数) 声明一下，FastAPI 就会在执行接口前**自动先跑这个依赖、把结果喂给接口**。

    本项目有两个最重要的依赖：

    依赖一：get_db —— 获取数据库会话（yield 型）¶

    from typing import AsyncGenerator
from sqlalchemy.ext.asyncio import AsyncSession

async def get_db() -> AsyncGenerator[AsyncSession, None]:
    async with AsyncSessionLocal() as session:   # AsyncSessionLocal 见 2.6 / 第三章
        try:
            yield session            # yield 之前=准备连接；把 session 交给接口用
            await session.commit()   # 接口正常结束后：提交事务
        except Exception:
            await session.rollback() # 出错则回滚
            raise

    注意它用了 yield（回顾 2.1.6 的「yield 上面是准备、下面是收尾」）：yield 把数据库会话交给接口使用，接口跑完后再自动提交或回滚、关闭连接。接口完全不用操心连接的开关，拿来就用。

    依赖二：get_current_user —— 校验登录（鉴权）¶

    from fastapi import Depends, HTTPException, status
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials

bearer_scheme = HTTPBearer()

async def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(bearer_scheme),
) -> dict:
    token = credentials.credentials
    user = verify_jwt(token)              # 解析并校验 JWT（伪代码，第三章实现）
    if not user:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="无效的认证凭证",
        )
    return {"user_id": user["id"], "role": user["role"]}

    它负责从请求头里取出 JWT Token、校验合法性，合法就返回用户信息，不合法就抛出 401 错误。

    在接口里使用这两个依赖¶

    @app.get("/my-reviews")
async def my_reviews(
    db = Depends(get_db),                       # 自动注入数据库会话
    current_user: dict = Depends(get_current_user),  # 自动注入当前用户（顺便完成鉴权）
):
    # 走到这里，说明用户已登录，且 db 已就绪
    return {"user": current_user["user_id"], "data": "..."}

    这个接口什么校验代码都没写，但因为声明了 Depends(get_current_user)，未登录的请求会被自动挡在 401；同时 db 也已经准备好。这就是依赖注入的威力：通用逻辑写一次，处处复用。

    EduAgent 里的真实应用：dependencies.py 定义了这两个依赖，几乎每个需要登录的接口都会写 current_user: dict = Depends(get_current_user) 来保护，并用 db = Depends(get_db) 拿数据库连接。我们会在第三章实现它们的完整版。

    2.5.6 文件上传¶

    简历审查、试卷批改都需要上传文件。FastAPI 用 UploadFile 接收上传的文件：

    from fastapi import FastAPI, File, UploadFile

app = FastAPI()

@app.post("/upload", status_code=202)
async def upload(file: UploadFile = File(...)):
    content = await file.read()                  # 异步读取文件内容（bytes）
    return {"filename": file.filename, "size": len(content)}

    要点：

    • file: UploadFile = File(...)：声明这是一个上传文件参数。
    • await file.read()：异步读出文件的二进制内容。
    • status_code=202：自定义返回的 HTTP 状态码。202 表示「已接受，正在后台处理」——很适合「先收下文件、后台慢慢批改」的场景（回顾 2.1.5 的后台任务）。

    EduAgent 里的真实应用：简历上传接口 /resume/upload 收到 PDF 后返回 202，然后用后台任务（create_task）异步跑审查流程，用户无需在前端干等。

    2.5.7 SSE 流式响应（重点）¶

    普通接口是「算完一次性返回」。但智能问答、模拟面试希望答案**像打字机一样逐字蹦出来**，这就要用 SSE（Server-Sent Events，服务器推送事件）：服务器和浏览器保持连接，持续不断地往外推送一小段一小段内容。

    本项目用 sse-starlette 库的 EventSourceResponse 实现。它接收一个**异步生成器**（回顾生成器：能不断 yield 产出值的函数），每 yield 一次就向前端推送一个事件：

    import asyncio
import json
from fastapi import FastAPI
from sse_starlette.sse import EventSourceResponse

app = FastAPI()

@app.post("/chat/stream")
async def chat_stream():
    async def event_generator():
        answer = "装饰器是一种包装函数的语法。"
        for char in answer:                       # 模拟逐字生成
            await asyncio.sleep(0.1)
            # 每个事件是一个字典，data 里放 JSON 字符串
            yield {"data": json.dumps({"type": "token", "content": char})}
        yield {"data": json.dumps({"type": "done"})}   # 结束标志

    return EventSourceResponse(event_generator())

    要点：

    • event_generator 是一个异步生成器：它用 yield 一次次产出事件，EventSourceResponse 负责把每个事件实时推给前端。
    • 每个事件是形如 {"data": "..."} 的字典，data 里通常放一段 JSON，前端解析后渲染。
    • 真实场景里，for char in answer 会换成「async for chunk in llm.astream(...)」——也就是 2.3 学的大模型流式输出，把模型吐出的每个 token 实时转发给前端。

    EduAgent 里的真实应用：问答接口 /qa/chat/stream 和面试接口都用 EventSourceResponse 实现流式。项目里更进一步，用 LangGraph 的事件流（graph.astream_events）捕获图中生成节点产出的 token，再通过 SSE 推送。完整实现见第五章和第八章。

    2.5.8 错误处理¶

    需要返回错误时，抛出 HTTPException 即可，FastAPI 会把它转成对应的 HTTP 错误响应：

    from fastapi import HTTPException

@app.get("/reviews/{review_id}")
async def get_review(review_id: str):
    review = find_review(review_id)     # 伪代码
    if review is None:
        raise HTTPException(status_code=404, detail="审查记录不存在")
    return review

    status_code 是 HTTP 状态码（404 = 找不到，401 = 未授权，400 = 请求有误……），detail 是给前端看的错误说明。

    章节总结¶

    本节我们学会了用 FastAPI 把功能暴露成 Web 接口：

    • 角色：API 层是系统的大门，负责接收校验请求、调用业务、返回结果，并自动生成 /docs 交互文档。
    • 定义接口：@app.get / @app.post + async def，返回字典自动转 JSON。
    • 请求与响应：用 Pydantic 模型接收请求体（自动校验）、用 response_model 约束响应；路径参数 {id} 与查询参数 ?key=。
    • 依赖注入（核心）：Depends 复用通用逻辑——get_db 提供数据库会话、get_current_user 完成登录校验。
    • 文件上传：UploadFile = File(...) + await file.read()，配合 202 状态码做后台处理。
    • SSE 流式：EventSourceResponse + 异步生成器，实现问答 / 面试的打字机效果。
    • 错误处理：raise HTTPException(status_code, detail)。

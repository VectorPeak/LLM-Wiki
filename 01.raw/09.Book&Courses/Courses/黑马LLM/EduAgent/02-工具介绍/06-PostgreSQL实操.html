    2.6 PostgreSQL 实操：MySQL 用户快速上手¶

    学习目标¶

    • 看清 PostgreSQL 与 MySQL 的关键差异，把已有的 MySQL 经验平滑迁移过来
    • 学会用 psql 命令行 / PyCharm 连接并操作 PostgreSQL
    • 确认基础 CRUD 在 PG 上和 MySQL 基本一致
    • 亲手实操本项目用到的 PG 专属特性：UUID、JSONB、CHECK、TIMESTAMPTZ 触发器、ON CONFLICT upsert、RETURNING
    • 掌握 schema 概念与「清空重建」操作

    📌 面向谁：本节假设你**已经学过 MySQL** 的基本操作（建表、CRUD），但**没用过 PostgreSQL**。所以这一节不重复教通用 SQL，而是聚焦「PG 和 MySQL 哪里不一样」+「本项目用到的 PG 特性」。

    📌 运行说明。请确认你本地已有 PostgreSQL 服务，或已用 3.1 的 docker-compose 起了 postgres 容器（端口 5433）。所有示例都可以在 psql 或 PyCharm 的 SQL 控制台里直接跑。

    💡 本节是「练习」，不产生项目文件。你可以把练习语句随手存成一个 pg_practice.sql 放在任意位置，方便反复跑。

    2.6.1 PostgreSQL vs MySQL：先看差异全景¶

    你已经会 MySQL 了，好消息是：两者九成是相通的——库、表、行、列的概念一样，SELECT/INSERT/UPDATE/DELETE 也几乎一样。你真正需要重新认识的，是下面这些差异（也正是本项目里会遇到的）：

    方面 MySQL 的做法 PostgreSQL 的做法（本项目用）
    命令行工具 mysql -u root -p psql -U 用户 -d 库
    列出所有库 SHOW DATABASES; \l
    切换库 USE 库名; \c 库名
    列出所有表 SHOW TABLES; \dt
    查看表结构 DESC 表名; \d 表名
    主键自增 INT AUTO_INCREMENT UUID DEFAULT uuid_generate_v4()（本项目）或 SERIAL
    布尔类型 TINYINT(1)（0/1） BOOLEAN（true/false）
    JSON 类型 JSON JSONB（二进制存储，更快、可建索引）
    自动更新时间 ON UPDATE CURRENT_TIMESTAMP TIMESTAMPTZ + 触发器
    插入或更新（upsert） INSERT ... ON DUPLICATE KEY UPDATE INSERT ... ON CONFLICT ... DO UPDATE
    插入后拿回主键 另调 LAST_INSERT_ID() 直接 ... RETURNING id
    CHECK 约束 8.0.16 之前被忽略 一直严格生效
    执行 SQL 文件 source x.sql \i x.sql（psql 内）或 psql -f x.sql

    把这张表过一遍，你心里就有数了。下面我们挨个上手。

    2.6.2 连接 PostgreSQL：psql 与 PyCharm¶

    方式一：psql 命令行¶

    # -h 主机  -p 端口  -U 用户  -d 数据库
psql -h localhost -p 5433 -U eduagent_user -d eduagent

    连上后，进入的是 psql 交互环境。这里有一套以反斜杠开头的**元命令**，对应你熟悉的 MySQL 命令：

    \l           列出所有数据库        （= MySQL 的 SHOW DATABASES;）
\c eduagent  切换到 eduagent 库     （= USE eduagent;）
\dt          列出当前库所有表       （= SHOW TABLES;）
\d users     查看 users 表结构      （= DESC users;）
\q           退出                  （= quit）

    注意：元命令（\dt 这种）不用加分号；普通 SQL 语句要加分号 ; 才执行。

    方式二：PyCharm 数据库工具（重点，跟着做一遍）¶

    如果你用 PyCharm 专业版，先建立连接：右侧 Database 工具窗 → + → Data Source → PostgreSQL → 填入 localhost / 5433 / eduagent / eduagent_user / 密码 → 下载驱动 → Test Connection → OK。社区版没有这个工具，用 psql 或 DBeaver 即可。

    连上后，右键这个数据源 → New → Query Console，打开一个能写 SQL 的控制台。下面这些操作请**跟着实际敲一遍**。

    ⚠️ 两个关键区别，先记住： 1. PyCharm 的 Query Console 只认标准 SQL，不认 psql 的反斜杠元命令（\l、\dt、\c 在这里都用不了）。所以在 PyCharm 里要用「SQL 语句」或「左侧数据库树」来完成列库/列表等操作。 2. PostgreSQL 没有 MySQL 的 USE 库名; 这种切库语句——USE 在 PG 里会直接报语法错误。切换数据库要用控制台顶部的下拉选择器（见下）。

    ① 列出所有数据库

    SELECT datname FROM pg_database WHERE datistemplate = false ORDER BY datname;

    选中这行，按 Ctrl+Enter（Mac：Cmd+Enter）执行。实际输出：

     datname
----------
 eduagent
 postgres

    （也可以直接看左侧 Database 树——每个数据库都列在数据源下面。）

    ② 切换数据库

    PG 没有 USE。在 PyCharm 里，看 Query Console 顶部的下拉框（显示当前连的 数据库.schema，如 eduagent.public），点开它选另一个数据库即可切换。你后续写的 SQL 就会发到所选的库。

    ③ 列出当前数据库的所有表

    SELECT table_name FROM information_schema.tables
WHERE table_schema = 'public' ORDER BY table_name;

    或者更直接：在左侧 Database 树里展开 eduagent → schemas → public → tables，右键 → Refresh，就能看到所有表。

    ④ 退出 / 断开

    PyCharm 里不需要"退出"——关掉 Query 标签页即可。想断开数据库连接，就右键数据源 → Disconnect。

    接下来是**最基础的增删改查与建表删表**，全部是标准 SQL，在 Query Console 里逐条执行（选中要跑的语句 Ctrl+Enter；或点绿色 ▶ 跑整段）。

    ⑤ 创建一张表

    CREATE TABLE demo_basic (
    id    SERIAL PRIMARY KEY,     -- SERIAL = 自增整数（相当于 MySQL 的 AUTO_INCREMENT）
    name  VARCHAR(50),
    score INT
);

    ⑥ 添加数据（INSERT）

    INSERT INTO demo_basic (name, score) VALUES ('小明', 80), ('小红', 90);
SELECT * FROM demo_basic ORDER BY id;

    实际输出：

     id | name | score
----+------+-------
  1 | 小明 |    80
  2 | 小红 |    90

    ⑦ 更新数据（UPDATE，务必带 WHERE）

    UPDATE demo_basic SET score = 100 WHERE name = '小明';

    ⑧ 删除数据（DELETE，务必带 WHERE）

    DELETE FROM demo_basic WHERE name = '小红';
SELECT * FROM demo_basic ORDER BY id;

    实际输出（小红已删除，小明分数已更新为 100）：

     id | name | score
----+------+-------
  1 | 小明 |   100

    ⑨ 删除表（DROP TABLE）

    DROP TABLE demo_basic;

    执行后表就被整个删除了。把 ⑤~⑨ 跑一遍，你就在 PyCharm 里完整走了一遍「建表 → 增 → 改 → 删 → 删表」，PG 的基础操作就全会了。这些和 MySQL 几乎一模一样，唯一要记住的就是上面那两个区别（不认 \dt、没有 USE）。

    2.6.3 基础 CRUD：和 MySQL 几乎一样¶

    先吃个定心丸——你在 MySQL 学的增删改查，在 PG 上**写法基本不变**。下面这些你扫一眼即可，确认「确实一样」：

    -- 查
SELECT id, username FROM users WHERE role = 'student' LIMIT 5;
-- 增
INSERT INTO users (tenant_id, username, email, password_hash, role)
VALUES ('tenant_default', 'demo01', 'demo01@x.com', 'hash...', 'student');
-- 改（务必带 WHERE）
UPDATE users SET is_active = false WHERE username = 'demo01';
-- 删（务必带 WHERE）
DELETE FROM users WHERE username = 'demo01';

    只有两个小地方要留意：

    • 字符串一律用单引号 'student'，不要用双引号（PG 里双引号是给「标识符/列名」用的，和 MySQL 不同）。
    • 布尔值直接写 true / false，不是 1 / 0。

    真正需要你重新学的，是下面这些 MySQL 没有或不一样的 PG 特性。

    2.6.4 PG 专属特性实操（本项目用到的，重点）¶

    这一节是本节的核心。下面每个特性都是你的 EduAgent 项目里真实用到的，我们用一张练习表 demo_members 挨个跑一遍（完整脚本见 2.6.6，可直接粘贴）。

    ① UUID 主键 + uuid-ossp 扩展¶

    本项目主键不用自增整数，而用 UUID（回顾 3.2 的设计原因）。PG 生成 UUID 需要先启用扩展：

    CREATE EXTENSION IF NOT EXISTS "uuid-ossp";   -- 启用一次即可

-- 建表时主键默认用 uuid_generate_v4() 自动生成
id UUID PRIMARY KEY DEFAULT uuid_generate_v4()

    若执行 CREATE EXTENSION 报权限不足，用超级用户 postgres 对该库先跑一次即可（回顾你手动建表时遇到的提示）。

    ② RETURNING：插入后直接拿回生成的值¶

    MySQL 插入后要另外查 LAST_INSERT_ID()，而 PG 用 RETURNING 一步到位——尤其适合「插入后立刻需要那条记录的 UUID」的场景：

    INSERT INTO demo_members (username, role, profile)
VALUES ('alice', 'student', '{"city":"上海","tags":["java","spring"]}')
RETURNING id, username;

    实际输出（id 是自动生成的 UUID）：

                      id                  | username
--------------------------------------+----------
 4b5da03a-b4f1-449d-9780-1eaeda825180 | alice
(1 row)

    ③ JSONB：直接存查结构化数据¶

    本项目大量用 JSONB（简历的评分、批改的薄弱点、面试报告都是）。上面 profile 字段存的就是一段 JSON。查询时用 PG 的 JSON 操作符：

    • 字段 ->> '键'：取出该键的值（文本）
    • 字段 -> '键'：取出该键的值（仍是 JSON）
    SELECT username,
       profile ->> 'city'  AS city,    -- 取文本
       profile -> 'tags'   AS tags     -- 取 JSON 数组
FROM demo_members
WHERE profile ->> 'city' = '上海';      -- 还能直接按 JSON 内部的值过滤

    实际输出：

     username | city |        tags
----------+------+--------------------
 alice    | 上海 | ["java", "spring"]
(1 row)

    看到没——你可以**直接在 SQL 里按 JSON 内部的字段查询**，这是 JSONB 比 MySQL 的 JSON 更顺手的地方之一。

    ④ ON CONFLICT DO UPDATE：upsert（存在就更新，不存在就插入）¶

    本项目保存面试 / 问答会话时，用 thread_id 做「有则更新、无则插入」。MySQL 是 ON DUPLICATE KEY UPDATE，PG 是 ON CONFLICT ... DO UPDATE：

    INSERT INTO demo_members (username, role)
VALUES ('alice', 'teacher')                       -- alice 已存在（username 唯一）
ON CONFLICT (username) DO UPDATE
    SET role = EXCLUDED.role                       -- EXCLUDED 代表「本次想插入的那行」
RETURNING username, role;
    • INSERT ... VALUES = 你想送进仓库的**新货物**。
    • ON CONFLICT = 发现仓库货架上已经有同名货物了。
    • EXCLUDED = 指代你手头**这箱新货物**（而不是货架上的旧货）。
    • SET role = EXCLUDED.role = 既然放不进去，那你就把货架上旧货的标签，撕下来换成我这箱新货的标签（更新）。

    实际输出（没有重复插入，而是把 alice 的 role 更新成了 teacher）：

     username |  role
----------+---------
 alice    | teacher
(1 row)

    EXCLUDED.role 是固定写法，表示「本次冲突时本来要插入的那行的 role」。

    ⑤ CHECK 约束：数据库层面拦截非法值¶

    本项目用 CHECK 把 role、status 等字段限定为固定取值。和 MySQL 不同，PG 的 CHECK 一直严格生效——插入非法值会直接被拒：

    -- role 只允许 student/teacher/admin，插入 'wizard' 会被拦
INSERT INTO demo_members (username, role) VALUES ('bob', 'wizard');

    实际输出（报错，数据进不去）：

    ERROR:  new row for relation "demo_members" violates check constraint "demo_members_role_check"

    这就是为什么 3.2 的建表脚本里大量用 CHECK (... IN (...))——把非法数据挡在数据库门外。

    ⑥ TIMESTAMPTZ + 触发器：自动维护 updated_at¶

    MySQL 可以用 ON UPDATE CURRENT_TIMESTAMP 让时间字段自动刷新；PG 没有这个语法糖，而是用**触发器**实现。先写一个触发器函数（注意 $$ ... $$ 是 plpgsql 的函数体写法），再把它挂到表上：

    -- 触发器函数：每次更新行时，把 updated_at 设为当前时间
CREATE OR REPLACE FUNCTION demo_touch_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 把函数挂到表上：每行 UPDATE 之前自动执行
CREATE TRIGGER trg_demo_updated_at
BEFORE UPDATE ON demo_members
FOR EACH ROW EXECUTE FUNCTION demo_touch_updated_at();
    • 你希望：只要修改了这行数据（比如把 role 从 student 改成 teacher），updated_at 就自动变成“修改的那一刻”。
    • 你不想：每次修改时，都手动在代码里写 UPDATE ... SET role='teacher', updated_at=NOW()。这样太累，而且程序员容易忘记写。

    解决方案：告诉数据库：“以后只要有人改这行，你出发前，先帮我把 updated_at 填好！”

    第二层：拆解第一段代码（制作“闹钟铃音”）¶

    CREATE OR REPLACE FUNCTION demo_touch_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

    这段代码不是在操作数据，而是在**定义一个“动作脚本”**（告诉数据库“该怎么改”）。逐行翻译如下：

    代码行 大白话解释
    CREATE OR REPLACE FUNCTION demo_touch_updated_at() “我要创建一个新技能（函数），给它起名叫 demo_touch_updated_at。”
    （如果以前有过同名的，就覆盖重写）
    RETURNS TRIGGER AS $$ “这个技能很特殊，它不是一个普通计算器，它是专为触发器（Trigger）准备的。”
    BEGIN “技能开始执行了……”
    NEW.updated_at = NOW(); “听好了！把准备要修改的那一行数据（系统内部叫它 NEW）里面的 updated_at 字段，改成现在的时刻（NOW()）。”
    （注意：这时候还没真正往硬盘上改，只是在“草稿纸”上改了）
    RETURN NEW; “改好了！把这张改过的‘草稿纸’（NEW）还给数据库，你就按这个新草稿去保存吧！”
    END; $$ LANGUAGE plpgsql; “技能结束。”（用的是 PostgreSQL 专用的语言）

    核心概念 NEW 是什么？ 当你执行 UPDATE 时，数据库会在内存里先复制一份你要改的那行数据，这份副本就叫 NEW。你在触发器里改的是这份副本，最后 RETURN NEW 就是把副本写回硬盘。

    第三层：拆解第二段代码（给“闹钟”装上“触发开关”）¶

    光有“闹钟铃音”没用，你得把这个铃音挂在门上。第二段代码就是干这个的：

    CREATE TRIGGER trg_demo_updated_at
BEFORE UPDATE ON demo_members
FOR EACH ROW EXECUTE FUNCTION demo_touch_updated_at();

    逐行翻译：

    代码行 大白话解释
    CREATE TRIGGER trg_demo_updated_at “我要安装一个触发器（自动监控器），给它起名叫 trg_demo_updated_at。”
    BEFORE UPDATE ON demo_members “监控目标：只要有谁尝试 UPDATE（修改） demo_members 这张表的数据，在修改真正写入硬盘之前（BEFORE），立刻拦住！”
    FOR EACH ROW “被修改的每一行，都要触发一次。如果我一次修改了 10 行，这个脚本就执行 10 次。”
    EXECUTE FUNCTION demo_touch_updated_at(); “拦住之后，立刻去执行刚才我们定义的那个技能脚本（把 updated_at 改成当前时间）。”

    验证一下——更新一行后，updated_at 会自动变得比 created_at 新：

    UPDATE demo_members SET is_active = false WHERE username = 'alice';
SELECT username, is_active, (updated_at > created_at) AS updated_changed
FROM demo_members WHERE username = 'alice';

    实际输出（is_active 是布尔，显示为 f；updated_changed 为 t 说明触发器生效了）：

     username | is_active | updated_changed
----------+-----------+-----------------
 alice    | f         | t
(1 row)

    3.2 的建表脚本末尾那段 $$ ... $$ 函数 + 给 10 张表批量挂触发器，做的就是这件事——现在你完全看得懂了。

    2.6.5 schema 与「清空重建」¶

    PostgreSQL 里，表默认建在一个叫 public 的 schema（模式）下。你可以把 schema 理解成「库里面再分的命名空间」。日常用 \dt 看到的就是 public 下的表。

    当你想**把整个库清空、重新建表**时（比如反复练习 3.2 的建表脚本），最干净的方式是删掉整个 public schema 再重建：

    DROP SCHEMA public CASCADE;   -- 删除 public 下所有表（CASCADE = 连带依赖一起删）
CREATE SCHEMA public;          -- 重建一个空的 public

    执行完后，库就回到「干净无表」的状态，可以重新跑 init_db.sql 了。（这也正是你之前手动建表时用到的清空方法。）

    2.6.6 完整实操脚本（可直接粘贴运行）¶

    下面把本节用到的所有 PG 特性串成一个完整脚本。复制到 psql 或 PyCharm 的 SQL 控制台执行，对照着实际输出走一遍，你就把 PG 的关键特性都摸过一遍了。

    -- ============ PostgreSQL 特性实操练习（pg_practice.sql）============
-- 连接：psql -h localhost -p 5433 -U eduagent_user -d eduagent

-- 0) 启用 UUID 扩展（若报权限不足，改用 postgres 超级用户执行这一句）
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- 1) 建练习表：集合 UUID / BOOLEAN / JSONB / CHECK / TIMESTAMPTZ
DROP TABLE IF EXISTS demo_members;
CREATE TABLE demo_members (
    id          UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    username    VARCHAR(64) NOT NULL UNIQUE,
    role        VARCHAR(16) NOT NULL CHECK (role IN ('student','teacher','admin')),
    is_active   BOOLEAN NOT NULL DEFAULT TRUE,
    profile     JSONB,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 2) updated_at 自动更新触发器
CREATE OR REPLACE FUNCTION demo_touch_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_demo_updated_at
BEFORE UPDATE ON demo_members
FOR EACH ROW EXECUTE FUNCTION demo_touch_updated_at();

-- 3) 插入 + RETURNING（拿回自动生成的 UUID）
INSERT INTO demo_members (username, role, profile)
VALUES ('alice', 'student', '{"city":"上海","tags":["java","spring"]}')
RETURNING id, username;

-- 4) JSONB 查询（按 JSON 内部字段过滤）
SELECT username, profile ->> 'city' AS city, profile -> 'tags' AS tags
FROM demo_members WHERE profile ->> 'city' = '上海';

-- 5) upsert：存在就更新（不会重复插入 alice）
INSERT INTO demo_members (username, role)
VALUES ('alice', 'teacher')
ON CONFLICT (username) DO UPDATE SET role = EXCLUDED.role
RETURNING username, role;

-- 6) CHECK 约束：下面这句会报错（role 非法），可注释掉观察
-- INSERT INTO demo_members (username, role) VALUES ('bob', 'wizard');

-- 7) 触发器验证：更新后 updated_at 自动变化
UPDATE demo_members SET is_active = false WHERE username = 'alice';
SELECT username, is_active, (updated_at > created_at) AS updated_changed
FROM demo_members WHERE username = 'alice';

-- 8) 清理练习表（练完即可删除，不影响项目的 14 张表）
DROP TABLE demo_members;
DROP FUNCTION demo_touch_updated_at();

    跑完这个脚本，你就在真实 PostgreSQL 上把 UUID、JSONB、CHECK、upsert、RETURNING、触发器全部实操了一遍。再回头看 3.2 的 14 张表，你会发现它们用的就是这些特性的组合。

    章节总结¶

    本节我们以「MySQL 老手」的视角，快速上手了 PostgreSQL：

    • 差异全景：库表行列、CRUD 都和 MySQL 相通；真正不同的是连接工具（psql / \dt 等）、主键（UUID）、布尔、JSON（JSONB）、自动时间（触发器）、upsert（ON CONFLICT）、RETURNING、严格的 CHECK。
    • 连接操作：用 psql 命令行或 PyCharm 连接，掌握 \l \c \dt \d \q 等元命令。
    • PG 专属特性实操（全部在真实库验证过）：UUID + 扩展、RETURNING、JSONB 读写、ON CONFLICT upsert、CHECK 拦截、TIMESTAMPTZ + 触发器。
    • schema 与清空重建：public schema、DROP SCHEMA public CASCADE; CREATE SCHEMA public;。

    这些正是你的 EduAgent 项目（尤其是 3.2 的建表脚本和后面各 Agent 的读写代码）真实用到的 PG 能力。有了这一节的手感，再看 3.2 那张大建表脚本就不会陌生了。

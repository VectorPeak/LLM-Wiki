    4.1 简历审查 Agent：全景与数据流¶

    学习目标¶

    • 理解简历审查 Agent 做什么、整体处理流程是怎样的
    • 看懂它的 8 节点流水线，以及数据如何在节点间流动（State 贯穿全程）
    • 把它和第二章学的「Agent = 图」心智模型对应起来
    • 了解本章的整体规划与要创建的文件

    🎉 这是你的第一个真实 Agent。 前面两章学的东西——LangGraph 的图与 State（2.4）、LLM 工厂与结构化输出（3.4 / 2.3）、Pydantic 建模（2.2）、异步并行（2.1）、数据库 JSONB 读写（3.2）、FastAPI 上传与后台任务（2.5 / 2.1）——本章会**全部用上、串成一个能跑的完整系统**。学完你会真切体会到："原来前面那些零件是为了拼这个。"

    4.1.1 这个 Agent 做什么¶

    一句话：学员上传一份 PDF 简历，系统自动给出一份专业的审查报告。 报告包含三部分：

    1. 六维度评分：项目深度、技术匹配度、表达规范性、简历结构、量化程度、真实可信度，每维度 0–100 分，加权出一个综合分；
    2. 逐条问题诊断：定位到简历的具体位置（如"项目经历-电商系统-第2句"），标注优先级（high/medium/low），并给出可操作的修改建议；
    3. 整体评价：核心亮点、最重要的改进方向、综合评语、与目标岗位的匹配度。

    它有几个鲜明特点，决定了它是「第一个 Agent」的原因：

    • 全自动、一条直线：从解析到出报告，8 个节点顺序执行，没有分支、没有人工介入（interrupt）、没有断点续传（checkpointer）——是最简单的 Agent 形态，适合入门。
    • 结构化输出贯穿全程：每一步 LLM 的产出都是严格的 Pydantic 结构（回顾 2.3 的 with_structured_output），而不是自由文本。
    • 并行是性能关键：六维度评分是 6 次独立的 LLM 调用，用 asyncio.gather 并行（回顾 2.1），把总耗时从"6 次相加"压成"1 次最慢的"。

    4.1.2 请求的一生（HTTP 视角）¶

    先从用户视角看整个流程是怎么走的：

    ① 学员 POST /resume/upload（带 PDF 文件 + JWT）
        │
        ▼
② API 把文件存到本地 /tmp，在 resume_reviews 表插入一条记录（status=processing）
        │
        ▼
③ API 立即返回 202 + review_id（不等审查完成！）
        │   同时在后台启动 LangGraph 图执行（异步任务）
        ▼
④ 学员拿着 review_id 轮询 GET /resume/reviews/{review_id}
        │
        ├── 还在审查 → 返回 {status: "processing"}
        └── 审查完成 → 返回完整报告（六维度+诊断+评价）

    这里有个重要的设计——上传接口不会"卡住"等审查跑完（审查要调好几次大模型，约 30–60 秒）。它把活儿丢到后台异步任务，立刻返回 review_id，让前端轮询。这正是 2.1.5 学的"后台任务 + GC 保护"和 2.5 学的"202 Accepted"的真实应用。

    4.1.3 8 节点流水线（Agent 内部视角）¶

    第 ③ 步在后台启动的那张「图」，内部是这样一条流水线。每个节点读取 State、做一件事、把结果写回 State：

             ┌──────────────────────────────────────────────────────────┐
         │                      ResumeState（贯穿全程）                │
         └──────────────────────────────────────────────────────────┘
START
  │
  ▼  ① upload_to_minio   （本地模式空跑，占位）
  ▼  ② download_pdf       （本地模式空跑，占位）
  ▼  ③ extract_text       PDF → raw_text、page_count
  ▼  ④ extract_structured raw_text → structured（结构化简历 JSON）
  ▼  ⑤ run_six_dimensions structured + raw_text → dimension_scores、weighted_score
  │                        （6 个维度 LLM 调用并行！）
  ▼  ⑥ diagnose_issues    汇总各维度问题 → issues（带优先级，排序）
  ▼  ⑦ generate_summary   综合一切 → summary（亮点/改进/评语/匹配度）
  ▼  ⑧ save_results       把 structured/scores/issues/summary 写入 resume_reviews
  │
  ▼
END

    逐个节点说一句它干什么、产出什么（写进 State 的哪个字段）：

    # 节点 干什么 写入 State
    ① upload_to_minio 本地模式空跑（原为上传对象存储，已简化） —
    ② download_pdf 本地模式空跑（文件已在本地 /tmp） —
    ③ extract_text 用 PyMuPDF 提取 PDF 文本，处理双栏布局 raw_text、page_count
    ④ extract_structured LLM 把原始文本提取成结构化简历 structured
    ⑤ run_six_dimensions **并行**评 6 个维度，算加权分 dimension_scores、weighted_score
    ⑥ diagnose_issues 汇总问题、去重、标优先级、排序 issues
    ⑦ generate_summary 生成整体评价 summary
    ⑧ save_results 写入数据库、清理临时文件 （持久化）

    关于 ① ② 两个空跑节点：它们在真实代码里就是 return {}（什么都不做），保留只是为了让图结构完整、并标明"这里原本是对象存储的位置"。本课程本地模式不用 MinIO（回顾第一章），文件直接存在本地 /tmp，所以这两步无事可做。我们如实保留它们，与真实代码一致，你不用纠结。

    4.1.4 对应回「Agent = 图」心智模型¶

    回顾 2.4 学的：一个 Agent = State + Node + Edge（+ 可选 Checkpointer）。简历 Agent 正好是这个模型最干净的体现：

    • State = ResumeState（一个 TypedDict）：那张贯穿 8 个节点的"工单"，前面填 PDF 路径，中间逐步填上文本、结构化数据、评分、问题，最后填上评价。
    • Node = 8 个节点函数：每个都遵循 2.4 的约定——接收 State、返回"要更新的字段"字典。
    • Edge = 8 条固定边（START → ① → ② → … → ⑧ → END）：没有条件边，因为这是一条直线。
    • Checkpointer = 无：这是一次性任务，不需要记忆或断点续传，所以 compile() 时不传 checkpointer。

    换句话说，简历 Agent 就是 2.4.4「搭一条直线图」的放大版——只不过把当时节点里的简单逻辑，换成了"调大模型做结构化提取/评分"的真实业务。你已经具备读懂它的全部基础。

    4.1.5 本章规划与要创建的文件¶

    本章我们按"数据流顺序"逐块构建这个 Agent。每节都是"逐行注释的完整文件 + 写完即测"。

    📁 本章要创建的文件（目录骨架已在 3.1.2 建好）：

    文件路径 作用 在哪节
    backend/agents/resume/state.py State 与所有 Pydantic 数据模型 4.2
    backend/agents/resume/prompts.py 各阶段提示词 4.3
    backend/agents/resume/nodes.py 8 个节点函数 4.4 / 4.5 / 4.6 / 4.7
    backend/agents/resume/graph.py 图装配 4.7
    backend/api/v1/resume.py 上传 / 查询 / 删除 / 列表 接口 4.8

    各节安排：

    • 4.2 先定义数据"长什么样"（state.py 的 Pydantic 模型 + State）；
    • 4.3 写好与大模型对话的"剧本"（prompts.py）；
    • 4.4 解析 PDF、提取结构化信息（前 4 个节点）；
    • 4.5 六维度并行评审（本章性能重点）；
    • 4.6 问题诊断与整体评价；
    • 4.7 持久化 + 把 8 个节点装配成图；
    • 4.8 暴露成 HTTP 接口，并端到端跑通。

    章节总结¶

    本节我们从全景上认识了第一个真实 Agent——简历审查 Agent：

    • 它做什么：PDF 简历 → 六维度评分 + 逐条诊断 + 整体评价。
    • 请求的一生：上传立即返回 202 + review_id，后台异步审查，前端轮询取结果。
    • 8 节点流水线：解析文本 → 结构化提取 → 六维度并行评审 → 问题诊断 → 整体评价 → 持久化（含两个本地模式空跑节点）。
    • 本质：就是 2.4「直线图」的放大版——State 贯穿、节点返回增量、固定边相连、无分支无记忆。

    5.3.1 为什么需要分块，chunk 多大合适¶

    上一节加载出来的 Document，PDF 是"一页一个 Document"，Markdown 是"整个文件一个 Document"。直接把它们扔给嵌入模型有两个问题：

    问题 A：太长——向量精度下降

    嵌入模型（BGE-M3）把一段文字压缩成一个 1024 维向量。文字越长，向量越"平均化"，能表达的具体语义越稀薄。把整章讲义压成一个向量，检索时几乎什么都能匹配，也几乎什么都匹配不准。

    问题 B：太短——语义残缺

    反过来，chunk 太小（比如按句子切，每句 20 个字），每个 chunk 上下文不完整，LLM 基于它生成的回答也会缺乏逻辑支撑。

    经验上的平衡点：

    chunk 大小 效果 适用场景
    < 100 字 精准但碎片化，LLM 很难基于单个 chunk 给出完整回答 不推荐
    200–600 字 推荐区间，一个知识点的正常篇幅 课程讲义、技术文档
    > 1000 字 向量语义稀薄，检索召回率下降 不推荐

    本项目选用 chunk_size=512，chunk_overlap=100： - 512 字：中文约 300–400 个汉字，刚好能覆盖一个完整的知识点解释 - 100 字重叠：防止一句完整的话被切断后，两个 chunk 各自只拿到半句话

    5.3.2 PDF 分块：RecursiveCharacterTextSplitter¶

    PDF 加载后的 Document 没有任何语义结构标记，只有纯文字 + 换行符。RecursiveCharacterTextSplitter 的策略是：按优先级逐级尝试分隔符，尽可能在"自然边界"处切开。

    优先级顺序（从高到低）：
  "\n\n"   → 段落边界（最优，两个换行）
  "\n"     → 行边界
  "。"     → 中文句号（句子边界）
  "，"     → 中文逗号（词组边界）
  " "      → 空格（英文单词边界）
  ""       → 强制切字符（最后兜底）

    每次尝试用最高优先级的分隔符切，如果切出来的块超过 chunk_size，就降级到下一个分隔符继续切，直到满足大小要求。

    from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_core.documents import Document

def split_pdf_documents(pages: list[Document]) -> list[Document]:
    """
    对 PDF 页面列表做递归字符分块。

    处理流程：
      1. 过滤空页（图片页 / 扫描件页，page_content 字数 < 20）
      2. RecursiveCharacterTextSplitter 按自然边界切分
      3. 在每个 chunk 的 metadata 里写入 source_name（文件名 + 页码）

    Args:
        pages: PyPDFLoader 返回的 list[Document]，每页一个 Document

    Returns:
        切分后的 list[Document]，每个元素是一个可嵌入的 chunk
    """
    # 过滤掉空页（扫描件 / 图片页，内容为空或极少）
    non_empty_pages = [
        p for p in pages
        if len(p.page_content.strip()) > 20
    ]
    skipped = len(pages) - len(non_empty_pages)
    if skipped > 0:
        print(f"  过滤空页：{skipped} 页（图片/扫描件页）")

    splitter = RecursiveCharacterTextSplitter(
        chunk_size=512,       # 目标 chunk 字符数
        chunk_overlap=100,    # 相邻 chunk 重叠字符数，防止知识点被切断
        separators=["\n\n", "\n", "。", "，", " ", ""],  # 按优先级尝试
        length_function=len,  # 用字符数衡量长度（不用 token，兼容中英文混合）
    )

    chunks = splitter.split_documents(non_empty_pages)

    # 给每个 chunk 补充 source_name（用于 Milvus 存储和检索结果标注）
    for chunk in chunks:
        filename = chunk.metadata.get("source", "未知文件")
        page_num = chunk.metadata.get("page", 0) + 1   # PyPDFLoader 页码从 0 开始
        chunk.metadata["source_name"] = f"{filename} 第{page_num}页"

    print(f"  [PDF] 分块完成：{len(non_empty_pages)} 页 → {len(chunks)} 个 chunk")
    return chunks

    5.3.3 Markdown 分块：语义切分 + 二次切分¶

    Markdown 有天然的语义结构——标题 #/##/### 划定了每个知识点的边界。MarkdownHeaderTextSplitter 利用这一结构，按标题层级把文档切成一个个完整的知识单元。

    第一步：按标题语义切分

    from langchain_text_splitters import MarkdownHeaderTextSplitter

headers_to_split_on = [
    ("#",   "H1"),   # 一级标题：章
    ("##",  "H2"),   # 二级标题：节
    ("###", "H3"),   # 三级标题：小节
]

md_splitter = MarkdownHeaderTextSplitter(
    headers_to_split_on=headers_to_split_on,
    strip_headers=False,    # 保留标题行在 page_content 里，让 chunk 自带上下文
)

    strip_headers=False 的效果（以课程讲义为例）：

    输入 Markdown：
  # 第三章 Spring IOC
  ## 3.1 什么是 IOC
  IOC（控制反转）是 Spring 框架的核心概念，它把对象的创建权交给容器……

切分后得到一个 Document：
  page_content = "## 3.1 什么是 IOC\nIOC（控制反转）是 Spring 框架的核心概念……"
  metadata     = {"H1": "第三章 Spring IOC", "H2": "3.1 什么是 IOC"}

    注意 metadata 里有 H1 和 H2——这两个字段告诉我们这个 chunk 归属于哪一章哪一节，在 Milvus 存储时可以直接用来构建 source_name。

    第二步：对超长段落做二次切分

    有些节（比如"原理详解"）可能几千个字，远超 512 字的上限。先用 MarkdownHeaderTextSplitter 切出语义块，再对超长的块用 RecursiveCharacterTextSplitter 二次切分：

    from langchain_text_splitters import RecursiveCharacterTextSplitter

# 二次切分器（参数与 PDF 保持一致，方便统一管理）
_char_splitter = RecursiveCharacterTextSplitter(
    chunk_size=512,
    chunk_overlap=100,
    separators=["\n\n", "\n", "。", "，", " ", ""],
)

    二次切分后，metadata 里的 H1/H2/H3 会**自动继承**到每个子块上（split_documents 会透传 metadata）。这是 MarkdownHeaderTextSplitter + RecursiveCharacterTextSplitter 组合使用的精髓——父块的标题上下文不会丢失。

    完整的 Markdown 分块函数：

    from pathlib import Path
from langchain_text_splitters import MarkdownHeaderTextSplitter, RecursiveCharacterTextSplitter
from langchain_core.documents import Document

# 模块级单例，避免重复创建
_MD_HEADER_SPLITTER = MarkdownHeaderTextSplitter(
    headers_to_split_on=[
        ("#",   "H1"),
        ("##",  "H2"),
        ("###", "H3"),
    ],
    strip_headers=False,
)

_CHAR_SPLITTER = RecursiveCharacterTextSplitter(
    chunk_size=512,
    chunk_overlap=100,
    separators=["\n\n", "\n", "。", "，", " ", ""],
)


def split_markdown_documents(docs: list[Document]) -> list[Document]:
    """
    对 Markdown 文档做两阶段分块：
      阶段1：MarkdownHeaderTextSplitter 按 #/##/### 标题语义切分
      阶段2：RecursiveCharacterTextSplitter 对超长段落二次切分

    两阶段结合保证：
      - 每个 chunk 对应一个完整知识点（语义完整）
      - 没有 chunk 超出嵌入模型的有效输入长度（大小可控）
      - 每个 chunk 的 metadata 里保留标题层级，用于构建 source_name

    Args:
        docs: TextLoader 返回的 list[Document]（整个 MD 文件一个 Document）

    Returns:
        切分后的 list[Document]
    """
    header_chunks: list[Document] = []

    for doc in docs:
        # 阶段1：按标题切分
        sections = _MD_HEADER_SPLITTER.split_text(doc.page_content)

        # 把原始文件路径传入每个 section 的 metadata
        source_path = doc.metadata.get("source", "")
        for section in sections:
            section.metadata["source"] = source_path

        header_chunks.extend(sections)

    # 阶段2：对超长段落二次切分（会自动继承 metadata 里的 H1/H2/H3）
    final_chunks = _CHAR_SPLITTER.split_documents(header_chunks)

    # 给每个 chunk 构建 source_name（文件名 + 标题层级）
    for chunk in final_chunks:
        source_path = chunk.metadata.get("source", "")
        filename    = Path(source_path).stem if source_path else "未知文件"
        # 用标题层级拼接，例如："课程讲义 > 第三章 > 3.1 什么是IOC"
        parts = [
            chunk.metadata.get("H1", ""),
            chunk.metadata.get("H2", ""),
            chunk.metadata.get("H3", ""),
        ]
        parts = [p for p in parts if p]   # 去掉空字符串
        chunk.metadata["source_name"] = (
            f"{filename} > {' > '.join(parts)}" if parts else filename
        )

    print(f"  [MD]  分块完成：{len(docs)} 个文件 → {len(final_chunks)} 个 chunk")
    return final_chunks

    5.3.4 两种策略对比¶

    同一份课程内容，两种策略的切法差异：

    原始内容（Markdown）：
  ## 3.2 Bean 的生命周期
  Bean 的创建过程分为以下几个阶段：
  实例化 → 属性注入 → 初始化回调 → 使用 → 销毁回调

MarkdownHeaderTextSplitter 切法：
  chunk 1 → page_content = "## 3.2 Bean 的生命周期\nBean 的创建过程..."
             metadata    = {"H1": "第三章 Spring IOC", "H2": "3.2 Bean 的生命周期"}
  （整段是一个知识点，语义完整，不再切分）

RecursiveCharacterTextSplitter 切法（如果直接用在 Markdown 上）：
  chunk 1 → "## 3.2 Bean 的生命周期\nBean 的创建过程分为以下几个"
  chunk 2 → "以下几个阶段：\n实例化 → 属性注入 → 初始化回调 → 使用 → 销毁回调"
  （从字符数出发，把完整的知识点劈成两半）
    策略 切分依据 优点 缺点
    RecursiveCharacterTextSplitter 字符数 + 分隔符优先级 普适，任何纯文本都能用 不理解语义，可能切断知识点
    MarkdownHeaderTextSplitter #/##/### 标题边界 语义完整，chunk 对应完整知识单元 只对 Markdown 有效
    两者组合（本节方案） 先语义，超长再字符 兼顾完整性和大小可控 仅适用于有标题结构的 Markdown

    5.3.5 封装统一分块入口¶

    def split_documents(docs: list[Document], file_path: str) -> list[Document]:
    """
    统一分块入口，根据文件类型自动选择分块策略。

    Args:
        docs:      load_document() 返回的 list[Document]
        file_path: 原始文件路径（用于判断格式，不重新读文件）

    Returns:
        分块后的 list[Document]，每个 chunk 的 metadata 含 source_name
    """
    ext = Path(file_path).suffix.lower()
    if ext == ".pdf":
        return split_pdf_documents(docs)
    elif ext in (".md", ".markdown"):
        return split_markdown_documents(docs)
    else:
        raise ValueError(f"不支持的文件类型：{ext}")

    5.3.6 当前阶段完整代码（build_knowledge_base.py 阶段版）¶

    # scripts/build_knowledge_base.py（阶段版：文档加载 + 分块，5.4 / 5.5 继续补全）

from pathlib import Path
from langchain_community.document_loaders import PyPDFLoader, TextLoader
from langchain_core.documents import Document
from langchain_text_splitters import (
    MarkdownHeaderTextSplitter,
    RecursiveCharacterTextSplitter,
)

# ── 模块级分块器单例 ──────────────────────────────────────────
_MD_HEADER_SPLITTER = MarkdownHeaderTextSplitter(
    headers_to_split_on=[
        ("#",   "H1"),
        ("##",  "H2"),
        ("###", "H3"),
    ],
    strip_headers=False,
)

_CHAR_SPLITTER = RecursiveCharacterTextSplitter(
    chunk_size=512,
    chunk_overlap=100,
    separators=["\n\n", "\n", "。", "，", " ", ""],
)


# ── 文档加载（5.2 内容，此处合并为完整文件）────────────────────

def load_document(file_path: str) -> list[Document]:
    """统一文档加载入口，根据扩展名选择 Loader"""
    path = Path(file_path)
    if not path.exists():
        raise FileNotFoundError(f"文件不存在：{file_path}")
    ext = path.suffix.lower()
    if ext == ".pdf":
        loader = PyPDFLoader(file_path)
        pages = loader.load()
        print(f"  [PDF] 加载完成：{len(pages)} 页 ← {path.name}")
        return pages
    elif ext in (".md", ".markdown"):
        loader = TextLoader(file_path, encoding="utf-8")
        docs = loader.load()
        print(f"  [MD]  加载完成：{len(docs[0].page_content)} 字符 ← {path.name}")
        return docs
    else:
        raise ValueError(
            f"不支持的文件类型：{ext}\n"
            f"当前支持：.pdf / .md / .markdown\n"
            f"提示：可用 markitdown 将 Word/PPT 转换为 .md 后再导入"
        )


# ── PDF 分块 ──────────────────────────────────────────────────

def split_pdf_documents(pages: list[Document]) -> list[Document]:
    """PDF 文档分块：过滤空页 + RecursiveCharacterTextSplitter"""
    non_empty_pages = [p for p in pages if len(p.page_content.strip()) > 20]
    skipped = len(pages) - len(non_empty_pages)
    if skipped > 0:
        print(f"  过滤空页：{skipped} 页（图片/扫描件页）")

    chunks = _CHAR_SPLITTER.split_documents(non_empty_pages)

    for chunk in chunks:
        filename = Path(chunk.metadata.get("source", "未知文件")).stem
        page_num = chunk.metadata.get("page", 0) + 1
        chunk.metadata["source_name"] = f"{filename} 第{page_num}页"

    print(f"  [PDF] 分块完成：{len(non_empty_pages)} 页 → {len(chunks)} 个 chunk")
    return chunks


# ── Markdown 分块 ─────────────────────────────────────────────

def split_markdown_documents(docs: list[Document]) -> list[Document]:
    """Markdown 文档分块：MarkdownHeaderTextSplitter + 二次递归切分"""
    header_chunks: list[Document] = []
    for doc in docs:
        sections = _MD_HEADER_SPLITTER.split_text(doc.page_content)
        source_path = doc.metadata.get("source", "")
        for section in sections:
            section.metadata["source"] = source_path
        header_chunks.extend(sections)

    final_chunks = _CHAR_SPLITTER.split_documents(header_chunks)

    for chunk in final_chunks:
        source_path = chunk.metadata.get("source", "")
        filename    = Path(source_path).stem if source_path else "未知文件"
        parts = [
            chunk.metadata.get("H1", ""),
            chunk.metadata.get("H2", ""),
            chunk.metadata.get("H3", ""),
        ]
        parts = [p for p in parts if p]
        chunk.metadata["source_name"] = (
            f"{filename} > {' > '.join(parts)}" if parts else filename
        )

    print(f"  [MD]  分块完成：{len(docs)} 个文件 → {len(final_chunks)} 个 chunk")
    return final_chunks


# ── 统一分块入口 ──────────────────────────────────────────────

def split_documents(docs: list[Document], file_path: str) -> list[Document]:
    """统一分块入口，根据文件类型自动选择分块策略"""
    ext = Path(file_path).suffix.lower()
    if ext == ".pdf":
        return split_pdf_documents(docs)
    elif ext in (".md", ".markdown"):
        return split_markdown_documents(docs)
    else:
        raise ValueError(f"不支持的文件类型：{ext}")

    章节总结¶

    • chunk 大小影响检索质量：推荐 200–600 字，本项目用 512 字 + 100 字重叠
    • PDF：用 RecursiveCharacterTextSplitter，按自然边界（段落→句子→字符）递归切分
    • Markdown：先用 MarkdownHeaderTextSplitter 按标题语义切，再对超长段落用 RecursiveCharacterTextSplitter 二次切，标题层级自动继承到子 chunk
    • 两种方式都在 metadata["source_name"] 里记录了来源标注，供 Milvus 存储和检索结果展示使用
    • split_documents() 统一入口屏蔽了格式差异，下游（嵌入、写入）不需要关心文件是什么格式

    下一节 5.4 BGE-M3 嵌入，拿到 chunk 列表后，用 BGE-M3 本地模型把每个 chunk 算成一对向量（1024 维稠密向量 + 稀疏权重字典），为写入 Milvus 做好准备。

    5.9 记忆管理（Memory）¶

    学习目标¶

    • 理解多轮对话场景下记忆管理的必要性，以及不加控制的后果
    • 掌握 LangGraph MemorySaver 的工作原理：thread_id 如何隔离不同学员的对话历史
    • 理解为什么每个 Agent 要使用独立的 MemorySaver 实例
    • 实现滑动窗口裁剪和摘要压缩两种记忆控制策略，理解各自适用场景

    💡 本节只写一个文件：backend/core/memory.py。 记忆管理是 RAG Agent 多轮问答的基础设施，后续 load_memory_node 和 save_memory_node 都依赖这里的工具函数。

    5.9.1 为什么需要记忆管理¶

    多轮对话是教学 Agent 的核心场景：学员会追问、修正、深入探讨同一个知识点。

    第1轮：学员："什么是 Spring IOC？"
       AI：  "IOC 是控制反转，由容器负责管理对象的生命周期……"

第2轮：学员："那依赖注入和它有什么区别？"
       AI：  ← 必须知道第1轮在讲 IOC，否则"依赖注入和它"中的"它"无从理解

    不加控制直接堆叠历史消息的问题：

    问题 后果
    历史消息无限增长 Context 窗口超限，推理报错或被截断
    Token 总量失控 API 费用随对话轮数线性增长
    早期无关内容干扰 大量旧上下文降低生成质量

    记忆管理的目标：保留对当前回答有价值的上下文，丢弃冗余历史，将 Token 用量控制在合理范围内。

    5.9.2 LangGraph MemorySaver 工作原理¶

    LangGraph 的 MemorySaver 是一个 Checkpointer，在每次 graph 运行结束时自动把完整 State 序列化保存。下次调用时，根据 thread_id 找到上次的 State，从断点处续接。

    第1轮调用：
  graph.ainvoke(state, config={"configurable": {"thread_id": "student_A_session_1"}})
  → 运行完后，MemorySaver 把 State（含 messages）保存到 thread_id 对应的槽位

第2轮调用（同一 thread_id）：
  graph.ainvoke(state, config={"configurable": {"thread_id": "student_A_session_1"}})
  → MemorySaver 自动读取上次保存的 State，合并后继续运行
  → 学员的历史消息自动续接，无需手动传递

    thread_id 的隔离作用：

    student_A_session_1  →  学员A的第1个会话历史
student_A_session_2  →  学员A的第2个会话历史（新开一局，互不影响）
student_B_session_1  →  学员B的第1个会话历史

    不同 thread_id 的 State 完全隔离，互不可见。

    5.9.3 实现 MemorySaver 管理与工具函数¶

    # backend/core/memory.py

from typing import Optional
from langgraph.checkpoint.memory import MemorySaver
from langchain_core.messages import BaseMessage, HumanMessage, AIMessage, SystemMessage

from backend.core.logger import get_logger

logger = get_logger(__name__)

# 每个 Agent 独立的 MemorySaver 实例
# 不同 Agent 的 State schema 不同，共用同一个 MemorySaver 会导致
# msgpack 序列化时 schema 字段冲突，必须隔离
_memory_savers: dict[str, MemorySaver] = {}


def get_memory_saver(agent_type: str = "default") -> MemorySaver:
    """
    获取指定 Agent 类型的 MemorySaver 单例。

    本地阶段使用内存存储（进程重启后历史丢失）。
    生产阶段替换为 AsyncPostgresSaver 即可持久化，业务代码无需修改。

    Args:
        agent_type: Agent 标识符，如 "qa" / "exam" / "resume" / "interview"

    Returns:
        MemorySaver 实例，传给 StateGraph.compile(checkpointer=...)
    """
    if agent_type not in _memory_savers:
        _memory_savers[agent_type] = MemorySaver()
        logger.info("memory.saver_initialized", agent=agent_type)
    return _memory_savers[agent_type]


def build_thread_id(student_id: str, session_id: str) -> str:
    """
    构建 LangGraph Checkpointer 使用的 thread_id。

    格式：student_{student_id}_session_{session_id}
    同一学员的不同会话有独立的历史，互不干扰。

    Example:
        build_thread_id("abc123", "xyz789")
        → "student_abc123_session_xyz789"
    """
    return f"student_{student_id}_session_{session_id}"


def build_config(student_id: str, session_id: str) -> dict:
    """
    构建 LangGraph 调用所需的 config 字典。

    用法：
        config = build_config(student_id, session_id)
        result = await graph.ainvoke(state, config=config)

    Returns:
        {"configurable": {"thread_id": "student_xxx_session_yyy"}}
    """
    return {
        "configurable": {
            "thread_id": build_thread_id(student_id, session_id),
        }
    }

    5.9.4 两种记忆控制策略¶

    策略一：滑动窗口（确定性裁剪）¶

    思路：只保留最近 N 轮对话，超出部分直接丢弃。SystemMessage（系统提示词）始终保留在最前，不计入轮数。

    window_size = 3，当前消息列表（7条）：
  [System] [H1][A1] [H2][A2] [H3][A3] [H4][A4]
                               ↑ 超出部分丢弃
裁剪后：
  [System] [H2][A2] [H3][A3] [H4][A4]   ← 保留最近 3 轮

    def trim_messages_to_window(
    messages: list[BaseMessage],
    window_size: int = 10,
) -> list[BaseMessage]:
    """
    滑动窗口裁剪：保留最近 window_size 轮对话。
    SystemMessage 始终保留在最前，不受 window_size 限制。

    Args:
        messages:    当前完整消息列表
        window_size: 保留的对话轮数（1轮 = 1 Human + 1 AI），默认 10 轮

    Returns:
        裁剪后的消息列表
    """
    system_messages  = [m for m in messages if isinstance(m, SystemMessage)]
    dialogue_messages = [m for m in messages if not isinstance(m, SystemMessage)]

    max_dialogue_messages = window_size * 2   # 1轮 = 2条消息

    if len(dialogue_messages) <= max_dialogue_messages:
        return messages   # 未超出窗口，不裁剪

    trimmed = dialogue_messages[-max_dialogue_messages:]

    logger.info(
        "memory.window_trimmed",
        original=len(dialogue_messages),
        kept=len(trimmed),
        window_size=window_size,
    )

    return system_messages + trimmed

    适用场景：大多数对话，简单高效，不需要调用 LLM。

    策略二：摘要压缩（语义保留）¶

    思路：当对话轮数超过阈值时，调用 LLM 把历史对话压缩成一段"学员画像摘要"，用摘要替换旧历史，保留语义关键信息。

    适用场景：长对话中有价值的信息（学员薄弱点、反复出现的错误、项目背景）需要跨窗口保留时。

    第一步：判断是否需要压缩

    def should_trigger_summary(
    messages: list[BaseMessage],
    threshold: int = 10,
) -> bool:
    """
    判断对话轮数是否超过阈值，决定是否触发摘要压缩。

    Args:
        messages:  当前消息列表
        threshold: 触发压缩的轮数阈值，默认 10 轮

    Returns:
        True → 需要压缩
    """
    dialogue_count = sum(
        1 for m in messages
        if isinstance(m, (HumanMessage, AIMessage))
    )
    return dialogue_count >= threshold * 2   # 每轮 2 条，dialogue_count / 2 = 实际轮数

    第二步：调用 LLM 压缩

    async def compress_to_summary(
    messages: list[BaseMessage],
    existing_summary: Optional[str] = None,
) -> str:
    """
    将历史对话压缩为结构化学员画像摘要。

    增量压缩：传入 existing_summary 防止已记录内容被重复写入。

    Args:
        messages:         待压缩的历史消息列表
        existing_summary: 上次的摘要（可选）

    Returns:
        压缩后的摘要文本
    """
    from langchain_core.messages import HumanMessage as LCHuman
    from backend.core.llm_factory import get_llm

    SUMMARY_PROMPT = """请将以下学员对话压缩为结构化学员画像摘要。

【压缩规则】
必须保留：学员明确不理解的知识点 / 反复出现的薄弱点 / 项目背景新增信息
选择性保留：已掌握知识点（简短标注）/ 学习进度信息
可以丢弃：已在上次摘要记录的内容 / 闲聊 / 已解决且理解的问题

【上一次摘要】
{previous_summary}

【本次新增对话】
{new_conversations}

请直接输出摘要文本，不要加任何前缀。"""

    conversation_text = "\n".join([
        f"{'学员' if isinstance(m, HumanMessage) else 'AI'}：{m.text if hasattr(m, 'text') and not callable(m.text) else str(m.content)}"
        for m in messages
        if isinstance(m, (HumanMessage, AIMessage))
    ])

    prompt_text = SUMMARY_PROMPT.format(
        previous_summary=existing_summary or "（无上次摘要）",
        new_conversations=conversation_text,
    )

    llm = get_llm("summarize")
    response = await llm.ainvoke([LCHuman(content=prompt_text)])
    summary = (
        response.content if isinstance(response.content, str)
        else str(response.content)
    ).strip()

    logger.info(
        "memory.summary_generated",
        input_messages=len(messages),
        summary_length=len(summary),
    )
    return summary

    5.9.5 两种策略的配合¶

    两种策略不是二选一，而是分层配合：

    每次 load_memory_node 加载历史时：

  1. 读取 MemorySaver 中的 messages
       │
       ├─ 轮数 < 10 → trim_messages_to_window(window_size=10) 保底裁剪
       │
       └─ 轮数 ≥ 10 → should_trigger_summary() 返回 True
                         → compress_to_summary() 生成新摘要
                         → 用摘要替换旧历史，再传给 LLM

    窗口裁剪保证每次 Token 量可控，摘要压缩在长对话中保留跨窗口的关键信息（薄弱点、错误模式）。

    章节总结¶

    • MemorySaver 原理：LangGraph Checkpointer，每次 graph 运行后自动保存 State，按 thread_id 隔离不同学员/会话
    • 为什么 Agent 独立 MemorySaver：不同 Agent 的 State schema 不同，共用会导致 msgpack 序列化冲突
    • build_thread_id：格式 student_{id}_session_{id}，唯一标识一段对话历史
    • 滑动窗口：保留最近 N 轮，SystemMessage 始终置顶，简单高效
    • 摘要压缩：超过 10 轮时调用 LLM 压缩历史，保留薄弱点、错误模式等跨窗口关键信息
    • 两者配合：窗口控制 Token 量，摘要保留语义关键信息，分层互补

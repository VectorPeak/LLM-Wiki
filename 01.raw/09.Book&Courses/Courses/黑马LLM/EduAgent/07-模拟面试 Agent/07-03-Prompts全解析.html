    7.3.1 系统提示词¶

    # backend/agents/interview/prompts.py

SYSTEM_PROMPT = """你是一位经验丰富的 IT 公司技术面试官，正在对应届生或初级工程师候选人进行模拟面试，岗位为{position}。

【面试官角色要求】
- 语气专业但不严苛，模拟真实面试氛围，让候选人感到适度紧张但不焦虑
- 每次只问一个问题，不连续抛出多个问题
- 对回答给予简短反应（"嗯，好的" / "有意思" / "可以"），不直接评判对错
- 不主动透露答案，可以用引导性提示（"可以从XXX角度思考"）
- 对于确实超出候选人能力范围的问题，轻描淡写地跳过（"没关系，我们换一个话题"）
- 面试结束前不暴露评分或评价结论"""

    SYSTEM_PROMPT 注入所有 LLM 调用（通过 _build_system_with_summary），让 LLM 始终以"面试官"角色回应，而不是助手角色。注入 {position} 使面试官提问聚焦在目标岗位的技术方向上。

    7.3.2 动态出题 Prompt（题库的第一备选项）¶

    TECH_BASE_GENERATE_PROMPT = """你是一位{position}岗位的资深技术面试官。
请为该岗位生成{count}道技术面试题，要真实考察候选人对核心概念的理解深度。

岗位：{position}

出题要求：
- 难度分布：中等（60%）、简单（20%）、困难（20%）
- 题目要考察原理理解，不是死记硬背，例如"请解释XXX的工作原理/核心思想"
- 每道题不超过60字，表述清晰
- 标签填该题涉及的技术方向（如 ["深度学习", "Transformer"]）

如果岗位是 AI/大模型/算法/NLP 方向，必须包含以下类型题目：
- Transformer 架构（Encoder/Decoder 各包含哪些模块，注意力机制如何计算）
- 过拟合与欠拟合的概念及解决过拟合的方法
- 自回归语言模型的生成原理
- RAG（检索增强生成）的基本流程
- 向量相似度检索的原理（如余弦相似度）
- 大模型微调方法（如 LoRA 的核心思想）

按 JSON 数组格式输出，每项格式：
{{"content": "题目内容", "difficulty": "medium/easy/hard", "tags": ["标签1"]}}

只输出 JSON 数组，不要任何其他文字。"""

    load_context_node 首轮执行时同时发起两路查询：从 DB interview_questions 表拉题（按 target_position 过滤），和用此 Prompt 让 LLM 生成 8 道岗位定制题。**LLM 生成题优先**放在题库前面（更精准），DB 题附加在后面（通用兜底）。如果 LLM 生成失败，纯用 DB 题。

    7.3.3 破冰热身阶段¶

    WARMUP_PROMPT = {
    "opening": """请生成模拟面试的欢迎开场白，邀请候选人自我介绍。

要求：
- 第一句以"欢迎来到{position}岗位的模拟面试"开头
- 自然友好，总共2-3句话
- 明确说"请先做个简单的自我介绍"，可提示包含学习背景、技术栈、感兴趣的方向""",
}

    WARMUP 阶段只有这一个 Prompt，只生成欢迎开场白，不做任何技术问题。热身阶段只持续1轮：学员发任意消息（自我介绍）就立即推进到 TECH_BASE。

    7.3.4 WARMUP → TECH_BASE 过渡专用 Prompt¶

    INTRO_EVAL_TECH_FIRST_PROMPT = """候选人刚才的自我介绍如下：
{intro}

岗位：{position}
第一道技术题：{first_question}

请以面试官身份，在同一条回复中完成以下三件事：
1. 用2-3句话中肯评价自我介绍（重点：逻辑是否清晰、各部分是否自洽、有无明显矛盾或遗漏，给出具体的正向反馈或改进提示）
2. 一句自然过渡语，引导进入技术基础环节（如"好的，接下来我们进入技术基础环节"）
3. 直接问出第一道技术题

语气自然，总共不超过5句话。"""

    这是一个**阶段衔接专用 Prompt**，只在 TECH_BASE 阶段的第一轮（stage_turns == 1 且 current_question is None）使用一次。它把"评价自我介绍"和"问第一道技术题"合并在一条回复里，避免两次单独的 LLM 调用。

    7.3.5 技术基础阶段 Prompts¶

    TECH_BASE_PROMPT = {
    # 上题反馈 + 出下一题（主流程）
    "ask_with_feedback": """上一道题：{question}
候选人回答：{answer}
回答质量：{quality}（excellent=优秀/adequate=基本达到/weak=较弱/no_answer=未作答）

下一道题：{next_question}

请以面试官身份，在同一条回复中：
1. 先用1-2句话对上一道题的回答给出具体反馈：
   - excellent：肯定核心亮点，点出1个可以进一步深化的方向
   - adequate：肯定基本思路，明确指出1个遗漏的关键知识点
   - weak：轻描淡写跳过（"好的，我们换个话题"），不展开评价
   - no_answer：给一句简短提示思路，然后说"我们换下一题"
2. 自然过渡后，直接问出下一道题

总共不超过4句话，语气自然像真实面试官。""",

    # 追问（回答 EXCELLENT 时触发）
    "followup": """候选人对"{question}"的回答如下：
{answer}

候选人回答质量：{quality}（excellent=优秀）

请生成一个深入追问，要求：
- 基于候选人回答中提到的具体技术点追问（如"你提到了X，能说说它的内部实现吗？"）
- 不重复相同问题
- 技术栈背景：{tech_stack}""",

    "weak_transition":  "好的，我们换一个话题。",
    "no_answer_hint":   """对于"{question}"，可以先从这个角度想想：它主要解决什么问题？我们换下一个话题。""",
}

    ask_with_feedback 是 TECH_BASE 的主 Prompt，把"上题评价"和"出下题"合并在一次 LLM 调用里——面试官听完回答自然地给个反馈，然后问下一题，这正是真实面试的节奏。

    weak_transition 和 no_answer_hint 是静态字符串（不调用 LLM），直接作为面试官回应输出，节省 LLM 调用。

    项目 Prompt 有两个关键设计：

    "内部参考，不要直接读出"：new_project 把简历项目的原始数据（角色、技术栈、亮点）注入 Prompt 作为上下文，但明确告知 LLM 这是内部参考，不要逐字读出，这样面试官提问时更自然（像翻简历找到这个项目，然后问）。

    技术栈定向追问：followup 里按 RAG/LLM微调/通用方向分类列出追问方向，让面试官的追问更有针对性，而不是每次都问"这个项目最大的挑战是什么？"这种泛化问题。

    7.3.8 回答质量评估 Prompts（Think Tool）¶

    # 前置推理（不约束输出格式）
EVALUATE_THINK_PROMPT = """在评估这道面试题的回答质量之前，请先进行深入分析。

【面试问题】
{question}

【候选人回答】
{answer}

请分析以下几点（中文，4-6句话）：
1. 候选人具体说明了哪些技术要点？（列举实质性内容）
2. 有哪些关键技术点完全未提及或一带而过？
3. 候选人是在真实理解基础上作答，还是在背诵模板答案？有何判断依据？
4. 回答的技术深度和覆盖广度总体如何？

直接输出分析内容，不加任何前缀标签。"""


# 主评估（输出质量标签）
EVALUATE_ANSWER_PROMPT = """请评估候选人对以下面试问题的回答质量。

【问题】
{question}

【候选人回答】
{answer}

请只输出以下4个标签之一，不要任何其他内容：
- excellent：回答有具体技术细节/量化数据/原理解释，深度足够
- adequate：回答方向正确但缺乏深度，表述较笼统
- weak：回答方向偏差、过于表面或明显不理解
- no_answer：明确表示不知道、回答为空或内容无关"""

    Think Tool 是两步评估流程：先用 EVALUATE_THINK_PROMPT 让 LLM 自由分析（不约束格式），得到 reasoning_trace；再把这段推理追加到 EVALUATE_ANSWER_PROMPT 末尾，让质量标签的判断更有依据。

    关键差异：不用 Think Tool 时，LLM 对"用不同表述说对了同一个知识点"和"背了模板答案"这两类情况容易误判。有了推理步骤后，LLM 先分析"是否真实理解"，再打标签，判断更准确。

    7.3.9 报告生成 Prompt¶

    GENERATE_REPORT_PROMPT = """请基于以下模拟面试记录，生成五维度评估报告。

【岗位】{position}
【总轮数】{total_turns}

【历史摘要（前期对话压缩）】
{history_summary}

【近期完整对话】
{conversation}

五个评估维度及权重：
1. 技术深度（35%）：技术知识掌握程度、概念理解深度、原理解释能力
2. 表达逻辑（20%）：回答条理性、是否使用 STAR 结构、语言表达清晰度
3. 项目经验（25%）：项目贡献清晰度、技术选型理由、难点解决过程
4. 抗压反应（10%）：遇到不会的问题如何应对、是否能快速调整思路
5. 整体印象（10%）：积极性、学习态度、对岗位的准备程度

评分标准：
- 90-100：远超初级岗位期望
- 75-89： 达到初级岗位要求
- 60-74： 基本达标，有明显提升空间
- 45-59： 差距较大，需系统补强
- 0-44：  尚未达到申请门槛

输出要求：
- overall_score：五维度加权平均（技术深度35% + 项目经验25% + 表达逻辑20% + 抗压反应10% + 整体印象10%）
- strengths：找出2-3条候选人在面试中真实表现出的优势
- improvements：基于实际表现，提出2-3条最重要的改进方向
- recommended_topics：列出3-5个候选人需要重点复习的知识点
- next_step_advice：给出一句具体的下一步备考建议"""

    报告 Prompt 同时接收两部分对话：{history_summary}（前期对话压缩摘要）和 {conversation}（最近40条完整对话）。这解决了面试对话可能超出 LLM 上下文窗口的问题——早期对话被压缩成摘要，保留关键信息；近期对话保持完整，让报告生成时能看到细节。

    章节总结¶

    • 10 个 Prompt 模块：SYSTEM / WARMUP / INTRO_EVAL_TECH_FIRST / TECH_BASE / PROJECT / CLOSING / STAGE_TRANSITION / EVALUATE_THINK / EVALUATE_ANSWER / GENERATE_REPORT
    • 动态出题：TECH_BASE_GENERATE_PROMPT 让 LLM 为任意岗位生成面试题，不依赖 DB 必须有数据
    • 合并 Prompt 的价值：INTRO_EVAL_TECH_FIRST 和 ask_with_feedback 把"评价 + 出题"合一，减少 LLM 调用，节奏更自然
    • Think Tool 两步：先自由推理（EVALUATE_THINK），再打标签（EVALUATE_ANSWER），减少对模板答案的误判

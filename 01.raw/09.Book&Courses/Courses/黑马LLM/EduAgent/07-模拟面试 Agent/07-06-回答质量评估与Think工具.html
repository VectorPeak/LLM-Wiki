    7.6 evaluate_answer 节点¶

    学习目标¶

    📁 本节修改的文件¶

    文件 状态 说明

    7.6.1 节点职责¶

    evaluate_answer_node 有两个职责：

    1. 评估回答质量：给学员上一条回答打 AnswerQuality 标签（EXCELLENT/ADEQUATE/WEAK/NO_ANSWER），供下一个节点 generate_response 决定追问还是换题
    2. 维护轮次计数：total_turn_count += 1，stage_turn_count += 1

    这两件事放在同一个节点里，确保计数和评估同步更新到 State。

    7.6.2 跳过评估的两种情况¶

    async def evaluate_answer_node(state: InterviewState) -> dict:
    """
    评估学员上一轮回答质量（EXCELLENT / ADEQUATE / WEAK / NO_ANSWER）。

    读取 state：
        total_turn_count / current_stage  判断是否跳过评估
        messages                          取学员最后一条回答
        current_question                  取当前题干（评估时作上下文）
        stage_turn_count                  用于 +1
    返回（写回 state）：
        last_answer_quality  本轮质量标签（给 generate_response 决定追问/换题）
        total_turn_count / stage_turn_count  各 +1（轮次真实发生）

    首轮和热身阶段不评估，直接返回 ADEQUATE。
    """
    total_turns   = state.get("total_turn_count", 0)    # 当前总轮数
    current_stage = state.get("current_stage", InterviewStage.WARMUP.value)  # 当前阶段
    messages      = state.get("messages", [])           # 对话消息

    # 首轮或热身阶段跳过评估：直接给中性标签 ADEQUATE，但计数照常 +1
    if total_turns == 0 or current_stage == InterviewStage.WARMUP.value:
        return {
            "last_answer_quality": AnswerQuality.ADEQUATE.value,    # 默认质量
            "total_turn_count":    total_turns + 1,                # 总轮数 +1
            "stage_turn_count":    state.get("stage_turn_count", 0) + 1,  # 阶段轮数 +1
        }

    首轮跳过（total_turns == 0）：首轮触发消息是 [开始面试]，这是 API 层注入的系统消息，不是学员的真实回答，不需要评估。

    热身阶段跳过（current_stage == WARMUP）：热身只是让学员做自我介绍，没有具体的技术问题，评估质量没有意义。跳过后直接给默认值 ADEQUATE，让 generate_response 继续生成热身回应。

    两种情况都**照常增加计数**（total_turn_count += 1，stage_turn_count += 1），因为轮次是真实发生的，只是不评估内容。

    7.6.3 明确未作答的快速路径¶

        student_answer = _get_last_student_answer(messages)   # 取学员最后一条回答文本

    # 明确未作答：空回答，或直说"不知道/不清楚/没学过" → 直接 NO_ANSWER，省一次 LLM
    if not student_answer.strip() or student_answer.strip() in ["不知道", "不清楚", "没学过"]:
        return {
            "last_answer_quality": AnswerQuality.NO_ANSWER.value,  # 标记未作答
            "total_turn_count":    total_turns + 1,               # 计数照常 +1
            "stage_turn_count":    state.get("stage_turn_count", 0) + 1,
        }

    如果学员明确表示"不知道"，不需要调用 LLM 评估，直接标记 NO_ANSWER，节省一次 LLM 调用。

    7.6.4 Think Tool 两步评估¶

        current_q     = state.get("current_question") or {}   # 当前题（可能为空 dict）
    question_text = current_q.get("content", "上一个问题") # 题干（缺省占位）
    answer_text   = student_answer[:800]                  # 回答截断到 800 字，控制 token

    # ── 第一步：Think Tool 推理分析（不约束格式，让 LLM 写判断依据）──
    reasoning_trace = ""
    try:
        think_prompt = EVALUATE_THINK_PROMPT.format(      # 拼推理 Prompt
            question=question_text,
            answer=answer_text,
        )
        think_llm  = get_llm("qa", temperature=0)         # 取模型（温度0，评估要稳定）
        think_resp = await think_llm.ainvoke([HumanMessage(content=think_prompt)])  # 调 LLM 推理
        reasoning_trace = _msg_text(think_resp).strip()   # 取出推理文本（"内心独白"）
        logger.debug("evaluate_think.done", stage=current_stage)
    except Exception as e:                                # 推理失败不致命，继续走主评估
        logger.warning("evaluate_think.failed", error=str(e))

    # ── 第二步：主评估，把第一步的推理结论注入 prompt 末尾 ───────
    think_context = (
        f"\n\n【评估前分析】\n{reasoning_trace}" if reasoning_trace else ""  # 有推理才追加
    )
    prompt = EVALUATE_ANSWER_PROMPT.format(               # 拼主评估 Prompt
        question=question_text,
        answer=answer_text,
    ) + think_context                                     # 末尾接上推理依据

    try:
        llm = get_llm("qa", temperature=0)                # 同样温度0
        response = await llm.ainvoke([HumanMessage(content=prompt)])  # 调 LLM 打标签
        quality_str = _msg_text(response).strip().lower() # 取文本转小写，便于匹配

        # 用 in 匹配（LLM 可能带空格/换行），命中哪个就用哪个标签
        if "excellent" in quality_str or "优秀" in quality_str:
            quality = AnswerQuality.EXCELLENT.value
        elif "weak" in quality_str or "较弱" in quality_str:
            quality = AnswerQuality.WEAK.value
        elif "no_answer" in quality_str or "未作答" in quality_str:
            quality = AnswerQuality.NO_ANSWER.value
        else:
            quality = AnswerQuality.ADEQUATE.value        # 兜底：模糊情况按基本及格
    except Exception as e:                                # 评估失败 → 兜底 ADEQUATE
        logger.warning("evaluate_answer.failed", error=str(e))
        quality = AnswerQuality.ADEQUATE.value

    logger.info(
        "evaluate_answer.done",
        stage=current_stage,
        quality=quality,
        total_turns=total_turns + 1,
    )

    return {
        "last_answer_quality": quality,                   # 本轮质量标签
        "total_turn_count":    total_turns + 1,           # 总轮数 +1
        "stage_turn_count":    state.get("stage_turn_count", 0) + 1,  # 阶段轮数 +1
    }

    7.6.5 Think Tool 的执行流¶

    第一步（自由推理）
  EVALUATE_THINK_PROMPT.format(question=..., answer=...)
         │
         ▼
  LLM 输出 reasoning_trace（自然语言分析，4-6句）：
    "候选人提到了 HashMap 扩容因子 0.75 和 resize() 方法，但没有说清
     扩容时重哈希的过程。回答方式偏向背诵，缺乏对链表转红黑树的原理解释..."

第二步（结构化评估）
  EVALUATE_ANSWER_PROMPT.format(question=..., answer=...)
  + "\n\n【评估前分析】\n" + reasoning_trace
         │
         ▼
  LLM 输出（仅4个标签之一）：
    "adequate"

    两步的关键差异： - 第一步 Prompt：不约束输出格式，让 LLM 自由分析，写出判断依据 - 第二步 Prompt：严格约束输出，只输出4个标签之一

    第一步的 reasoning_trace 相当于"内心独白"，追加到第二步 Prompt 末尾，使 LLM 在打标签时有明确的推理依据，而不是凭直觉判断。

    7.6.6 质量标签的文本解析¶

    LLM 输出四个标签之一，用 in 匹配而不是精确比对：

    if "excellent" in quality_str or "优秀" in quality_str:
    quality = AnswerQuality.EXCELLENT.value
elif "weak" in quality_str or "较弱" in quality_str:
    quality = AnswerQuality.WEAK.value
elif "no_answer" in quality_str or "未作答" in quality_str:
    quality = AnswerQuality.NO_ANSWER.value
else:
    quality = AnswerQuality.ADEQUATE.value   # 兜底：方向判断 adequate 最常见

    用 in 而不是 == 是因为 LLM 有时会在标签前后加空格或换行。兜底到 ADEQUATE 是合理的保守策略——模糊情况视为基本及格，不追问也不直接跳过。

    🧪 本节实测¶

    这个节点会**真的调用 LLM**（优秀回答路径调两次：Think Tool 推理 + 主评估）。测试喂入三种回答，看它分别打出什么质量标签。

    前置条件：.env.local 配好 DEEPSEEK_API_KEY（②③ 两条路径不调用 LLM，①调用）。

    # scripts/manual_tests/itv_07_06_evaluate.py
# 运行：python scripts/manual_tests/itv_07_06_evaluate.py

import asyncio
from langchain_core.messages import HumanMessage

from itv_fixtures import (
    load_env, section, make_state_eval_excellent, make_state_eval_no_answer,
    base_state, ANSWER_SCRIPT,
)

load_env()

from backend.agents.interview.nodes import evaluate_answer_node


async def run(title: str, state: dict):
    cur_q  = (state.get("current_question") or {}).get("content", "（无）")
    answer = state["messages"][-1].content
    print(f"\n[{title}]")
    print(f"  问题: {cur_q}")
    print(f"  学员回答: {answer[:50]}{'...' if len(answer) > 50 else ''}")
    updates = await evaluate_answer_node(state)
    print(f"  → 质量标签: {updates['last_answer_quality']}")
    print(f"  → 计数更新: total_turns={updates['total_turn_count']} "
          f"stage_turns={updates['stage_turn_count']}")


async def main():
    section("① 优秀回答（Transformer）→ Think Tool 推理 + LLM 评估")
    await run("有技术细节的回答", make_state_eval_excellent())

    section("② 明确不会（'不知道'）→ 快速路径，不调用 LLM")
    await run("no_answer 快速路径", make_state_eval_no_answer())

    section("③ WARMUP 阶段 → 跳过评估，直接 ADEQUATE")
    await run("warmup 跳过", base_state(
        current_stage="warmup", stage_turn_count=1, total_turn_count=1,
        messages=[HumanMessage(content=ANSWER_SCRIPT[0])]))

    section("✅ 07-06 evaluate_answer 三条路径验证完成")


if __name__ == "__main__":
    asyncio.run(main())

    💡 读懂这个测试： - 第①条里这段 Transformer 回答内容其实不错，但 LLM 在 Think Tool 分析后判为 adequate——质量标签是 LLM 的判断，不是写死的。要它给 excellent，回答得有更突出的原理深度或量化细节。换句话说，这个标签每次由模型现场评定，同一段回答在不同措辞下可能拿到不同标签，这正是要让学员亲眼看到的。 - 第②条 不知道 命中快速路径，完全没调用 LLM 就返回 no_answer，省一次 API 调用。 - 第③条 WARMUP 阶段直接跳过评估返回 adequate，但 total_turns / stage_turns 照常 +1（轮次真实发生了，只是不评估内容）。

    章节总结¶

    • 跳过路径：首轮和 WARMUP 阶段直接返回 ADEQUATE，照常增加计数
    • 快速路径：学员明确不知道 → 直接 NO_ANSWER，不调用 LLM
    • Think Tool 两步：先自由推理（reasoning_trace）→ 再把推理追加到主 Prompt 做打标签；两步都用 get_llm("qa", temperature=0) 保证确定性
    • 兜底策略：LLM 异常时默认 ADEQUATE；匹配用 in，兜底用 else

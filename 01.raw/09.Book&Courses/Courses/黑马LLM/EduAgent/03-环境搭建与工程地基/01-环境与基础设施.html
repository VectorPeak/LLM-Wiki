    3.1 环境与基础设施¶

    学习目标¶

    • 理清 EduAgent 真正依赖的基础设施：PostgreSQL + Milvus
    • 用 conda 创建并激活 Python 3.11 开发环境
    • 看懂并安装精简后的项目依赖 requirements.txt
    • 用 docker-compose 一键启动 PostgreSQL 与 Milvus，并理解端口隔离设计
    • 配置 .env.local 环境变量，理解「绝不硬编码、绝不提交密钥」的原则
    • 完成环境连通性验证

    从本章开始，我们正式进入项目实战。本节是「打地基」的第一步——把开发环境和基础设施搭起来。预备篇学的工具，从这里开始一个个落到真实工程里。

    3.1.1 本章要搭什么：基础设施总览¶

    EduAgent 应用层**真正连接**的基础设施只有两个：

    • PostgreSQL：关系型数据库，存用户、试卷、批改记录、会话等业务数据（回顾 2.6）；
    • Milvus：向量数据库，存知识库文档的向量，支撑问答 Agent 的 RAG 检索。

    但 Milvus 自己运行时需要两个**内部依赖**——etcd（存元数据）和 minio（存向量文件）。这两个容器是给 Milvus 用的，我们的应用代码完全不直接访问它们（回顾第一章的说明）。所以我们启动时会带上它们，但你不用关心它们的细节。

    各服务的端口规划如下。注意一个贯穿全项目的设计——端口隔离：作者本机已经跑着其它的 PostgreSQL、Milvus 等服务，为了不冲突，EduAgent 全部用「+1」之类的隔离端口。

    服务 容器内端口 对外端口 用途 应用是否直接连
    PostgreSQL 5432 5433 业务数据 ✅ 是
    Milvus 19530 19531 向量数据 ✅ 是
    etcd 2379 不对外 Milvus 元数据 ❌ 否（Milvus 内部用）
    MinIO 9000 不对外 Milvus 向量文件存储 ❌ 否（Milvus 内部用）
    FastAPI 后端 — 8000 主应用 —

    为什么端口要隔离？ 因为本机 5432、19530 等默认端口可能已被其它项目占用。EduAgent 统一用 5433、19531 这些「错开」的端口，避免和你机器上已有的服务打架。所有端口都从 .env.local 读取，代码里绝不写死。

    右侧的 → 3.x / 第 N 章 标注了每个文件**将在哪一节创建**。你现在不需要创建这些 .py 文件的内容，只需要把目录建出来、并在每个包目录下放一个空的 __init__.py。可以用下面的命令快速搭好骨架（Mac / Linux）：

    # 在项目根目录 EduAgent/ 下执行
mkdir -p scripts models backend/core backend/db backend/api/v1 \
         backend/agents/{resume,qa,exam,interview} backend/mcp

# 给所有 Python 包目录创建空的 __init__.py
touch backend/__init__.py backend/core/__init__.py backend/db/__init__.py \
      backend/api/__init__.py backend/api/v1/__init__.py \
      backend/agents/__init__.py backend/mcp/__init__.py

    💡 为什么要有 __init__.py？ 它（哪怕是空文件）告诉 Python「这个目录是一个包」，这样 from backend.config import get_settings 这类导入才能正常工作。Windows 用户可以在资源管理器里手动新建这些空文件，或用 Git Bash 执行上面的命令。

    之后每一节，开头都会有一个「📁 本节要创建/修改的文件」清单，并标出当前进度，你照着往对应位置填代码即可。

    3.1.3 创建 Python 3.11 环境（conda）¶

    本项目**严格锁定 Python 3.11**（部分依赖对版本敏感）。用 conda 创建一个独立环境，避免污染你的其它项目：

    # 创建名为 edu_agent 的环境，指定 Python 3.11
conda create -n edu_agent python=3.11 -y

# 激活环境（之后每次开发都要先执行这句）
conda activate edu_agent

# 验证版本
python --version      # 应输出 Python 3.11.x

    如果你还没装 conda，可以安装 Miniconda（轻量版）。之后所有的 pip install、python 命令，都请确认是在 edu_agent 这个已激活的环境里执行。

    3.1.5 用 docker-compose 启动基础设施¶

    我们用 Docker 来运行 PostgreSQL 和 Milvus，省去手动安装的麻烦。在项目根目录准备 docker-compose.yml。下面是**精简后的版本**——原始文件里的 Redis、Judge0、Langfuse、前端等服务都已删除（代码用不到），只保留四个服务：postgres + milvus + Milvus 的两个内部依赖 etcd / minio。

    # docker-compose.yml — EduAgent 本地开发环境（精简版）
# 启动：docker-compose --env-file .env.local up -d
version: "3.9"

services:

  # ── PostgreSQL 主数据库（对外 5433，本机 5432 已占用）──
  postgres:
    image: postgres:15-alpine
    container_name: edu_agent_postgres
    restart: unless-stopped
    environment:
      POSTGRES_DB: ${DB_NAME:-eduagent}
      POSTGRES_USER: ${DB_USER}
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - postgres_data:/var/lib/postgresql/data
      # 容器首次启动时自动执行建表脚本（见 3.2 节）
      - ./scripts/init_db.sql:/docker-entrypoint-initdb.d/01_init_db.sql:ro
    ports:
      - "5433:5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USER} -d ${DB_NAME:-eduagent}"]
      interval: 10s
      timeout: 5s
      retries: 5

  # ── etcd（Milvus 元数据存储，仅内部使用，不对外暴露端口）──
  etcd:
    image: quay.io/coreos/etcd:v3.5.14
    container_name: edu_agent_etcd
    restart: unless-stopped
    environment:
      ETCD_AUTO_COMPACTION_MODE: revision
      ETCD_AUTO_COMPACTION_RETENTION: "1000"
      ETCD_QUOTA_BACKEND_BYTES: "4294967296"
    command: >
      etcd
      --advertise-client-urls=http://127.0.0.1:2379
      --listen-client-urls=http://0.0.0.0:2379
      --data-dir=/etcd
    volumes:
      - etcd_data:/etcd

  # ── MinIO（Milvus 向量文件存储，仅内部使用，不对外暴露端口）──
  minio:
    image: minio/minio:latest
    container_name: edu_agent_minio
    restart: unless-stopped
    command: server /data
    environment:
      MINIO_ROOT_USER: ${MINIO_ACCESS_KEY:-minioadmin}
      MINIO_ROOT_PASSWORD: ${MINIO_SECRET_KEY:-minioadmin}
    volumes:
      - minio_data:/data
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9000/minio/health/live"]
      interval: 15s
      timeout: 5s
      retries: 5

  # ── Milvus 向量数据库（对外 19531，本机 19530 已占用）──
  milvus:
    image: milvusdb/milvus:v2.4.0
    container_name: edu_agent_milvus
    restart: unless-stopped
    command: ["milvus", "run", "standalone"]
    environment:
      ETCD_ENDPOINTS: etcd:2379                 # 连内部 etcd
      MINIO_ADDRESS: minio:9000                 # 连内部 MinIO
      MINIO_ACCESS_KEY_ID: ${MINIO_ACCESS_KEY:-minioadmin}
      MINIO_SECRET_ACCESS_KEY: ${MINIO_SECRET_KEY:-minioadmin}
    volumes:
      - milvus_data:/var/lib/milvus
    ports:
      - "19531:19530"
    depends_on:
      etcd:
        condition: service_started
      minio:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9091/healthz"]
      interval: 15s
      timeout: 10s
      retries: 10

# ── 数据卷（持久化，重启容器数据不丢失）──
volumes:
  postgres_data:
  etcd_data:
  minio_data:
  milvus_data:

    启动基础设施（先确保 .env.local 已配好，见下一节）：

    docker-compose --env-file .env.local up -d

    -d 表示后台运行。等约 20~30 秒后，检查各服务是否健康：

    docker-compose ps

    确认 edu_agent_postgres 和 edu_agent_milvus 的状态都是 healthy：

    NAME                  STATUS
edu_agent_postgres    Up (healthy)
edu_agent_etcd        Up
edu_agent_minio       Up (healthy)
edu_agent_milvus      Up (healthy)

    几个要点： - 数据卷（volumes） 让数据持久化——即使你 docker-compose down 再重启，数据库里的数据也不会丢。 - healthcheck 让 Docker 知道每个服务有没有真正就绪。Milvus 的 depends_on 配置确保它在 etcd、MinIO 准备好之后才启动。 - etcd 和 MinIO 没有对外端口——它们只在 Docker 内部网络里被 Milvus 通过 etcd:2379、minio:9000 访问，你的应用和宿主机都不需要碰它们。

    3.1.7 Windows 用户特别说明¶

    如果你用 Windows + conda，可能遇到一个导入 _lzma 的报错（DLL load failed while importing _lzma）。项目的 main.py 顶部已内置了这个问题的修复代码——它会自动把 conda 的 DLL 路径加入搜索范围，正常情况下你不会遇到这个错误。只要确认你是在已激活的 edu_agent 环境里运行即可。这一点你现在了解即可，不用做任何额外操作。

    3.1.8 验证环境连通性¶

    最后做个最小的连通性检查，确认两个数据库都能连上。新建 check_env.py：

    import asyncio
from sqlalchemy import text
from sqlalchemy.ext.asyncio import create_async_engine
from pymilvus import connections, utility

DB_URL = "postgresql+asyncpg://eduagent_user:你的密码@localhost:5433/eduagent"

async def check_postgres():
    engine = create_async_engine(DB_URL)
    async with engine.connect() as conn:
        r = await conn.execute(text("SELECT 1"))
        print("✅ PostgreSQL 连通：", r.scalar())
    await engine.dispose()

def check_milvus():
    connections.connect(alias="default", host="localhost", port="19531")
    print("✅ Milvus 连通，已有集合：", utility.list_collections())

async def main():
    await check_postgres()
    check_milvus()

asyncio.run(main())

    运行 python check_env.py，若两行都打印出 ✅，说明基础设施已就绪：

    ✅ PostgreSQL 连通： 1
✅ Milvus 连通，已有集合： []

    （此时 Milvus 还没有任何集合，是正常的——我们会在第五章建知识库集合。完整的环境自检脚本 verify_env.py 会在第八章实现。）

    章节总结¶

    本节我们搭好了 EduAgent 的开发环境与基础设施：

    • 依赖梳理：应用真正连接的只有 PostgreSQL（5433）和 Milvus（19531）；etcd 和 MinIO 只是 Milvus 的内部依赖，应用不碰。
    • Python 环境：用 conda 创建并激活严格锁定的 Python 3.11 环境 edu_agent。
    • 依赖安装：用精简后的 requirements.txt（剔除了 Redis、Celery、OCR、语音、Langfuse 等未使用的包），pip install 一键装好。
    • 基础设施：用精简后的 docker-compose.yml 一键启动 PostgreSQL + Milvus，理解端口隔离与 healthcheck。
    • 环境变量：用 .env.local 管理所有配置与密钥，牢记「密钥与代码分离、绝不提交 Git、绝不硬编码」。
    • 验证：用最小脚本确认两个数据库连通。

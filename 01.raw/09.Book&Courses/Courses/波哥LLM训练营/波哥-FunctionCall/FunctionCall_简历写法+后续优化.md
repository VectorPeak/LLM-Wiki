### 1.3 精简版（适合一页简历）

- 项目背景：构建能“理解 - 决策 - 调用工具 - 整合输出”的旅行顾问 Agent，覆盖旅行规划 / 问路 / 酒店检索 / 闲聊等主线工作流；支持链式工具调用与多轮反问补齐信息。
- 技术栈：Python、Transformers / PEFT、Qwen-3 0.6B、LoRA、Milvus / RAG、Pandas、NumPy、Docker、Bash
- 核心工作与方案：
  - 数据构造：搭建端到端数据 pipeline，按路由类型精确采样与标注（旅行规划、问路、酒店查询、闲聊 / 拒答，对话追问 / 不追问），构建 3030 条种子集；通过模板生成、多轮上下文拼接、槽位扰动（日期 / 地点 / 预算）、语义改写等策略做数据增强；随机种子 42 进行 80 / 20 训练 / 测试严格分层划分，确保微调数据覆盖面与多样性。（可加入人工评估链路）
  - 不平衡样本处理：针对多轮工具调用样本最终 response 稀少的长尾问题，设计按 assistant 轮数渐进拆分复本对话（1 轮 -> 2 轮 -> N 轮），最后一轮复制 3 份强化输出质量；对无工具调用对话保持原样完整分布，使 3030 条训练样本扩展至 7612 条，有效缓解样本不平衡导致的长尾学习不足问题。
  - 微调：基于 Qwen-3 0.6B 进行 LoRA SFT，同时优化自然语言回复与函数调用参数（argument-level）CE Loss，teacher-forcing 学习工具链顺序调用与参数对齐；训练 1 个 epoch，loss 从 xx 到 xx。
  - 评估与上线：从路由准确率、函数调用精确 / 召回、端到端成功率、延迟、人工质量打分等多维评估；A / B 验证后上线，搭建数据回流与持续评估迭代闭环。
- 成果：
  - 端到端任务成功率：从 [XX%] 提升至 [YY%]；路由准确率 +[A]pp；函数调用 EM +[B]pp
  - 推理时延：较 API 串联方案降低约 [C]%；成本下降约 [D]%

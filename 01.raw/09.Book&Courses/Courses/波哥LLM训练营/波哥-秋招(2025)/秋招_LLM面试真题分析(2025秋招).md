## 二、分门别类说面试

## 1. 大模型架构与原理

面试官对“大模型架构与原理”的考察，已经从“是什么”（What）的层面，全面深入到“为什么”（Why）和“怎么办”（How）的层面。考察的核心是以 Transformer 为绝对基石，辐射到其关键组件的数学原理、设计思想的深度辨析、现代架构的演进与权衡，以及前沿变体的实现与优化。

求职者不仅要能背诵架构图，更要能：

1. **深入推导**：手写公式，解释每个符号的物理意义。
2. **辨析比较**：清晰阐述不同组件、不同架构的优劣和设计思考。
3. **洞察前沿**：熟悉 LLaMA、Qwen、MoE 等现代架构的创新点及其背后的动机。
4. **动手实现**：具备手撕核心模块（尤其是注意力机制）代码的能力。

以下是根据面试题频率和深度整理出的四大核心模块和若干高频话题：

### 模块一：Transformer 全貌

这是所有问题的起点，也是必考的基础。考察点覆盖了从宏观到微观的各个层面。

闭上眼睛，脑子里应该有那张经典的图。

#### 1. 整体架构（必考中的必考）

- **题目特征**：“请详细描述 Transformer 模型的核心结构/架构组成...”
- **考察要点**：
  - 能够清晰画出或描述 Encoder-Decoder 的完整结构图。
  - 准确说出每个宏观模块：输入嵌入（Input Embedding）、位置编码（Positional Encoding）、编码器栈（Encoder Stack）、解码器栈（Decoder Stack）、输出层（Linear + Softmax）。
  - 解释数据流：一个序列是如何在模型中从输入到输出进行传递和转换的。

#### 2. 架构演进与选型思辨（高频进阶题）

- **题目特征**：“为什么当前主流大模型多采用 Decoder-only 架构？”“比较 Encoder-Decoder、Encoder-only、Decoder-only...”
- **考察要点**：
  - **Encoder-Decoder（如 T5、BART）**：优势在于 NLU 和 NLG 任务的结合，适用于翻译、摘要等 Seq2Seq 任务。
  - **Encoder-only（如 BERT）**：优势在于深度双向上下文理解，适用于分类、NER 等 NLU 任务。
  - **Decoder-only（如 GPT、LLaMA）**：优势在于自回归生成，天然适合文本续写、对话等生成任务。面试中需要重点阐述其成为主流的原因：训练目标统一、易于扩展、生成能力强大、无缝适应 few-shot/zero-shot learning。

### 模块二：核心引擎——注意力机制

这是整个架构原理考察的重中之重，问题最密集、最深入、花样最多。

其实就是围着注意力转。

#### 1. 自注意力机制（Self-Attention）的原理与公式（必考）

- **题目特征**：“请详细解释 Self-Attention...”“推导公式...”“手写代码...”
- **考察要点**：
  - **QKV 的物理意义**：必须能用通俗语言解释 Query（查询）、Key（键）、Value（值）。例如：“Query 代表当前词想寻找的信息，Key 代表序列中其他词能提供的信息标签，Value 是这些词的实际内容。通过计算 Q 和 K 的相似度，来决定该给每个 V 多大的权重。”
  - **计算过程**：能够一步步描述计算流程：输入向量 -> 线性变换得到 Q、K、V -> 计算注意力分数（Score = Q · K^T）-> 缩放（Scale）-> Mask（可选）-> Softmax 归一化得到权重（Attention Weights）-> 加权求和（Σ weights · V）得到输出。
  - **数学公式**：必须能准确写出：

$$
Attention(Q,K,V)=softmax\left(\frac{QK^T}{\sqrt{d_k}}\right)V
$$

#### 2. 多头注意力（Multi-Head Attention）的设计方法（高频）

- **题目特征**：“为什么使用多头注意力？”“解释其工作原理...”
- **考察要点**：
  - **动机（Why）**：核心是“允许模型在不同位置、从不同的表示子空间共同关注信息”。单头注意力像是只用一种方式看问题，多头则是从多个角度（如语法关系、语义关系等）综合分析。
  - **过程（How）**：描述 Q、K、V 如何被线性投影并拆分（split）成多个“头”，每个头独立计算注意力，最后将所有头的输出拼接（concat）并经过一个最终的线性投影。
  - **维度变化**：能清晰说明在整个 MHA 计算过程中张量维度的变化。

#### 3. 关键细节的深度追问（区分度题）

- **题目特征**：“为什么注意力分数要除以 $\sqrt{d_k}$？”“Mask 的作用是什么？”
- **考察要点**：
  - **缩放因子 $\sqrt{d_k}$**：这是极高频问题。标准答案需包含两方面：
    - **数学原理**：当 $d_k$ 较大时，点积 $Q \cdot K^T$ 的结果方差会增大，可能导致一些值过大。
    - **实际效果**：这会将 Softmax 函数推向梯度极小的饱和区，导致梯度消失，使训练不稳定。除以 $\sqrt{d_k}$ 是为了将点积结果的方差稳定在 1 附近，保持梯度平稳。
  - **Masking**：能够区分 Padding Mask（在 Encoder 和 Decoder 中都用，忽略 padding token）和 Causal/Look-ahead Mask（仅用于 Decoder，防止未来的 token 信息泄露到当前位置）。

### 模块三：关键辅助组件与设计选择

这些组件保证了 Transformer 能够有效工作，是考察候选人知识完备性的关键。

知其然，知其所以然。

#### 1. 位置编码（Positional Encoding）（高频）

- **题目特征**：“Transformer 如何处理位置信息？”“请解释 RoPE 的原理及其优势...”
- **考察要点**：
  - **必要性**：Transformer 本身是置换不变的（Permutation-Invariant），无法感知序列顺序，必须引入位置信息。
  - **方法比较**：
    - **绝对位置编码（Absolute PE, sin/cos）**：原始方案，能外推但效果有限。
    - **可学习位置编码（Learned PE，如 BERT）**：灵活但外推性差。
    - **相对位置编码（Relative PE）**：关注相对距离，更符合直觉。
    - **旋转位置编码（RoPE, Rotary Position Embedding）**：当前热点与重点。必须理解其核心思想：通过对 Q、K 向量进行旋转来隐式地引入绝对位置并显式地编码相对位置信息。其优势在于良好的外推性和理论优雅性，是 LLaMA 等模型成功的关键之一。

#### 2. 残差连接（Residual Connection）与层归一化（Layer Normalization）（高频）

- **题目特征**：“为什么使用残差连接和 LayerNorm？”“为什么用 LayerNorm 而不是 BatchNorm？”
- **考察要点**：
  - **残差连接**：解决深度网络梯度消失和网络退化问题，保证信息和梯度能顺畅地跨层流动。
  - **Layer Normalization**：稳定训练过程，加速收敛。
  - **LayerNorm vs. BatchNorm**：极高频对比题。核心区别在于归一化的维度。BN 在 batch 维度上操作，对 batch size 敏感，不适合长度可变的 NLP 序列。LN 在特征维度上对单个样本操作，与 batch size 和序列长度无关，完美契合 NLP 场景。
  - **变体（RMSNorm）**：知道 RMSNorm 是 LN 的简化版，去掉了 re-centering（减均值），计算更快，在现代大模型（如 LLaMA、Qwen）中被广泛应用。

#### 3. 前馈网络（Feed-Forward Network, FFN）

- **题目特征**：“FFN 的作用是什么？”
- **考察要点**：
  - **作用**：提供非线性变换，增加模型容量和表达能力。可以理解为在自注意力提取的加权信息基础上，进行一次特征加工和提炼。
  - **结构**：通常是两个线性层夹一个非线性激活函数（ReLU、GeLU，或现代模型中的 SwiGLU）。

### 模块四：现代架构创新与理论分析

这部分考察候选人是否跟进行业前沿，并具备系统性分析能力。

多看新的、有影响力的论文，比如 DeepSeek、Kimi、Qwen 的技术报告。

#### 1. 注意力机制的优化变体（高频，体现技术视野）

- **题目特征**：“介绍几种节省内存的注意力变体...”“解释 GQA/MQA/FlashAttention...”
- **考察要点**：
  - **动机**：标准自注意力的计算和空间复杂度都是 $O(n^2)$，n 为序列长度，这成为处理长文本的瓶颈。
  - **主流方案**：
    - **Multi-Query Attention（MQA）**：所有头共享一套 K 和 V，大幅减少推理时的 KV Cache 大小。
    - **Grouped-Query Attention（GQA）**：MQA 和 MHA 的折中，多组 Query 共享一套 K 和 V，平衡了效果和效率。
    - **FlashAttention**：一种 I/O 感知的注意力算法，通过分块计算避免读写巨大的注意力矩阵到 HBM，从而实现加速和节省内存。
    - **稀疏注意力（Sparse Attention）**：将全局注意力替换为窗口注意力、全局注意力和随机注意力的组合，将复杂度降至 $O(n)$。

#### 2. 混合专家模型（Mixture of Experts, MoE）（前沿热点）

- **题目特征**：“解释 MoE 的原理...”“MoE 相比 Dense 模型的优势...”
- **考察要点**：
  - **原理**：模型由多个“专家”（通常是 FFN）和一个“门控网络”（Router）组成。对每个 token，门控网络选择激活一小部分（如 top-k）专家进行计算。
  - **优势**：能够在不显著增加计算量（FLOPs）的情况下，极大扩展模型参数量，提升模型容量。
  - **挑战**：训练不稳定、负载均衡（Load Balancing）问题、推理部署复杂。

#### 3. 特定模型架构分析

- **题目特征**：“分析 LLaMA 的架构特点...”“比较 BERT 和 GPT...”
- **考察要点**：要求对至少一个主流开源模型（特别是 LLaMA 系列）的技术栈了如指掌，例如 Pre-Normalization（稳定训练）、RMSNorm（高效）、SwiGLU（更好的激活函数）、RoPE（优秀的位置编码）。

#### 4. 复杂度与幻觉分析

- **题目特征**：“分析 Transformer 的计算复杂度...”“大模型产生幻觉的原因...”
- **考察要点**：
  - **复杂度**：能够准确给出自注意力和 FFN 的时间/空间复杂度，并理解它们是模型性能的主要瓶颈。
  - **幻觉**：从模型架构（如自回归生成模式的固有缺陷）、训练数据（噪声、偏差、知识截止）和推理过程（解码策略）等角度分析幻觉成因。

### 备考建议

1. **回归经典**：彻底吃透《Attention Is All You Need》原始论文，确保每个细节都了然于胸。
2. **动手实践**：强烈建议用 PyTorch 等框架从零手写一个 Transformer，特别是多头自注意力模块。这会让你对维度变化、Masking 等细节的理解提升一个档次。
3. **精读源码/博客**：选择一个主流模型（如 LLaMA、Qwen），阅读其官方实现或高质量的源码解读博客，理解其相比原始 Transformer 的每一处改进。
4. **形成对比思维**：准备一个表格或思维导图，系统性地比较各种架构（Decoder-only vs Encoder-Decoder）、归一化方法（LN vs BN vs RMSNorm）、位置编码（Absolute vs RoPE）等的优劣和适用场景。
5. **关注前沿**：持续关注顶级会议和头部公司的技术博客，了解 MoE、注意力变体等最新进展。

总之，面试官期待的是一位不仅“知其然”，更能“知其所以然”的候选人。对架构原理的深刻理解，是衡量你是否能在大模型领域进行创新和解决实际问题的核心标准。

## 2. 大模型训练与微调

大模型算法工程师的核心工作内容，也是面试中考察实践能力和工程经验的重点。这部分不仅测试你对训练流程和微调技术的掌握，更能深刻反映出你对数据、算力、算法三者之间复杂权衡的理解，以及将理论落地到实际业务中的能力。

考察的核心可以概括为三个维度：“怎么训”、“怎么调”和“怎么省”。

### 第一维度：怎么训——从零到一的完整流程

这部分考察你对大模型生命周期的宏观理解，从数据准备到模型成型，每一个环节都至关重要。

一般人没有这个经历，对着论文把流程记住应付面试就好了。或者讲讲自己简历上的其他模型训练经验。

#### 1. 完整训练流程（宏观视野）

- **题目特征**：“请系统性地阐述从零开始训练一个大语言模型的完整流程...”
- **考察要点**：
  - **数据准备**：能清晰描述数据收集、高质量清洗（去重、去噪、过滤有害内容）、数据配比（不同来源数据的混合策略）、分词（Tokenization）等关键步骤。这是决定模型能力上限的基石。
  - **预训练（Pre-training）**：理解其目标是让模型学习通用的语言知识和世界知识。熟悉主流的预训练任务，如自回归语言建模（Causal LM，如 GPT）和掩码语言建模（Masked LM，如 BERT）。
  - **后训练（Post-training）/ 对齐（Alignment）**：这是让模型变得“有用”和“安全”的关键。必须能清晰地区分并阐述：
    - **监督微调（SFT）**：使用高质量的“指令-回答”数据对，教模型遵循指令。必须能手写其损失函数（交叉熵损失）。
    - **对齐微调（RLHF/DPO）**：使用人类偏好数据，让模型的输出更符合人类价值观。

#### 2. 训练中的核心概念与挑战（理论深度）

- **Scaling Laws（缩放定律）**：理解模型性能与模型规模、数据量、计算量三者之间的幂律关系，并知道通常增加数据量是提升性能最有效的方式。
- **过拟合与正则化**：能够识别过拟合的迹象（训练集表现好，验证集差），并熟练说出多种解决方案（数据增强、Dropout、权重衰减 L1/L2、早停等）。
- **梯度问题**：解释梯度消失/爆炸的成因（链式法则、激活函数饱和），并掌握对应的解决方案（残差连接、梯度裁剪、合适的权重初始化、选择合适的激活函数如 ReLU）。

### 第二维度：怎么调——高效适配下游任务（How to Fine-tune）

微调是连接通用大模型与特定应用场景的桥梁，考察重点在于对各种微调技术的深刻理解和选型能力。

**微调这块，要记住，围绕着自己的业务场景来讲，不要脱离实际，不要为了微调而微调。**

#### 1. 参数高效微调（PEFT）vs. 全参数微调（Full Fine-tuning）

- **题目特征**：“请比较 LoRA 与全参数微调...”“在什么场景下选择 PEFT？”
- **考察要点**：
  - **全参数微调**：效果上限高，但计算成本、存储成本巨大，且容易导致灾难性遗忘。
  - **PEFT**：核心优势是高效。只训练少量额外参数，大幅降低计算和存储需求，便于多任务部署，且能有效缓解灾难性遗忘。

#### 2. LoRA（Low-Rank Adaptation）（简历出现的太多，实际用的并不多）

- **题目特征**：“请详细解释 LoRA 的原理...”“手写 LoRA 伪代码...”“LoRA 的参数初始化...”
- **考察要点**：
  - **核心思想**：基于“模型权重的变化量是低秩的”这一假设，将大的权重更新矩阵 $\Delta W$ 分解为两个小的低秩矩阵 $B \cdot A$，即 $\Delta W = BA$。训练时冻结原始权重 $W$，只训练 $A$ 和 $B$。
  - **数学原理**：能够推导参数量如何从 $d \times k$ 降低到 $(d+k)\times r$，其中 $r \ll d,k$。
  - **初始化策略（高频细节）**：必须知道 A 矩阵通常采用高斯分布初始化，B 矩阵采用零初始化。其目的是保证在训练开始时，$\Delta W = BA = 0$，使 LoRA 模块对模型的初始输出没有影响，从而保证训练的稳定性。
  - **关键超参（rank, alpha）**：理解 rank（秩）控制了新增参数的数量，是效果与效率的权衡；alpha 是一个缩放因子，用于调节 LoRA 输出的强度。

#### 3. 其他 PEFT 方法（Adapter, Prompt Tuning, P-Tuning）

- **考察要点**：能够简要说出它们与 LoRA 的区别。Adapter 是在 Transformer 层中插入新的小模块；Prompt Tuning 是冻结模型，只学习 soft prompt；P-Tuning 是其改进版，引入了可学习的 prompt encoder。

### 第三维度：怎么省——大规模训练的工程优化

这部分考察你是否具备处理超大模型训练的工程能力，核心是如何在有限的硬件资源上“塞下”并“跑起”大模型。

有工程经验的同学，这部分原理要熟悉，有的公司真考。

#### 1. 分布式训练并行策略（系统视野）

- **题目特征**：“请比较数据并行、模型并行...”
- **考察要点**：
  - **数据并行（Data Parallelism, DP）**：每个 GPU 上有一个完整的模型副本，处理不同批次的数据。简单但显存冗余大。
  - **模型并行（Model Parallelism）**：将模型本身切分到不同 GPU 上。
    - **张量并行（Tensor Parallelism, TP）**：层内并行，将大的矩阵运算（如线性层）切分到多个设备上，通信密集（All-Reduce）。
    - **流水线并行（Pipeline Parallelism, PP）**：层间并行，将模型的不同层放到不同设备上，形成流水线，会产生“气泡”（设备空闲）。
  - **选型策略**：能根据模型大小、硬件条件（卡间带宽）分析如何组合使用这些策略（3D 并行）。

#### 2. 显存优化技术（工程细节）

- **DeepSpeed ZeRO（Zero Redundancy Optimizer）**：极高频考点。必须能清晰区分：
  - **ZeRO-1**：分割优化器状态（Optimizer States）。
  - **ZeRO-2**：在 1 的基础上，再分割梯度（Gradients）。
  - **ZeRO-3**：在 2 的基础上，再分割模型参数（Parameters），即“卸载”（Offload）。
- **混合精度训练（Mixed Precision）**：理解使用 FP16/BF16 进行计算可以加速训练、节省显存，同时使用 FP32 保存关键权重以维持数值稳定性。知道 Loss Scaling 是防止梯度下溢的关键技术。
- **梯度累积（Gradient Accumulation）**：在显存不足以放下大 batch size 时，通过累积多个小 batch 的梯度，模拟一个大 batch 的训练效果。
- **梯度检查点（Gradient Checkpointing/Activation Recomputation）**：通过在前向传播时不保存中间激活值，而在反向传播时重新计算它们，来用计算换取显存。

总结来说，这部分面试要求你不仅是一个懂算法的科学家，更要是一个懂系统、懂工程的实践者。能够清晰地阐述整个训练流程，深入理解微调技术的原理与权衡，并熟练掌握各种资源优化策略，才能证明你具备驾驭大模型训练与微调复杂工程的能力。

## 3. 强化学习与 RLHF

2024 到 2025 年最时髦的词之一——RL。今年简历里要是没有强化学习（特别是 RLHF/DPO），面试大模型岗位时确实会感觉有点跟不上节奏了。这不仅仅是一个技术热点，更是当前大模型从“能说话”进化到“说好话”、“懂分寸”的核心技术路径，即所谓的模型对齐（Alignment）。

面试官通过这部分，重点考察你是否理解为什么需要对齐，以及如何实现对齐的主流技术范式。此外，RL 本身作为一种决策优化框架，与 Agent、RAG 等前沿方向的结合潜力巨大，是展现你技术视野的绝佳机会。

考察可以分为四大板块：“为何对齐”、“经典 RLHF 范式”、“DPO 范式”和“GRPO”。

### 第一板块：为何对齐——SFT 的局限性与 RLHF 的必要性

这是理解所有对齐技术的前提，是 “Why” 的问题。

- **题目特征**：“为什么在 SFT 之后还需要进行 RLHF？”“只用 SFT 有什么局限性？”
- **考察要点**：
  - **SFT（监督微调）的目标**：SFT 通过模仿高质量的“指令-回答”数据，教模型“学会做什么”，即具备遵循指令的基本能力。其损失函数是交叉熵损失，本质上是最大似然估计（MLE）。
  - **SFT 的局限性**：
    1. **标注成本高**：很难穷尽所有场景并提供唯一的“正确答案”，高质量标注数据昂贵且稀缺。
    2. **目标不完全一致**：模型的 MLE 目标和人类偏好的复杂目标（如安全性、有用性、无害性）之间存在差距。SFT 只能学习“平均正确”，而无法学习细致的偏好。
    3. **泛化能力有限**：对于未见过的指令或模糊指令，SFT 模型可能表现不佳或产生不安全的回答。
  - **RLHF 的价值**：RLHF 通过学习人类的偏好，而不是模仿单一的正确答案，来教模型“应该怎么做”，使其输出更符合人类的价值观和期望。它弥补了 SFT 在对齐目标上的不足，是实现 3H（Helpful, Honest, Harmless）目标的关键一步。

SFT（监督微调）之后进行 RLHF（基于人类反馈的强化学习）的目的是为了弥补 SFT 的局限性，使模型更好地理解人类偏好，并生成更符合人类期望的、更安全、更有帮助的回答。

#### 补充介绍：SFT 的局限性

1. **无法捕捉细微的人类偏好**：SFT 的数据通常是人工标注的示范数据，这些数据虽然质量较高，但很难穷尽所有可能的优质回答，也难以捕捉人类在不同情境下对回答的细微偏好。例如，两个回答可能都“正确”，但一个可能更简洁，一个可能更详细，人类可能更偏好其中一个。SFT 模型很难学会这种细微的区分。
2. **泛化能力有限**：SFT 模型在训练数据之外的领域或面对新颖问题时，可能无法生成同样高质量的回答。它倾向于模仿训练数据的风格和内容，如果训练数据没有覆盖到某些方面，模型就可能表现不佳。
3. **容易产生幻觉或不真实信息**：SFT 模型虽然能生成流畅的文本，但并不总是能保证信息的准确性或真实性。它可能会“编造”事实，或者根据训练数据中的模式生成看似合理但不正确的信息。
4. **难以处理开放性问题和复杂指令**：对于开放性问题或需要多步骤推理的复杂指令，SFT 模型可能难以生成完全符合用户意图的回答。它可能只会给出其中一部分，或者理解错指令的重点。
5. **无法有效纠正有害或有偏见的内容**：如果 SFT 的训练数据中包含有害、有偏见或不安全的内容，模型可能会学习并复制这些不良特性。仅仅通过 SFT 很难有效地过滤或纠正这些问题。
6. **缺乏对“有用性”和“无害性”的深入理解**：SFT 只是让模型学习如何生成“像人类写的那样”的文本，但它并不真正理解什么是“有用”或“无害”。它可能生成技术上正确但缺乏实用价值，或者某些方面具有潜在危害的回答。

#### RLHF 如何弥补这些局限性

RLHF 通过引入人类反馈作为奖励信号，让模型能够：

- **更好地理解人类偏好**：人类对模型生成回答的排名或评分，直接告诉模型哪些回答更好，哪些更差。这使得模型能够学习到 SFT 数据中难以体现的细微偏好。
- **提高泛化能力**：通过对不同类型回答进行评估，RLHF 可以帮助模型在更广泛的任务和情境中生成高质量的回答。
- **减少幻觉和不真实信息**：当人类对模型生成的不准确或不真实信息给出低评价时，模型会学习避免生成这类内容。
- **优化开放性问题和复杂指令的回答**：人类反馈可以指导模型生成更全面、更准确地遵循复杂指令的回答。
- **有效纠正有害或有偏见的内容**：RLHF 是一个强大的机制，可以让人类明确指出并惩罚模型生成的有害、有偏见或不安全内容，从而显著提高模型的安全性。
- **学习“有用性”和“无害性”的真正含义**：通过对回答的有用性、无害性、真实性和帮助性进行排名，RLHF 使模型能够内化这些价值观，并努力生成符合这些标准的回答。

总结来说，**SFT 是让模型学会“说什么”，而 RLHF 是让模型学会“说什么会更好”。RLHF 让模型从一个模仿者变成一个更理解人类意图、更可靠、更安全的助手。**

可以把 SFT 和 RLHF 的区别想象成训练一个做蛋糕的机器人：

- **SFT 阶段**：我们给机器人看大量优秀蛋糕图片和制作步骤（高质量示范数据）。机器人学会了如何把面粉、糖、鸡蛋等混合，然后烘烤，看起来像个蛋糕。它能做出一个“形式上正确”的蛋糕，但可能味道一般，或者有时候会把盐当糖放。
- **RLHF 阶段**：我们请很多人品尝机器人做出来的各种蛋糕（人类反馈）。他们会说哪个蛋糕更好吃，哪个太甜，哪个太咸。机器人根据这些反馈来调整自己的配方和制作方式。通过这个过程，机器人不仅能做出一个“形式正确”的蛋糕，还能做出一个“真正美味”的蛋糕，并且学会避免犯错，例如不再把盐当糖。

这就是为什么在 SFT 之后还需要进行 RLHF：SFT 提供了基础能力，而 RLHF 则将这种能力精炼，使其更符合人类的真实期望和偏好。

### 第二板块：经典范式——RLHF 与 PPO

这是理解对齐技术的经典路径，考察对整个三阶段流程和核心算法的掌握。

#### 1. RLHF 三阶段流程（宏观理解）

- **题目特征**：“请详细阐述 RLHF 的技术流程...”
- **考察要点**：必须能清晰地讲出三个阶段：
  1. **阶段一：监督微调（SFT）**：获取一个有基本指令遵循能力的初始策略模型（Actor）。
  2. **阶段二：训练奖励模型（Reward Model, RM）**：收集人类对不同模型输出的偏好数据（如 A > B），训练一个 RM 来模拟人类的打分器。
  3. **阶段三：强化学习优化（PPO）**：使用 RM 作为环境的奖励函数，冻结 RM，用 PPO 算法微调 SFT 模型，使其在最大化 RM 奖励的同时，不过于偏离原始 SFT 模型（通过 KL 散度惩罚项）。

#### 2. PPO（Proximal Policy Optimization）算法（核心算法）

- **题目特征**：“请详细解释 PPO 的原理...”“写出 PPO 的损失函数...”
- **考察要点**：
  - **核心思想**：PPO 是一种 On-policy 的 Actor-Critic 算法，其核心是通过 Clipped Surrogate Objective（裁剪代理目标）来限制每次策略更新的步长，从而保证训练的稳定性。
  - **损失函数**：能够写出并解释 PPO-Clip 的目标函数，理解其中重要性采样比率 $r(\theta)$、优势函数 A 和裁剪（clip）的作用。
  - **KL 散度惩罚**：在 RLHF 中，PPO 的目标函数通常还会加入一个 KL 散度项，例如：

$$
-\beta \cdot KL(\pi_{\theta}\ \|\ \pi_{SFT})
$$

用于防止模型为了追求高奖励而产生奖励黑客（Reward Hacking）现象。

### 第三板块：新锐范式——DPO

这是当前更流行、更简洁的对齐方法，是 RLHF 的有力竞争者和替代品，面试必考。

- **题目特征**：“请解释 DPO 的原理...”“对比 DPO 和 PPO...”
- **考察要点**：
  - **核心动机**：DPO 巧妙地发现，RLHF 中最大化奖励的目标函数可以被直接用偏好数据来优化，从而绕过了显式训练奖励模型和复杂的强化学习过程。
  - **原理**：DPO 将偏好概率（基于 Bradley-Terry 模型）与策略概率建立起一个解析关系，推导出了一个可以直接在偏好数据上优化的分类损失函数。
  - **DPO vs. PPO（RLHF）**：
    - **优势**：更简单、更稳定。省去了训练奖励模型和 PPO 在线采样这两个复杂且不稳定的环节。
    - **劣势**：效果上限可能略低于精心调优的 RLHF。对偏好数据的质量和分布更敏感。
    - **选型**：DPO 是当前许多开源模型对齐的高性价比首选。

### 第四板块：前沿探索——GRPO

这部分考察你是否关注更细分、更前沿的强化学习应用，特别是在解决复杂推理问题上的探索。

- **题目特征**：“请解释 GRPO 的原理...”“对比 GRPO 与 PPO/DPO...”
- **考察要点**：
  - **核心动机**：在数学推理等任务中，答案往往是非对即错的二元分布，这会导致奖励信号非常稀疏（sparse）。当一个批次内所有样本都正确或都错误时，PPO/DPO 的梯度会消失，学习效率极低。GRPO 就是为了解决这个问题。
  - **原理**：
    1. **分组（Grouping）**：GRPO 将一个批次内的样本根据其最终结果（如答案是否正确）分成不同的组（例如，正确组和错误组）。
    2. **组间相对优化（Group Relative Optimization）**：它的优化目标不再是简单地最大化绝对奖励，而是拉大正确组和错误组之间的期望奖励差距。即使所有样本都错了，它依然可以通过比较“错得离谱”和“错得接近”的样本来产生有效的学习信号。
    3. **损失函数**：GRPO 的损失函数包含组间相对优势项，确保模型学习去偏爱正确组的生成路径。
  - **GRPO vs. PPO/DPO**：
    - **优势**：在奖励稀疏和二元反馈（对/错）的场景下，GRPO 能够提供更稠密、有效的学习信号，显著提升学习效率和最终效果。特别适合于数学推理、代码生成等有明确正确答案的任务。
    - **适用场景**：当任务反馈主要是二元的，且容易出现“全对”或“全错”的批次时，GRPO 是比 PPO/DPO 更优的选择。

总结而言，这部分内容要求你不仅要懂 RL 的基本概念，更要能站在大模型对齐的视角，清晰地阐述 SFT、RLHF（PPO）、DPO、GRPO 这几者之间的演进关系、技术细节和实践权衡。理解它们各自解决了什么问题，以及带来了什么新的挑战，是衡量你在此领域深度和广度的关键。

## 4. RAG 与 Agent

一般同学简历上的项目，RAG 和 Agent 大概率有一个。所以这部分被问的频率也是非常非常高的。

如果说模型本身是“大脑”，那么 RAG（检索增强生成）和 Agent 就是为这个大脑装上了“外部知识库”和“手脚”，使其能够查询最新信息、与外部世界交互并完成复杂任务。这部分是当前大模型应用落地的绝对核心，考察的是你将大模型从一个“聊天玩具”转变为一个“能干活的系统”的综合能力。

面试官通过这部分，重点考察你的系统设计思维、工程实践能力和对前沿应用范式的理解。

### 第一板块：RAG——让模型言之有据

RAG 是解决大模型幻觉、知识陈旧两大痛点的核心技术。考察点从基本流程到高级优化，层层递进。

#### 1. 核心流程（必考）

- **题目特征**：“请详细描述 RAG 的技术流程...”
- **考察要点**：必须能清晰、分步地描述完整的 RAG 生命周期。

**离线阶段（Ingestion/Indexing）：**

1. **文档加载（Load）**：从各种数据源（PDF、HTML、DB）加载原始文档。
2. **文本切分（Split/Chunking）**：将长文档切分成小块（chunks）。这是一个关键优化点，需要讨论不同策略（按大小、按章节、语义切分）及其对检索效果的影响。
3. **向量化（Embed）**：使用 Embedding 模型（如 BERT、Sentence-BERT、BGE）将文本块转换为向量。
4. **索引（Index）**：将文本块和其对应的向量存入向量数据库（如 FAISS、Milvus），构建高效的 ANN 索引。

**在线阶段（Inference）：**

1. **查询处理（Query Processing）**：用户输入查询。
2. **检索（Retrieve）**：将查询向量化，在向量数据库中检索出 Top-K 个最相似的文本块。
3. **增强/构建上下文（Augment）**：将检索到的文本块与原始查询一起，构建成一个精心设计的 Prompt。
4. **生成（Generate）**：将构建好的 Prompt 喂给大模型（LLM），生成最终答案。

#### 2. 优化策略（区分度题）

- **题目特征**：“RAG 有哪些优化手段？”“如何提升检索精度？”
- **考察要点**：这部分是展现你实践经验和技术深度的关键。需要能系统性地从各个环节阐述优化策略。

**检索器优化（核心）：**

- **混合检索（Hybrid Search）**：结合稀疏检索（如 BM25，关注关键词匹配）和密集检索（向量检索，关注语义相似度），优势互补。
- **两阶段检索（Recall + Rerank）**：第一阶段用高效的方法（如向量召回）快速召回大量相关文档（保证召回率），第二阶段用更强大但更慢的模型（如 Cross-Encoder）对召回结果进行重排序（保证精确率）。
- **查询改写/扩展（Query Rewriting/Expansion）**：使用 LLM 对用户的原始查询进行改写或扩展，生成更适合检索的查询语句，尤其在多轮对话中至关重要。

**索引与分块优化：**

- **精细化分块（Chunking Strategy）**：除了简单的固定大小切分，还应考虑语义边界、句子边界，甚至可以采用“小块检索，大块喂 LLM”的策略。
- **元数据与图结构**：在索引中加入元数据（如来源、时间戳），或者使用 GraphRAG，利用知识图谱的结构化信息来指导检索，提升关联性。

**生成器优化：**

- **上下文构建（Prompt Engineering）**：如何组织检索到的内容，如何设计指令，直接影响生成质量。
- **后处理与过滤**：对 LLM 的输出进行校验，检查其是否忠于检索内容（事实一致性），并过滤掉不合规的输出。

#### 3. 评估体系（Evaluation）

- **题目特征**：“如何评估 RAG 系统？”
- **考察要点**：需要从两个维度进行评估：
  - **检索模块评估**：Hit Rate（命中率）、MRR（平均倒数排名）、NDCG 等。
  - **生成模块评估**：Answer Relevance（答案相关性）、Faithfulness/Groundedness（事实一致性，即答案是否基于检索内容）、Answer Correctness（答案正确性）。通常需要借助 LLM-as-a-Judge 或人工评估。

### 第二板块：Agent——让模型自主行动

Agent 是 RAG 的自然延伸，它不再是被动地回答问题，而是能主动规划、执行、反思的智能体。

#### 1. 核心架构（The Anatomy - 必考）

- **题目特征**：“Agent 的核心组件是什么？”“Agent 的工作原理...”
- **考察要点**：Agent 的核心是一个决策循环（Reasoning Loop）。必须能清晰地描述其核心组件：
  - **规划模块（Planning）**：大模型的“大脑”，负责理解用户意图、将复杂任务拆解成可执行的子任务，并制定行动计划。常使用 ReAct（Reason + Act）或 Chain-of-Thought（CoT）等范式。
  - **工具调用模块（Tool Use）**：模型的“手脚”，使其能够与外部世界交互。核心技术是 Function Calling，LLM 能根据规划，选择合适的工具（API、数据库查询、代码执行器），并生成符合规范的调用参数。
  - **记忆模块（Memory）**：赋予 Agent 短期和长期记忆。短期记忆用于处理多轮对话的上下文；长期记忆（通常通过 RAG 实现）使其能存储和检索过去的经验和知识。
  - **反思/自校准模块（Reflection）**：Agent 在执行任务后，能够评估自己的行为结果，总结经验，修正错误，并在后续规划中进行优化。

#### 2. 系统设计与协作

- **题目特征**：“如何设计一个 Agent 系统？”“单 Agent vs. 多 Agent...”
- **考察要点**：
  - **单 Agent**：适合处理流程相对固定、工具集明确的任务。
  - **多 Agent 系统（Multi-Agent System）**：适合处理极其复杂的、需要不同角色专长协作的任务（如软件开发 Agent 团队）。你需要讨论其优势（专业化、并行化）和挑战（通信成本、任务分配、协作一致性）。
  - **框架选型**：了解并能比较主流的 Agent 框架，如 LangChain（组件化）、LangGraph（专为多 Agent 协作设计的循环图结构）。

总结而言，RAG 与 Agent 的面试考察，已经从简单的“调包”层面，深入到系统设计、性能优化、鲁棒性保障和前沿框架应用的层面。面试官希望找到的，是能够深刻理解 RAG 和 Agent 背后的原理，并能根据具体业务场景，权衡各种技术方案，设计、搭建并持续优化一个稳定、高效、可靠的智能应用系统的综合型人才。

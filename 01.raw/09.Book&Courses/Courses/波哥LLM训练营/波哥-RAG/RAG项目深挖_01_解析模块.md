# 【RAG项目深挖-01】解析模块

## 1. PDF解析的整体架构

### 1.1 为什么选择Deepdoc？

不要只说“用了 Deepdoc”，要说为什么：

**更好的回答：**

> 我们对比了多个方案：
>
> - **PyPDF2/PDFMiner**：只能提取文本，无法处理复杂布局
> - **Unstructured**：通用性强但保险文档的表格识别率只有75%左右
> - **Deepdoc**：基于 LayoutLMv3 的布局分析 + PaddleOCR，对中文文档友好，表格识别率能达到88%
>
> 最终选择 Deepdoc 作为 base，但针对保险场景做了 **3个关键优化**（下面展开）

### 1.2 PDF解析的pipeline细节

```text
输入PDF → 版面分析 → 元素分类 → 针对性解析 → 结构化输出
```

**深挖每个环节：**

#### Step 1: 版面分析（Layout Analysis）

- **模型**：LayoutLMv3（DocLayout）微调版
- **识别类别**：标题、正文、表格、图片、页眉页脚、印章、水印（7类）
- **输出**：每个元素的 bbox 坐标 + 类别 + 置信度
- **优化点**：保险合同中印章和签名经常和文字重叠，我增加了一个**遮挡检测模块**：
  - 如果某个 text 块的 OCR 置信度 < 0.6，且与印章区域 IoU > 0.3，会先去除印章再 OCR
  - 用 **color histogram + connected component analysis** 分离印章和文本层

**可能的追问：**

- Q: LayoutLMv3 的原理是什么？
  - A: 多模态 Transformer，同时建模**文本、视觉、位置**三个特征。通过 Mask Language Modeling + Masked Image Modeling 预训练

#### Step 2: 表格解析（关键优化点）

**面试官想听：**

**问题分析：**

> 保险文档中有3类表格：
>
> 1. **有边框表格**（80%）：Deepdoc 默认可以处理
> 2. **无边框表格**（15%）：通过空格对齐的文本，Deepdoc 识别率只有62%
> 3. **半结构化表格**（5%）：表头有边框，内容无边框，识别率只有55%

**我的优化方案：**

| 表格类型 | 原方案 | 优化后方案 | 准确率提升 |
| --- | --- | --- | --- |
| 有边框 | Deepdoc内置 | 无需优化 | 95% → 95% |
| 无边框 | Deepdoc内置 | **调用MinerU 2.5** | 62% → 97% |
| 半结构化 | Deepdoc内置 | **规则+ML混合** | 55% → 92% |

**无边框表格的处理细节：**

1. **先用启发式规则判断**：检测文本块是否有**高度对齐**（纵向间距方差 < 5px）
2. **如果是无边框表格**：
   - 原方案用 Deepdoc → 提取出来的是纯文本，列对齐全乱
   - 新方案：调用 **MinerU 2.5 的 TabRec 模型**（专门针对无边框表格训练）
   - 输出：HTML 结构化表格
3. **为什么不全用 MinerU？**
   - MinerU 推理速度慢（单页300ms vs Deepdoc 80ms）
   - 所以做了**分类器前置**，只对无边框表格调用 MinerU

**可能的追问：**

- Q: MinerU 2.5 的原理？
  - A: 基于 Table Transformer 架构，用 **row/column detection** 识别隐式表格结构，然后用 **cell matching** 重建单元格关系

#### Step 3: 扫描件/模糊图片处理

**加强版：**

**问题场景：**

> 我们有30%的文档是**扫描件**：客户合同、发票、手写单据
>
> - 水印干扰：合同章会有“仅供XX使用”水印，和文字重叠
> - 模糊不清：扫描分辨率低（200dpi 以下），OCR识别率只有73%

**我的优化pipeline：**

```python
def preprocess_scanned_image(img):
    # Step 1: 模糊检测（拉普拉斯方差）
    blur_score = cv2.Laplacian(img, cv2.CV_64F).var()

    if blur_score > 100:  # 清晰图片
        return img
    elif 50 < blur_score <= 100:  # 中度模糊
        # 去噪 → 锐化 → 超分辨率 → 对比度增强
        img = cv2.fastNlMeansDenoising(img)
        img = cv2.filter2D(img, -1, sharpen_kernel)
        img = sr_model.predict(img)  # Real-ESRGAN
        img = cv2.convertScaleAbs(img, alpha=1.5, beta=10)
    else:  # 严重模糊（blur_score ≤ 50）
        # 直接用 MinerU 2.5（它内置了更强的预处理）
        return minerU_process(img)

    return img
```

**水印去除的技术细节：**

1. **问题**：传统方法（高斯滤波/中值滤波）会把文字也模糊掉
2. **我的方案**：
   - 用 **ResNet 提取特征** → 区分水印和文本的纹理差异
   - 训练数据：人工标注200张带水印的合同（标注像素级 mask）
   - 方法：**U-Net 语义分割**，输出水印 mask → 用 **inpainting** 填充水印区域
3. **优化**：灰度方差分析作为先验规则，减少计算量：
   - 水印区域通常灰度方差 < 30（接近纯色）
   - 文字区域灰度方差 > 80（边缘明显）

**量化效果：**

- OCR准确率：73% → 94%（提升21个百分点）
- 处理速度：单页180ms（可接受）

## 2. 关键技术深挖（面试官必问）

### 2.1 如何评估解析质量？

不要只说“准确率99%”，要说怎么算的：

| 指标 | 定义 | 我们的做法 |
| --- | --- | --- |
| 字符准确率 | 正确字符数/总字符数 | 人工标注500页测试集，逐字对比 |
| 表格结构准确率 | 行列关系正确的单元格占比 | 用 table-transformer-metric 计算 IoU |
| 语义完整性 | 是否有丢失关键信息 | 用 LLM 做 QA 测试：能否从解析结果回答问题 |

**例子：**

> 比如一份保险合同的“免责条款”表格，如果行列对应错了，会导致 RAG 检索时把不同条款混淆，这种错误比丢失几个字严重得多。所以我们设计了**加权准确率**：关键字段（金额、日期、责任范围）权重 ×3

### 2.2 解析失败的case怎么处理？

**体现你的工程能力：**

1. **日志监控**：记录每个文件的解析时长、OCR置信度、异常类型
2. **异常降级**：
   - 如果 MinerU 调用超时（>5s），降级为纯 OCR
   - 如果某页解析失败，跳过该页并标记，不影响其他页
3. **人工审核队列**：
   - 置信度 < 0.8 的结果进入审核队列
   - 每周 review 50 个 badcase，反哺模型优化

### 2.3 如何处理PDF中的非文本元素？

**细说图片/表格：**

- **图片**：
  - 如果是流程图/示意图：用 **GPT-5** 生成描述，作为该 chunk 的 metadata
  - 如果是数据图表：用 **chart-to-text 模型（Deplot）** 提取数据
- **公式**：用 **LaTeX-OCR** 识别数学公式，转为文本表达

### 2.4 Metadata增强

#### 元数据增强

**每个 chunk 不只是文本，还要带上丰富的 metadata**

```python
{
    "content": "保险金额为50万元...",
    "metadata": {
        "doc_id": "contract_123",
        "page": 5,
        "section": "第二章 保险条款",
        "doc_type": "保险合同",
        "create_date": "2024-01-15",
        "entities": ["50万元", "意外伤害"],
        "keywords": ["保险", "责任"],
        "confidence": 0.96,  # 解析质量分数
        "source_bbox": [100, 200, 500, 300]  # 原始位置
    }
}
```

**用途：**

- 检索时可以过滤（只搜合同类文档）
- 按置信度加权排序
- 追溯到原文位置

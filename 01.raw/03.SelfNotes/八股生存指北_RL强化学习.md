## For future Claude

这是一份面向面试和快速复习的强化学习笔记，重点不是推导所有算法细节，而是建立一条主线：RL 解决“如何从反馈中学习决策”，RLHF 把人类偏好变成奖励信号，PPO 用受约束的策略更新稳定训练，DPO 直接从偏好对中优化语言模型，GRPO 则用组内相对优势降低 PPO 在大模型训练中的资源开销。

# 八股生存指北：RL 强化学习

强化学习这条线，最容易被背成一堆名词：RL、RLHF、PPO、DPO、GRPO。更好的记法是把它们放到同一个问题里：

> 模型不是只要“知道标准答案”，而是要在一系列选择中，逐渐学会什么行为更值得重复。

监督学习像“老师给标准答案”；强化学习像“自己做事，然后根据结果被奖励或惩罚”。大模型后训练里的 RLHF、PPO、DPO、GRPO，本质上都是围绕这个问题展开：如何让模型的输出更符合人类偏好、任务目标或可验证奖励。

## RL：强化学习是什么？

强化学习（Reinforcement Learning, RL）是一种让智能体（Agent）在环境（Environment）中通过 **试错 + 奖励反馈** 学习决策的方法。

它不像监督学习那样直接给出标准答案，而是让模型不断尝试动作，根据结果获得奖励或惩罚，逐渐学会：

> 在什么状态下，采取什么动作，才能获得更大的长期收益？

| 核心要素 | 含义 | 例子 |
| --- | --- | --- |
| Agent 智能体 | 做决策、学习策略的主体 | 玩游戏的 AI、机器人、语言模型 |
| Environment 环境 | 智能体互动的外部世界 | 游戏界面、道路、对话任务 |
| State 状态 | 当前处境或上下文 | 蛇的位置、车辆速度、当前 prompt |
| Action 动作 | 智能体可以做出的选择 | 向左、刹车、生成下一个 token |
| Reward 奖励 | 环境返回的反馈信号 | 得分 +1、撞墙 -10、回答被偏好 |
| Policy 策略 | 状态到动作的选择规则 | 看到食物在右侧，就更倾向向右走 |

![RL 核心要素](https://img.vectorpeak.cn/obsidian/2026/05-06/20260518132217180.png?imageSlim)

### 用贪吃蛇理解 RL

假设要训练一个玩贪吃蛇的 AI：

- **Agent**：控制贪吃蛇的 AI 程序。
- **Environment**：贪吃蛇游戏界面。
- **State**：当前画面里的全部信息，比如蛇头位置、食物位置、身体位置、墙的位置。
- **Action**：AI 可执行的操作，比如向上、向下、向左、向右。
- **Reward**：环境给出的反馈，比如吃到食物 +10，撞墙或撞到自己 -10，普通移动 -0.1。

一开始，AI 可能像无头苍蝇一样乱走，很快撞死。但经过大量试错，它会逐渐学到：

- 当食物在右上方时，向右或向上走更可能带来长期收益。
- 当左边被身体堵住时，向左走会立刻死亡，应该避免。
- 如果长期原地绕圈，虽然不立刻死亡，但也拿不到高奖励。

最终，AI 学到的不是某一个固定动作，而是一套“在不同状态下如何选择动作”的策略。

## RL 的核心目标

强化学习最终要做的是更新策略：让高价值动作更容易被选中，让低价值动作更少被选中。

如果某个动作 $a$ 在状态 $s$ 下带来了更高回报，就提高它被选择的概率：

$$
\pi_{\text{new}}(a \mid s) > \pi_{\text{old}}(a \mid s)
$$

如果某个动作带来了较低回报或惩罚，就降低它被选择的概率：

$$
\pi_{\text{new}}(a \mid s) < \pi_{\text{old}}(a \mid s)
$$

更一般地，RL 的优化目标可以写成：

$$
\theta^* = \arg\max_{\theta} \mathbb{E}_{\pi_\theta}\left[\sum_{t=0}^{T}\gamma^t r_t\right]
$$

| 符号 | 含义 |
| --- | --- |
| $\theta$ | 策略或模型参数，比如神经网络权重 |
| $\theta^*$ | 训练后希望得到的最优参数 |
| $\pi_\theta$ | 由参数 $\theta$ 控制的策略 |
| $\mathbb{E}_{\pi_\theta}$ | 在当前策略下采样行动后得到的期望表现 |
| $r_t$ | 第 $t$ 步获得的奖励 |
| $\gamma$ | 折扣因子，通常 $0 \le \gamma \le 1$ |
| $\gamma^t r_t$ | 越远的未来奖励，权重通常越小 |

这条公式的直觉是：训练模型参数 $\theta$，让策略 $\pi_\theta$ 在长期平均意义下拿到尽可能高的累计奖励。

## RLHF：把人类偏好变成奖励

RLHF（Reinforcement Learning from Human Feedback）是“基于人类反馈的强化学习”。它的作用是把人类对输出质量的偏好，转化为模型可以学习的奖励信号。

大模型并不天然知道什么叫“回答得好”。“好”往往很主观，也很难写成死规则。例如，不能简单规定“每个回答必须包含一个比喻，语气提高 20%”。但人类可以更容易地做比较：

> 这个回答比那个回答更好。

RLHF 的关键，就是把这种人类直觉转换成一个可计算的奖励模型，然后再用强化学习优化语言模型。

![RLHF 流程](https://img.vectorpeak.cn/obsidian/2026/05-06/20260518145213236.png?imageSlim)

### RLHF 的典型流程

1. **监督微调（SFT）**

   先用高质量指令数据训练一个基础助手模型，让它学会基本的问答格式、指令遵循和表达方式。

2. **训练奖励模型（Reward Model）**

   给同一个 prompt 准备多个模型回答，让人类标注者比较哪一个更好。奖励模型学习这种偏好排序，输出一个“这个回答有多好”的分数。

3. **用强化学习优化策略**

   语言模型生成回答，奖励模型打分，再用 PPO 等 RL 算法更新语言模型，让它更倾向生成高分回答。

RLHF 的本质不是“人类直接教模型每一步怎么做”，而是先训练一个近似人类偏好的打分器，再让模型围绕这个打分器优化自己的输出策略。

## PPO：稳定地更新策略

PPO（Proximal Policy Optimization，近端策略优化）是强化学习里常用的策略优化算法。它由 OpenAI 在 2017 年提出，核心思想是：

> 允许模型改进策略，但每次不要改得太猛。

普通策略梯度方法容易出现一个问题：如果某次更新步子太大，模型可能从一个还不错的策略直接跳到一个更差的策略。PPO 的价值就在于给策略更新加上“安全带”，限制新旧策略之间的差异。

### 用学做糖醋排骨理解 PPO

假设一个厨师正在学习做糖醋排骨。

如果使用粗暴试错：

1. 第一次放 5 勺醋，太酸，得分很低。
2. 第二次直接改成 0 勺醋，完全不像糖醋排骨，还是很差。

问题在于策略变化太剧烈：从“醋太多”直接跳到“完全没醋”，每次都像坐过山车，学习很不稳定。

PPO 的做法更像稳健调整：

1. 先把 5 勺醋作为当前策略基准。
2. 下一次只允许小幅修改，比如试 4.5 勺或 4 勺。
3. 如果 4.5 勺得分更高，就继续沿这个方向小步调整。
4. 如果 4 勺效果变差，就不要过度采纳这个改动。

PPO 的核心不是“不探索”，而是“探索要受约束”。它希望策略持续变好，但避免一次更新把模型带崩。

### PPO 的核心公式

PPO 常见的 clipped objective 可以写成：

$$
L^{\text{CLIP}}(\theta) =
\mathbb{E}_t\left[
\min\left(
r_t(\theta)\hat{A}_t,
\text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t
\right)
\right]
$$

其中：

$$
r_t(\theta)=\frac{\pi_\theta(a_t\mid s_t)}{\pi_{\theta_{\text{old}}}(a_t\mid s_t)}
$$

| 符号 | 含义 |
| --- | --- |
| $r_t(\theta)$ | 新策略与旧策略选择同一动作的概率比 |
| $\hat{A}_t$ | 优势函数，表示这个动作比平均水平好多少 |
| $\epsilon$ | 裁剪阈值，用来限制更新幅度 |
| $\text{clip}$ | 把概率比限制在 $[1-\epsilon, 1+\epsilon]$ 之间 |

直觉上，如果一个动作明显比平均水平好，模型应该提高它的概率；但如果提高得太猛，PPO 会把收益裁掉，阻止模型过度更新。

## DPO：直接从偏好对中学习

DPO（Direct Preference Optimization，直接偏好优化）可以看成对 RLHF 流程的一种简化。

传统 RLHF 通常需要三步：先 SFT，再训练奖励模型，最后用 PPO 做强化学习。DPO 认为这条路太绕，于是直接从“好回答 vs 坏回答”的偏好对中优化语言模型。

它跳过了显式奖励模型，也不需要再用 PPO 采样训练。它直接告诉模型：

> 对同一个问题，优选回答应该比劣选回答更容易被生成。

### 用甜品师理解 DPO

RLHF 像是先培养一个“甜品鉴定官”：

1. 你先教 AI 做甜品。
2. 再让人类比较多个甜品，训练一个甜品鉴定官。
3. 最后让 AI 不断做甜品，由鉴定官打分，AI 根据分数调整。

DPO 则更直接：

1. 对同一道题，给模型一份优选答案和一份劣选答案。
2. 直接训练模型提高优选答案的概率，降低劣选答案的概率。
3. 不再单独训练奖励模型，也不再跑一轮复杂的 RL。

DPO 的妙处是把“奖励建模 + 强化学习优化”合并成一个更简单的分类式目标。它仍然利用人类偏好，但工程上通常更简单、更稳定。

### DPO 的核心目标

DPO 的常见损失函数可以写成：

$$
\mathcal{L}_{\text{DPO}}(\pi_\theta;\pi_{\text{ref}})
=
-\mathbb{E}_{(x,y_w,y_l)}
\left[
\log \sigma
\left(
\beta
\log \frac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)}
-
\beta
\log \frac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}
\right)
\right]
$$

| 符号 | 含义 |
| --- | --- |
| $x$ | 输入 prompt |
| $y_w$ | preferred / chosen answer，优选回答 |
| $y_l$ | rejected answer，劣选回答 |
| $\pi_\theta$ | 当前训练中的模型 |
| $\pi_{\text{ref}}$ | 参考模型，通常是 SFT 模型 |
| $\beta$ | 控制模型偏离参考模型的强度 |

直觉上，DPO 希望当前模型相对于参考模型，更偏向优选答案，同时更远离劣选答案。

## GRPO：用组内比较替代价值模型

GRPO（Group Relative Policy Optimization，组相对策略优化）是一种面向大语言模型 RL 微调的算法，可以理解为 PPO 的一个变体。

PPO 通常需要一个 critic / value model 来估计某个状态的基准价值。但在大模型训练中，额外维护一个价值模型会增加显存、算力和训练复杂度。GRPO 的思路是：

> 对同一个问题一次生成一组回答，用组内平均表现作为基准，计算每个回答的相对优势。

也就是说，GRPO 不再问“这个回答的绝对分数是多少”，而是问：

> 在同一组回答里，这个回答比平均水平好多少？

### 用小班教学理解 GRPO

假设要训练一个 AI 厨师做西红柿炒鸡蛋。

传统 PPO 更像一对一评分：

- AI 做一盘菜。
- 老师尝一口，给 60 分。
- AI 根据这个分数调整。

GRPO 更像小班比较：

1. 对同一道菜，AI 一次做出 8 个版本。
2. 老师把 8 个版本放在一起比较。
3. 第 3 盘明显最好，第 5 盘明显最差，其余一般。
4. AI 学到：第 3 盘里的做法要增强，第 5 盘里的做法要抑制。

这种组内比较能提供更稳定的相对信号，也省掉了单独训练 value model 的开销。

### GRPO 的核心直觉

对同一个问题 $q$，模型生成一组回答：

$$
\{o_1, o_2, \dots, o_G\}
$$

每个回答得到一个奖励：

$$
\{r_1, r_2, \dots, r_G\}
$$

GRPO 用组内奖励均值和标准差来估计相对优势：

$$
\hat{A}_i = \frac{r_i - \text{mean}(\{r_1,\dots,r_G\})}{\text{std}(\{r_1,\dots,r_G\})}
$$

如果某个回答比组内平均水平好，它的优势 $\hat{A}_i$ 为正；如果比平均水平差，优势为负。模型随后增加高优势回答的生成概率，降低低优势回答的生成概率。

GRPO 的关键价值是：在不额外训练 critic/value model 的情况下，仍然可以得到可用的优势估计，因此更适合资源敏感的大模型后训练。

## 一句话区分 RLHF、PPO、DPO、GRPO

| 名词 | 解决的问题 | 一句话记法 |
| --- | --- | --- |
| RL | 如何从奖励中学习决策 | 试错后，增加好动作概率，降低坏动作概率 |
| RLHF | 如何把人类偏好用于训练 | 先把人类偏好训练成奖励模型，再优化语言模型 |
| PPO | 如何稳定地做策略更新 | 每次只允许策略小步改进，避免更新过猛 |
| DPO | 如何简化 RLHF | 跳过奖励模型和 PPO，直接从偏好对中学习 |
| GRPO | 如何降低大模型 RL 的训练开销 | 用同题多回答的组内比较估计优势，省掉 value model |

## 面试时可以这样回答

如果面试官问“RLHF、PPO、DPO、GRPO 的关系是什么”，可以按这条线回答：

> RL 是从奖励中学习策略的总框架。RLHF 是把人类偏好引入大模型后训练的一套流程，通常先训练奖励模型，再用 PPO 优化语言模型。PPO 的作用是限制策略更新幅度，让强化学习过程更稳定。DPO 则把偏好学习改写成一个直接优化目标，不再显式训练奖励模型，也不需要跑 PPO。GRPO 是 PPO 的一种变体，它通过同一 prompt 下多回答的组内比较估计相对优势，减少对额外 value model 的依赖，常用于大模型推理能力的 RL 微调。

更短的记忆方式是：

> RL 是原则，RLHF 是流程，PPO 是稳定更新工具，DPO 是偏好优化捷径，GRPO 是面向大模型的轻量 PPO 变体。

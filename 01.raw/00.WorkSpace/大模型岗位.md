# 大模型岗位介绍

大模型岗位主要围绕大模型生命周期展开，整体链路可以概括为：

```text
数据 -> 训练/对齐 -> 评测 -> 推理部署 -> 应用落地 -> 监控迭代
```

从具体工作内容看，不同岗位通常对应链路中的不同环节。不同岗位对技术深度、系统理解、工程实现、数据处理和行业知识的要求重点不同，面试考察方式也会有所差异。因此，准备大模型岗位时，需要根据目标方向调整复习策略和项目准备深度。

常见岗位包括：大模型算法工程师、大模型开发工程师、大模型数据工程师、大模型推理部署工程师、垂直领域微调工程师。

## 0x01. 岗位速览

**应用开发工程师**：相对容易入门，重工程实现与业务落地，适合新人或从后端、数据、业务系统开发方向转入。

**大模型算法工程师**：技术含量和上限较高，深度依赖数学基础、深度学习理论、训练经验和论文阅读能力，通常对学历、论文、科研背景和模型训练经验要求更高。

**大模型推理部署工程师**：工程壁垒较高，关注模型如何跑得快、跑得稳、跑得便宜，需要后端、系统、GPU、部署和性能优化能力，直接影响线上成本与服务质量。

**大模型数据工程师**：容易被低估，但在大模型链路中不可或缺。数据质量决定模型训练效果、泛化能力和业务可用性，工作重点在语料清洗、样本构造、数据版本和数据质量控制。

**垂直领域微调工程师**：最贴近行业落地，负责将通用模型适配到法律、医疗、金融、工业等具体场景中，强调领域理解、数据构造、Prompt 设计、微调经验和评测迭代。

## 0x02. 大模型算法工程师

大模型算法工程师是大语言模型技术体系中的核心岗位之一，主要负责模型结构设计、算法优化、训练流程管理和模型性能评估等工作。该岗位通常要求具备扎实的深度学习理论基础与实践经验，能够从算法层面构建具备通用能力和可扩展性的模型体系。

### 2.1 岗位定位和核心职责

在实际工作中，大模型算法工程师通常参与模型架构设计与优化、训练任务定义、损失函数设计、训练策略制定、训练过程监控和评估结果分析等环节。部分高级岗位还会参与算法创新，例如设计新的注意力机制、稀疏结构、低秩模块或对齐方法，用于提升模型效果与表达能力。

### 2.2 关键技术能力要求

1. **深度学习理论基础**：掌握神经网络结构、前向传播、反向传播、梯度计算、参数更新、正则化和优化算法等基础内容，能够理解模型训练过程中的核心机制。
2. **Transformer 架构理解**：熟悉 Self-Attention、Multi-Head Attention、LayerNorm、位置编码、MLP、残差连接、KV Cache 等关键结构，能够解释主流大模型架构的设计逻辑。
3. **主流训练范式掌握**：理解预训练、指令微调、RLHF、DPO、偏好对齐等阶段的任务目标、数据形式和训练方法。
4. **大模型训练优化经验**：熟悉分布式训练、数据并行、模型并行、流水线并行、混合精度训练、梯度累积、ZeRO 优化等方法。
5. **算法调优与性能分析能力**：能够根据 Loss 曲线、梯度变化、参数分布和评测结果判断训练状态，定位梯度爆炸、收敛异常、过拟合或欠拟合等问题。
6. **论文阅读与复现能力**：能够快速理解前沿论文，并将新的模型结构、训练策略或优化方法落地到具体任务中。

### 2.3 典型工作流程

1. **任务理解与模型设计**：根据任务目标确定模型规模、结构类型、训练目标和核心设计方案。
2. **数据适配与样本处理**：参与 Tokenization 策略、输入格式、训练集与验证集划分等设计，保证数据与训练目标一致。
3. **训练调试与性能迭代**：监控训练指标，分析异常现象，调整训练参数和优化策略。
4. **评估验证与结果产出**：基于验证集、测试集和人工评估结果判断模型表现，并形成可复现的实验结论。

### 2.4 常用技术工具与平台

算法工程师常用 PyTorch、TensorFlow、HuggingFace Transformers、DeepSpeed、Megatron-LM、ColossalAI、Accelerate、TensorBoard、Weights & Biases、MLflow 等工具。大规模训练中还需要理解 NCCL、CUDA、多卡通信、混合精度和分布式调度相关内容。

### 2.5 岗位价值与发展方向

大模型算法工程师决定模型能力的上限，是模型研发链路中的源头角色。未来可以向高级算法工程师、研究员、算法科学家、模型负责人、AI 架构负责人等方向发展。具备工程实现能力与算法创新能力的复合型人才更具竞争力。

## 0x03. 大模型开发工程师

大模型开发工程师主要承担大模型在工程化过程中的实现、封装与平台集成任务，是连接底层算法研究与上层应用系统的关键岗位。该岗位的工作重心在于将已有的大模型能力通过可调用接口、模块化组件、服务化架构等方式封装起来，使其能够在实际业务中高效、安全、稳定地运行。

### 3.1 岗位定位与职能边界

在大模型生命周期中，开发工程师通常介入模型推理服务搭建、接口 API 封装、前后端调用、缓存机制设计、任务调度实现、多模型集成、模型评估体系建设等多个工程层面，是大模型应用落地的直接执行者与系统支撑者。

### 3.2 关键技术能力要求

1. **大模型调用与封装能力**：需要具备使用主流框架，如 HuggingFace Transformers、OpenAI API、ChatGLM、Qwen 等加载并调用大模型的能力，熟悉 Prompt 构造、Token 控制和输出解析等细节。
2. **推理服务部署与优化经验**：能够完成本地部署、云端部署及容器化部署，掌握 Docker、Conda、Kubernetes 等工具，熟悉 KV Cache、批处理、并发控制等推理性能优化方法。
3. **系统架构与微服务设计能力**：了解 Web 系统与微服务设计理念，能基于业务需求完成模块划分、服务拆分、任务路由与模块协同，实现 RESTful 接口设计、模块解耦、异常处理和日志记录。
4. **任务调度与控制逻辑构建**：负责构建智能体或多模块系统中 Prompt 调用的状态机、上下文管理模块、历史信息追踪与决策逻辑，确保多轮交互、插件调用、RAG 融合等功能具备良好扩展性。
5. **工程代码质量与可维护性**：具备良好的代码组织、测试覆盖、日志记录与错误处理能力，能够对模型调用链路中的每个步骤进行模块化和抽象化处理，提高系统可扩展性与稳定效率。

### 3.3 典型工作流程

1. **模型能力接入与封装**：从算法工程师或开源模型处获取模型权重与接口文档，完成模型加载、Prompt 输入格式适配、Token 编码处理和输出结构化封装。
2. **模型服务化与性能优化**：通过 FastAPI、Triton 或 vLLM 部署推理服务，并结合负载均衡、缓存策略和请求分流机制构建高并发、低延迟服务体系。
3. **功能集成与系统设计**：将大模型能力嵌入业务流程，构建智能问答、文档摘要、代码生成、知识库检索、Agent 工作流等应用场景。
4. **多模型管理与调用路由**：设计统一模型管理接口，实现多模型版本切换、上下文状态路由、多任务模型组合和模型能力分发。
5. **系统监控与异常处理**：构建调用链监控体系，统计响应时长、异常次数、Token 消耗、内存使用等指标，并结合日志系统进行问题定位。

### 3.4 常用技术工具与平台

开发工程师常用 Python、Go、FastAPI、Flask、Transformers、vLLM、LangChain、LlamaIndex、Redis、MongoDB、PostgreSQL、SQLAlchemy、Docker、Kubernetes、Nginx、Prometheus、Grafana、Sentry 等工具。

### 3.5 岗位价值与发展方向

大模型开发工程师是模型能力产品化的关键角色，可以向 AI 应用架构师、RAG 工程师、Agent 工程师、AI 平台工程师、后端架构师和技术负责人等方向发展。

## 0x04. 大模型数据工程师

在大模型系统中，数据工程师是支撑预训练、微调与推理各阶段的底层力量，负责数据采集、清洗、结构化、存储与分发。与传统数据分析岗位不同，大模型数据工程师需要处理大规模、高维度、多模态的非结构化数据，不仅要解决数据可用性问题，还要保障数据对模型训练效果的正向支撑。

### 4.1 岗位定义与职责核心

该岗位主要负责搭建数据获取与处理流程，构建高质量训练语料，设计分词策略与 Token 机制，实现分布式数据加载优化，建立数据版本与可追溯机制，支持多语言、多模态和领域数据的并行处理。

### 4.2 关键技术能力要求

1. **大规模文本数据处理能力**：掌握海量文本数据的清洗、去重、切分、规整和编码处理，熟悉正则表达式、文本处理库和分布式文件系统。
2. **分词与 Token 机制理解**：熟悉 BPE、SentencePiece、WordPiece 等分词器，掌握 Tokenizer 构建、词表训练、Token 长度分布控制和文本对齐机制。
3. **数据增强与样本构造经验**：能够使用改写、扩写、反事实样本、边界样本、指令生成等方法构造训练样本，提高模型泛化能力。
4. **分布式数据加载与预处理优化**：熟悉 DataLoader 优化、Sharding、缓存策略、异步加载和数据流水线设计，避免数据成为训练瓶颈。
5. **多模态与多语言数据处理能力**：能够处理文本、图像、语音、视频等多模态数据，并进行格式统一、语义对齐和质量控制。

### 4.3 典型工作流程

1. **语料采集与初筛**：从开源项目、公开网站、内部知识库、社交平台等渠道获取文本，并进行合规审查和初步清洗。
2. **数据清洗与格式规整**：统一文本编码，清除特殊字符、HTML 标签、异常断句、乱码和冗余标记。
3. **数据切分与 Token 统计**：将长文本切分为适合上下文窗口的片段，统计平均长度、最大 Token 数、分布范围和覆盖情况。
4. **训练样本构造与增强**：结合任务目标构造问答、对话、摘要、偏好排序、Few-shot 示例等训练数据。
5. **数据版本管理与溯源机制**：记录每次数据构建的版本号、处理脚本、时间戳、来源和处理规则，保证结果可复现。

### 4.4 常用技术工具与平台

数据工程师常用 Python、Bash、Pandas、Polars、HuggingFace Datasets、spaCy、Jieba、OpenCC、NLPAug、Spark、Flink、Ray、Airflow、MLflow、DVC、Delta Lake、Parquet、JSONL 等工具。

### 4.5 岗位价值与发展方向

数据工程师决定模型训练数据的质量边界，是模型能力提升的重要基础。未来可向大模型数据架构师、数据质量负责人、训练数据管道负责人、合成数据工程师、Prompt 数据工程师等方向发展。

## 0x05. 大模型推理部署工程师

推理部署工程师是大模型工程体系中负责模型上线、服务发布与推理性能优化的关键岗位，主要任务是将训练好的大语言模型从离线环境转换为可在线调用的服务接口，并在推理过程中保证系统稳定性、可扩展性与高性能响应。

### 5.1 岗位定位和核心职责

该岗位通常需要与算法、开发、系统运维、安全团队紧密协作，在模型格式转换、量化、硬件适配、服务封装、资源调度等多个层面形成闭环工作流，是大模型从实验室走向生产环境的关键执行者。

### 5.2 关键技术能力要求

1. **模型格式转换与兼容性适配**：掌握 PyTorch、ONNX、TensorRT、GGUF、vLLM 等格式或框架之间的转换流程，理解不同部署框架对模型结构支持的差异。
2. **推理加速与性能优化**：熟悉 FP16、INT8、KV Cache、Batching、PagedAttention、多线程异步调用等推理优化方法，能够平衡吞吐、延迟和显存占用。
3. **多卡部署与资源调度**：掌握多卡部署、NCCL 通信、模型并行、张量并行、流水线并行、GPU 负载监控和资源分配策略。
4. **服务封装与接口管理**：能够使用 FastAPI、Flask、Triton、BentoML、gRPC 等构建模型服务接口，完成路由管理、参数解析、错误响应和日志收集。
5. **系统监控与容错能力**：熟悉请求量、响应时延、失败率、硬件利用率等指标监控，能够设计熔断、重启、超时、回退和告警机制。

### 5.3 典型工作流程

1. **模型接收与格式标准化**：获取训练完成的模型及配置文件，完成格式转换、静态图构建和输入输出结构标准化。
2. **推理引擎选择与性能测试**：根据部署场景选择 vLLM、TensorRT、ONNX Runtime、Triton 等方案，并进行 Latency、Throughput、显存占用等指标测试。
3. **服务封装与线上部署**：基于推理方案封装模型服务，配置多进程或多实例机制，完成 Docker 化与持续集成配置。
4. **资源调度与运行监控**：根据模型资源需求配置 GPU 或 CPU-GPU 混合部署，使用 Prometheus、Grafana 等工具监控推理链路。
5. **优化迭代与问题修复**：基于真实调用数据和用户反馈持续优化响应路径、推理性能和异常处理机制。

### 5.4 常用技术工具与平台

推理部署工程师常用 ONNX Runtime、TensorRT、vLLM、Triton Server、DeepSpeed Inference、FastAPI、BentoML、gRPC、Docker、Kubernetes、NVIDIA Container Toolkit、Nginx、Prometheus、Grafana、Sentry、ELK 等工具。

### 5.5 岗位价值与发展方向

推理部署工程师保障大模型从理论能力转化为实际服务能力。随着边缘部署、多模态推理、低功耗计算和模型服务平台的发展，该岗位可以进一步向 AI 基础设施工程师、推理优化专家、MLOps 工程师、模型服务平台负责人等方向发展。

## 0x06. 垂直领域微调工程师

垂直领域微调工程师是大模型团队中专注于模型在特定行业或任务上进行再训练与能力定制的岗位。该岗位在预训练模型基础上，通过有限或特定领域的数据进行微调，使模型具备更强的专业理解能力与场景适配能力。

### 6.1 岗位定位和核心职责

与算法工程师不同，微调工程师通常不负责从零构建模型底层结构，而是更多参与数据处理、训练策略设计、指标评估与迭代优化，围绕法律问答、医疗报告生成、金融分析、政务问询、工业运维等具体任务构建专业能力闭环。

### 6.2 关键技术能力要求

1. **行业知识与任务理解能力**：需要理解目标行业的术语、流程、知识结构和业务边界，能够抽象出符合业务需求的任务定义与评价标准。
2. **模型微调与参数优化能力**：掌握全参数微调、冻结微调、LoRA、QLoRA、Adapter、Prefix Tuning 等技术路线，并能根据数据规模、算力预算和业务场景选择训练策略。
3. **指令构造与 Prompt 设计能力**：能够针对具体任务构造高质量 Prompt 模板、示例指令和上下文配置，优化 Zero-shot、Few-shot 等输入形式。
4. **数据增强与标注指导能力**：具备设计反事实样本、扰动样本、边界样本等方法的经验，能够协助标注团队构建高质量样本集。
5. **评估指标与质量控制能力**：熟悉 BLEU、ROUGE、EM、F1、准确率、召回率、人工评分和 A/B 测试等评估方式，能够监测模型在不同迭代中的表现变化。

### 6.3 典型工作流程

1. **场景需求分析与任务定义**：根据业务部门或产品线需求，提炼可落地的模型任务，明确输入输出格式、预期效果和边界条件。
2. **语料准备与数据构建**：联合数据工程师完成语料搜集、结构化、指令体系设计、样本构造和标签体系建设。
3. **模型选择与训练策略制定**：根据任务复杂度和资源条件选择 Qwen、ChatGLM、LLaMA、Baichuan 等预训练模型，并确定微调策略和超参数。
4. **训练调试与指标监控**：持续监控 Loss、精度、样本覆盖和泛化表现，诊断过拟合、漂移和语义偏差问题。
5. **评估验证与业务集成**：使用测试集、自动指标、人工评估或 A/B 测试验证效果，确认模型具备上线条件后对接开发或推理部署团队。

### 6.4 常用技术工具与平台

垂直领域微调工程师常用 Transformers、PEFT、TRL、DeepSpeed、ColossalAI、Weights & Biases、TensorBoard、Pandas、Datasets、spaCy、Jieba、OpenCC、Label Studio、Doccano 等工具。

### 6.5 岗位价值与发展方向

垂直领域微调工程师决定模型能否真正理解业务语境并满足特定场景下的精度要求。未来可进一步发展为行业模型专家、Prompt 设计工程师、AI 产品交付工程师、行业知识增强建模专家等角色。

## 0x07. 不同岗位技术侧重点和面试技巧

大模型相关岗位虽然都围绕同一类核心技术展开，但在实际职责、技能要求与面试重点上存在明显差异。理解不同岗位的技术关注点，有助于制定更有针对性的准备策略。

### 7.1 岗位技术侧重分析

**算法工程师**：强调模型架构、训练机制和优化策略，面试通常集中在 Transformer 结构细节、训练范式、梯度更新、Loss 分析、论文复现和模型改造能力。

**开发工程师**：强调工程实现与系统集成，面试通常关注模型封装、API 设计、RAG、Agent、上下文管理、任务调度、日志系统和系统设计能力。

**数据工程师**：强调海量文本处理、Tokenizer、数据增强、数据质量和数据管道，面试可能要求说明语料清洗流程、样本构造逻辑或编写数据处理脚本。

**推理部署工程师**：强调模型上线后的服务能力与稳定性，面试关注 ONNX、TensorRT、vLLM、KV Cache、量化、并发优化、多卡部署和监控体系。

**垂直领域微调工程师**：强调任务定义、领域数据、Prompt、LoRA、评测指标和业务闭环，面试关注如何把通用模型适配到具体行业场景。

### 7.2 学习路线

了解岗位差异后，学习路线应结合自身背景和目标岗位进行选择。通用基础包括 Python、Linux、Git、Docker、机器学习、深度学习、PyTorch、Transformer、Prompt Engineering 和 RAG。之后再根据目标方向深入算法训练、工程开发、数据处理、推理部署或垂直微调。

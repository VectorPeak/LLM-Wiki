### Concept-概念

#### 1. AI 时代如何高效学习 #ai #learning #notes

基于文字的知识压缩，AI 已经做得非常好了。过去需要花很多时间整理资料、提炼重点、归纳框架；现在，这些工作很大一部分都可以交给 AI。但学习本身并没有消失。只要学习仍然有人参与，它依然可以拆成四个环节：输入、训练、输出、反馈。

输入是获取知识，训练是理解、消化和迁移，输出是用语言、作品或行动表达出来，反馈是发现问题、修正认知并形成能力。其中，知识更接近“能被语言描述的内容”，技能更接近“真正能做出来的能力”。AI 可以极大提高输入和反馈的效率，但不能直接替人完成能力的形成。

在高中和初中阶段，某种具体的笔记方式曾经很重要，比如康奈尔笔记、思维导图、错题本。但到了 AI 时代，固定的笔记形式没有那么重要了。真正重要的不是“记下了什么”，而是“记的过程是否帮助自己完成了理解、重组和迁移”。笔记不再只是知识仓库，而应该是思考过程的痕迹。

当输入效率和反馈效率都提高很多之后，学习不应该只追求更完整的知识库，而应该更快进入使用场景。最好的学习方式仍然是学以致用。费曼学习法的价值在于逼迫自己把概念讲清楚，从而区分核心原理和辅助解释；思维导图的价值不在于严谨全面，而在于从一个核心问题出发，把概念、方法和应用连接起来，重要的是推导过程真的发生。

考试和项目在某种程度上相似：它们都不是单纯检查“知道多少”，而是在逼人面对具体问题，并给出一个可行解。区别在于，应试教育通常是扣分逻辑，答案固定，犯错扣分；工作和项目更接近加分逻辑，工具开放，路径不唯一，重要的是能不能做出可用结果。人生最终需要的往往也不是最优解，而是可行解。

与其维护庞大的错题集，不如维护真正有价值的问题集。人很容易在自己曾经犯错的地方继续犯错。问题集的意义不是记录错误，而是持续暴露认知缺口。学习本质上是一个 diff：不是把所有新知识塞进大脑，而是让新知识和旧有知识发生比较，找到真正改变理解结构的部分。

同时，人一定会遗忘。艾宾浩斯遗忘曲线提示了这一点。但在真实工作中，一个知识点出现的频率，往往和使用频率相关。经常被使用的知识会自然留下来，长期不用的知识即使背过也会消失。所以学习不仅需要输入和输出，还需要归档和复习。但复习不一定是机械重复知识点，更高效的方式是记录真正卡住自己的问题、改变理解的概念，以及实践中反复遇到的模式。

过去人们需要记住大量知识，是因为检索成本很高。当知识检索变得足够容易时，真正需要记住的可能不是知识本身，而是：问题在哪里，结构是什么，自己为什么会错，以及下一次如何更快地用起来。

#### 2. JEP 444 Java 虚拟线程的理解 #java #jep #virtual-threads #concurrency

Java 自己写的关于 JEP 444 虚拟线程的记录：虚拟线程本质上是一种编程抽象，严格来说它并不会直接提高性能上限，或者说能达到的性能上限不会发生特别大的变化。它真正带来的价值，是让开发者可以重新使用更直观的 `1 request : 1 thread` 编程模型。

从操作系统层面看，`Process` 更接近资源调度的最小单位，`Thread` 更接近 CPU 时间片轮转的最小单位。传统线程最终还是由 OS 层面调度，因此线程数量会受到较强限制。但在用户态，虚拟线程提供了一层新的抽象：virtual thread 与 platform thread 是多对少的关系，JVM 可以在用户态进行调度，把大量虚拟线程挂载到少量平台线程上。

所以虚拟线程解决的核心问题，不是让单个任务跑得更快，而是缓解传统线程数量不足、阻塞式代码难以扩展的问题。它让同步阻塞风格的代码在高并发场景下仍然可以保持可读性和可维护性。

### Concept-概念

#### 1. dry-run 概念 #workflow #safety

dry-run 指“试运行/演练运行”：在不真正执行有副作用操作的前提下，先模拟一遍流程，查看将会发生什么。常见用途是检查命令、部署、删除、迁移、发布、同步等操作是否符合预期。它的核心价值是降低误操作风险：先看计划和影响范围，再决定是否真正执行。

### Pitfall-踩坑

#### 1. FastAPI `root_path` 与 Nginx `/static/` 转发口径必须一致 #fastapi #nginx #deploy #static

部署到 `/projects/knowfoundry-rag-console/` 这类公网前缀时，FastAPI 配置了 `APP_ROOT_PATH=/projects/knowfoundry-rag-console`，这意味着静态资源实际应该按 `/projects/knowfoundry-rag-console/static/...` 这一整类路径进入后端。

这次页面变成裸 HTML 的原因不是缺少某一个 CSS/JS 文件，而是整个 `/static/` 静态资源路径族的转发口径错了：页面请求的是 `/projects/knowfoundry-rag-console/static/css/app.css`、`/projects/knowfoundry-rag-console/static/js/app.js`，但 Nginx 原先用 `proxy_pass http://127.0.0.1:8000/static/;` 把前缀剥掉后转成 `/static/...`，而当前 FastAPI 在 `root_path` 下并不识别这个无前缀路径，于是 CSS/JS/图片统一 404。

正确经验：针对整个 `/static/` 做统一转发规则，而不是逐个补 CSS/JS 文件；如果 FastAPI 感知公网前缀，Nginx 就不要再剥掉这个前缀，应让 `/projects/knowfoundry-rag-console/static/...` 原样进入上游，例如 `proxy_pass http://127.0.0.1:8000;`。反过来，如果 Nginx 负责剥前缀，FastAPI 就不应该再配置同一个 `root_path`。两边只能选一种口径。

后续：部署检查里增加静态资源 smoke check，至少验证首页、`/static/css/app.css`、`/static/js/app.js` 在公网前缀下返回 200 且 MIME 分别是 `text/html`、`text/css`、`text/javascript`。

### Concept-概念

#### 1. RFC 是什么 #concept #engineering

RFC 是 Request for Comments 的缩写，直译是“请求评论”。在工程语境里，它通常指一种技术提案或设计讨论文档：先把问题背景、目标、方案、取舍、影响范围和待讨论点写清楚，再邀请团队或社区评审。RFC 的重点不是一开始就给出最终答案，而是把复杂问题公开化、结构化，让相关人能围绕同一份材料讨论。

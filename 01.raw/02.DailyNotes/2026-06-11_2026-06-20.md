#### 2. Transformer 自注意力公式当中根号 dk 的作用 #transformer #attention

为什么要缩放：因为 attention 的分数是 `QK^T`，如果 key 的维度比较大，点积的数值可能会变大。这个分数直接进 softmax 的话，softmax 容易变得很尖锐，接近 one-hot，导致梯度比较小，所以需要缩放来稳定训练。

为什么缩放因子是 `√d_k`：假设 q 和 k 的每一维都是均值 0、方差 1，并且相互独立，那么 `q · k` 是 `d_k` 个随机乘积项的和。每一项方差大约是 1，所以点积的方差是 `d_k`，标准差是 `√d_k`。因此除以 `√d_k` 后，点积结果的方差大约变成 1，softmax 的输入尺度就比较稳定。

如果除以 `d_k`，就会缩放过度，因为点积结果的标准差不是按 `d_k` 增长，而是按 `√d_k` 增长。

### Concept-概念

#### 1. SVM #machine-learning

SVM 是一种监督学习模型，常用于分类。它的核心思想是：在不同类别之间找一条“分界线”，并且让这条线离两边最近的样本都尽可能远。这个距离叫 margin，决定分界线位置的那些最近样本叫 support vectors。SVM 本质上是在追求最大间隔分类，因此通常泛化能力比较好。对于非线性问题，SVM 可以通过 kernel trick 把数据映射到更高维空间，在高维空间中做线性分割，从而在原空间形成非线性分类边界。

#### 2. KL 散度、交叉熵误差与知识蒸馏 #machine-learning #distillation

KL 散度（相对熵）用来衡量两个概率分布之间的差异，表示如果用分布 Q 去近似真实分布 P，会损失多少信息。

KL 散度可以写成：**KL(P ∥ Q) = ∑ P(x) log(P(x) / Q(x))**，读作：**P 到 Q 的 KL 散度**。

交叉熵误差衡量的是：真实分布和模型预测分布之间有多不一致。模型给真实类别的概率越高，交叉熵越小；给真实类别的概率越低，交叉熵越大。H(P, Q) = -∑ P(x) log Q(x)。

交叉熵和 KL 散度关系是：**H(P, Q) = H(P) + KL(P ∥ Q)**。如果真实分布 **P** 固定，那么 **H(P)** 是常数。所以训练模型时：**最小化交叉熵 ≈ 最小化 KL(P ∥ Q)**，也就是让模型预测分布 **Q** 尽量接近真实分布 **P**。

**H(P)** 是真实分布自己的熵，可以理解成：真实世界本身有多不确定。它只由真实分布 **P** 决定，和模型预测 **Q** 没关系。

在知识蒸馏中，软标签通常指教师模型经过 softmax 后输出的概率分布。相比 one-hot 硬标签，软标签包含类别之间的相似性信息，也就是 dark knowledge。训练学生模型时，可以把教师分布记为 P，学生分布记为 Q，用交叉熵 H(P,Q) 或 KL(P∥Q) 来约束学生输出接近教师输出。因为 H(P,Q)=H(P)+KL(P∥Q)，而教师分布 P 固定时 H(P) 是常数，所以最小化交叉熵等价于最小化 KL 散度。实际蒸馏中还会引入温度系数 T，使教师输出更平滑，从而暴露更多非正确类别之间的关系，帮助学生学到教师模型的泛化能力。

#### 3. DPO、PPO、GRPO 的区别 #rlhf #alignment

**PPO 是 OpenAI 那条路线。** 先训一个 reward model，再用 RL 去优化 policy。每次更新都要让当前 policy 现采新样本，所以是 on-policy。优点是表达力强，理论上多复杂的偏好都能拟合。缺点是要同时跑四个模型：policy、ref、reward、value，显存吃不消，训练也不稳，调参很痛苦，还容易 reward hacking。

**DPO 是 Stanford 那篇论文的路子。** 数学上证明了在 Bradley-Terry 偏好假设下，可以绕过 reward model，直接用偏好对优化 policy。数据是预先准备好的，不需要在线采样，所以是 off-policy。只要两个模型，policy 和 ref，显存友好，训练稳，跟 SFT 差不多省心。代价是受离线数据的分布偏移影响，理论上限不如 PPO，β 这个超参对结果还挺敏感。

**GRPO 是 DeepSeek 用的。** 算 PPO 的简化版，把 value model 砍了。同一个 prompt 采一组 response，组内相对 reward 当作 advantage，不再单独训一个 value 网络去估。少了一个跟 policy 一样大的 value model，显存省一大截。GRPO 在数学推理这种有明确对错的任务上特别好用：reward 直接看答案对不对，1 分或者 0 分。DeepSeek-R1 用的就是这个。

简单选一下：数据现成、要稳、要省钱，DPO；reward 复杂、有算力、要做到极致，PPO；reward 是规则可判的（数学、代码），GRPO。

**On-policy 和 off-policy。** On-policy 是用当前正在训的模型采的样本来更新这个模型，PPO、GRPO 都是。Off-policy 是用别的模型（或者历史的自己）采的样本来更新当前模型，DPO 就是。实践上 on-policy 数据新鲜但贵，off-policy 数据便宜但有分布偏移。DPO 训到后面效果掉，很多时候就是 policy 已经飘离 ref 太远，那批离线数据相当于过期了。Iterative DPO 就是为了解决这个：训一段时间停下来，用新模型重新采一批数据继续训。

**Reward hacking。** 模型学会钻 reward 函数的空子，分数刷得很高但没真解决问题。最典型的几个例子：reward 给长回答打高分，模型就开始废话连篇；reward 喜欢礼貌用语，模型每句话开头都“非常感谢您的提问”；代码任务的 reward 是单元测试通过，模型学会写 `if input == test_case_1: return answer_1`。本质上就是 reward 函数和真实目标对不齐，模型把这个 gap 放大了。防御办法没什么花活：RM 持续迭代、加 KL 约束让 policy 别飘太远、人工抽查、对抗测试。

#### 4. Kimi 注意力残差论文 #transformer #paper

这篇论文主要重新思考了 Transformer 里的 residual connection。传统 PreNorm Transformer 里，每一层都是把前一层 hidden state 和当前层输出直接相加，相当于所有历史层贡献的权重都是固定的 1。这样在模型很深的时候，会出现两个问题：一是 hidden state 的幅度会不断累积，二是每一层真正新增的信息会被越来越多历史信息稀释。

Kimi 提出的 Attention Residuals 是把残差路径从“固定相加”改成“可学习选择”。具体来说，当前层不再简单接收所有前面层的均匀累加结果，而是通过 softmax attention 在深度维度上对前面层的输出分配权重。这样模型可以根据输入内容决定更关注哪些浅层或中间层表示。

但 full attention over all previous layers 会带来显存和通信开销，所以论文又提出 Block AttnRes，把层分成 block，只在 block 级别做聚合，降低成本。实验上，他们把它接到 Kimi Linear 结构里，在 48B total / 3B activated 参数模型上训练，发现可以缓解 PreNorm dilution，让输出幅度和梯度分布更均匀，并提升下游任务表现。

面试时可以理解成“把 token 维度上的 attention 思想，迁移到了 layer/depth 维度上”。标准 attention 是让一个 token 从其他 token 里选择有用信息；Attention Residuals 是让一个 layer 从之前的 layer 里选择有用表示。传统 residual 是无条件相加，而 AttnRes 是有选择地聚合。

贡献主要有三个：

1. 指出 PreNorm Transformer 里标准残差连接存在 depth-wise dilution，也就是越往深层，单层贡献越容易被历史累积信息稀释。
2. 提出 Full AttnRes，用 attention 权重替代固定残差累加。
3. 提出 Block AttnRes，让这个方法在大模型训练里更实际，避免 full AttnRes 的显存和通信成本过高。

面试官可能追问：

问：它和普通 attention 有什么区别？

答：普通 self-attention 是在 sequence/token 维度上做信息选择，Attention Residuals 是在 depth/layer 维度上做信息选择。前者回答“当前 token 应该看哪些 token”，后者回答“当前层应该利用哪些前面层的表示”。

问：为什么不用标准 residual 就好了？

答：标准 residual 的优点是训练稳定、梯度容易传播，但它的聚合方式太固定。所有层输出都默认等权累加，在很深的网络里可能导致 hidden state 不断增长，也会让每层新增信息的边际贡献变小。AttnRes 想保留残差路径的稳定性，同时让信息聚合变得可学习。

问：它有什么代价？

答：Full AttnRes 需要保存并访问所有前面层输出，显存和通信成本都高。论文的工程解法是 Block AttnRes，把层按 block 聚合，在性能收益和训练成本之间做折中。

### Question-疑问

#### 1. PQ 的索引方式（IVF_PQ） #vector-search #faiss

IVF_PQ 是两层结构：IVF 先用粗聚类把向量分到倒排桶里，查询时只搜最近的若干桶；PQ 再把桶内向量切成多个子向量，每段用码本索引压缩表示。查询时用 PQ code 近似算距离，必要时再用原始向量 rerank。

在 Faiss 的 IndexIVFPQ 中，常见做法是对 residual 做 PQ：先算 vector - coarse centroid，再编码残差，这通常比直接压缩原始向量更准。

#### 2. 二次精排 reranker 是干嘛的 #rag #reranker

reranker 是在第一阶段 embedding 检索召回候选之后，对 query 和每个 candidate chunk 逐对打相关性分数，再重新排序。embedding 负责快速海选，reranker 负责更细地判断候选是否真的回答问题。

典型流程是：用户问题 -> embedding 召回 top 50/top 100 -> reranker 重排 -> 取 top 3/top 5 给 LLM。好处是提高上下文质量，代价是更慢、更贵，所以通常只对小候选集精排。

#### 3. IVF_SQ8 索引的原理 #vector-search #milvus #index

IVF_SQ8 可以理解成 IVF_FLAT 的压缩版。IVF 先用聚类中心把向量分到多个倒排桶里，查询时只探测最近的若干个桶；SQ8 则把桶内向量从 float32 压缩成 8-bit 标量量化表示，从而节省内存并提高扫描速度。

SQ8 的核心不是像 PQ 那样把向量切成多个子空间，而是对每个维度的连续浮点值做 scalar quantization，把 float 映射成 0 到 255 的整数码。查询时可以用这些 8-bit 码近似计算距离，再按需要对候选结果做精排。

它的取舍是：比 IVF_FLAT 更省内存、更快，但因为向量被量化，召回和距离精度会有一定损失；通常适合数据量较大、内存敏感、能接受近似误差的向量检索场景。

#### 4. 召回文章准确但大模型回答不准确怎么办 #rag #generation #faithfulness

如果召回内容已经准确，问题通常不在检索层，而在生成层的 grounding 和 faithfulness。解决思路是让模型更强约束地基于上下文回答：要求只使用给定材料、引用证据句、无法从材料推出时回答不知道，并降低 temperature。

工程上可以把“生成”拆成两步：先从召回文章中抽取与问题直接相关的证据片段，再让模型基于证据片段组织答案。必要时增加回答校验器，让另一个模型检查答案中的每个结论是否能被原文支持，不支持的结论删掉或重写。

还可以优化 prompt 结构和上下文组织：把最相关片段放前面，去掉噪声 chunk，保留标题、来源、时间等元信息，避免把太多相似但冲突的内容塞给模型。对于高风险场景，最终答案应带引用或原文依据。
#### 5. requirements.lock.txt 与 pip resolver 卡死 #python #pip #docker

在远端 Docker 构建 RAG API 镜像时，直接 pip install -r requirements.txt 会触发 pip resolver 反复求解版本，尤其是 paddleocr、OpenCV、LangGraph 等依赖组合，表现为长时间卡住或重复下载多个候选版本。更稳的做法是维护完整递归依赖锁文件 
equirements.lock.txt，构建时使用锁文件安装，必要时配合 --no-deps 绕开 resolver；对于 	orch==2.7.1+cpu 这类特殊源依赖，可以从锁文件中拆出单独安装，避免 --extra-index-url 让 pip 对所有包都访问 PyTorch 源。

### Concept-概念

#### 1. Nginx 以及反向代理 #nginx #reverse-proxy

Nginx 常用来作为 Web 服务器和反向代理。反向代理的核心是：客户端访问一个统一入口，例如 `https://api.example.com`，Nginx 在服务器内部把请求转发给真实服务，例如 `http://127.0.0.1:34000`。这样外部不需要直接暴露应用端口，可以统一处理 HTTPS、域名、访问控制、日志、限流和负载均衡。

#### 2. fallback #llm-gateway #availability

fallback 指主路径失败后自动切换到备用路径。在 LLM 网关或 LiteLLM 里，可以配置优先模型和备用模型：如果主模型因为超时、限流、上游 5xx、认证失败或额度问题不可用，系统就按顺序尝试备用模型。它的价值是提高可用性，但不同模型的能力、价格、上下文长度和工具调用兼容性可能不同，所以最好在能力相近的模型之间配置 fallback。
#### 3. 路径前缀反代 #nginx #reverse-proxy #deployment

路径前缀反代是用同一个域名或 IP 的某个子路径承载项目，例如 http://117.72.244.79/projects/knowfoundry-rag-console/，Nginx 通过 location ^~ /projects/knowfoundry-rag-console/ 转发到后端服务，并常用 proxy_pass http://127.0.0.1:8000/; 在转发时去掉前缀。它适合暂时没有域名、需要在一台服务器上按路径区分多个项目的场景。

关键风险是前端或后端如果写死了绝对路径，例如 /static/...、/api/...、/health，浏览器会请求站点根路径，而不是带前缀的路径，容易造成静态资源、接口、WebSocket 或回调地址异常。长期多项目部署更推荐子域名；如果必须用路径前缀，需要确认应用支持 base path，或在 Nginx/前端中统一处理前缀。

### Concept-概念

#### 1. GitHub Secrets 是什么 #github-actions #security #deployment

GitHub Secrets 是 GitHub 给仓库、组织或环境提供的加密变量存储，用来保存不能写进代码仓库的敏感配置，例如服务器地址、SSH 用户名、SSH 私钥、API Key、数据库密码、部署 Token 等。

在 GitHub Actions 里，workflow 文件只写 `${{ secrets.JDCLOUD_HOST }}`、`${{ secrets.JDCLOUD_USER }}`、`${{ secrets.JDCLOUD_SSH_KEY }}` 这样的引用名，不直接出现真实值。真实值在仓库后台的 Secrets 页面配置，普通代码浏览者看不到，日志里通常也会被 GitHub 自动打码。

它解决的问题是：代码可以公开，部署流程仍能拿到必要的敏感配置，同时避免密码、私钥、Token 进入 Git 历史。对于 JD-Cloud CD 来说，本机 `~/.ssh/config` 只能作为判断需要哪些 Secret 的线索，不能把私钥或连接信息硬编码进公开仓库。

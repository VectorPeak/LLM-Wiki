# 简历模板四：RAG 质量评测与可观测性工程师

## 项目名称

**KnowForge RAG 平台：质量评测体系与 LangSmith 可观测性闭环**

## 项目周期

20XX.XX - 20XX.XX（按实际经历填写）

## 项目背景

RAG 系统的质量问题往往不是单点错误，而是检索、重排、Prompt、知识库版本、数据隔离和 LLM 生成共同作用的结果。KnowForge 建立了入库质量、主链路评测、追问评测、性能基线和 LangSmith Bad Case 闭环，用确定性工程指标判断版本是否可以发布，并用 RAGAS 作为补充语义质量分析。

## 技术栈

| 类别 | 技术选型 |
|---|---|
| 主评测 | 自研工程回归评测脚本 |
| 补充评测 | RAGAS 0.3.6，语义质量分析 |
| 指标 | Recall@K、MRR、关键词覆盖率、命中路径、Prompt Profile、场景隔离、错误率、耗时 |
| 可观测性 | LangSmith Trace、Annotation、Dataset、Experiment |
| 报告 | JSON / Markdown 报告、评测趋势、门禁输出 |
| 测试 | pytest、API 冒烟、WebSocket 验收 |
| 门禁 | `check_ingestion_quality_gate.py`、`check_evaluation_gate.py`、`check_followup_gate.py`、`check_performance_gate.py` |

## 核心功能

1. **入库质量门禁**：检查失败文件、未支持文件、空文件、OCR 风险、低质量 chunk、重复 chunk、FAQ 空值、重复 FAQ、非法 source 和 FAQ/文档冲突。
2. **主链路评测**：基于评测集运行真实问答链路，统计 Recall@K、MRR、关键词覆盖率、命中路径、source 推断、Prompt Profile 和场景隔离。
3. **追问专项评测**：验证多轮追问中的历史上下文读取、查询改写、source 命中和关键事实覆盖。
4. **性能基线**：采集总耗时、首 Token、检索、重排、LLM 生成等阶段耗时，识别慢阶段和性能回归。
5. **LangSmith 观测**：把 `scenario_id`、`kb_version`、`hit_type`、`sources_count`、`top_source_score`、`prompt_profile` 等写入 Trace metadata。
6. **Bad Case 闭环**：从 Trace 发现问题，标注 expected fields，加入 Dataset，运行 Experiment，对比修复前后结果。
7. **RAGAS 补充评测**：对答案相关性、忠实度、上下文相关性进行补充分析，不替代工程主门禁。
8. **分组验收**：按场景、source、hit_type、Prompt Profile 分组看退化，避免全局平均分掩盖局部问题。

## 个人职责

- 设计 RAG 质量保障体系，将入库质量、检索质量、生成质量、性能和可观测性拆成独立门禁。
- 开发 `evaluate_core_chain.py` 和 `check_evaluation_gate.py`，支持从评测集运行主链路并输出可判定的 Gate 报告。
- 开发追问评测和性能基线脚本，覆盖多轮上下文、查询改写、首 Token、总耗时和慢阶段分析。
- 设计入库质量检查规则，覆盖 FAQ、文档、表格、OCR 风险和多版本元数据完整性。
- 集成 LangSmith Trace，建立 Trace → Annotation → Dataset → Evaluation → Gate 的 Bad Case 回归流程。
- 引入 RAGAS 作为补充语义质量评测，明确它不替代 Recall@K、MRR、hit_type、source、Prompt Profile 等企业工程指标。
- 编写 pytest 和 API 冒烟测试，覆盖意图、检索、Prompt、版本、质量门禁、接口和 WebSocket 关键路径。

## 项目成果

- 建立了覆盖入库、检索、生成、追问、性能和线上观测的多层质量保障体系。
- 将评测从“看答案感觉是否正确”升级为可量化指标：Recall@K、MRR、关键词覆盖率、命中路径、Prompt Profile 和场景隔离。
- 质量门禁可在候选版本发布前拦截错误版本，保证未通过评测的知识库版本不会成为 active 版本。
- LangSmith Trace 支持按场景、版本、命中路径和耗时定位问题，并把 Bad Case 沉淀为回归样本。
- RAGAS 补充评测用于分析语义忠实度和答案相关性，与工程门禁形成互补。
- 实际简历中建议补充自己的结果：评测集规模、门禁阈值、失败样本修复数量、回归问题发现次数、P95 耗时变化。

## 简历使用建议

- 不要把 RAGAS 写成主评测。当前项目主门禁是自研工程回归指标，RAGAS 是补充语义质量分析。
- 如果没有真实 CI，不要写“CI 自动发布阻断”，可以写“支持接入 CI 的门禁脚本”。
